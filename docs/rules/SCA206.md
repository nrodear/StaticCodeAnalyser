# SCA206 — Formatter off/on marker malformed or unpaired

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> `{(*}` / `{*)}` formatter marker is malformed or unpaired - GExperts, CnWizards and JCF then format the region anyway or stop formatting for the rest of the file

## Description

The comments `{(*}` and `{*)}` switch the code formatter off and on again for the region between them. They come from DelForExp and are honoured by the GExperts formatter, the CnWizards formatter and JEDI Code Format (also inside Lazarus); the Delphi IDE formatter (Ctrl+D, up to Delphi 12) ignores them, and Delphi 13 no longer ships a formatter. The formatters accept only the exact four characters - `{ (*}` or `{*) }` is an ordinary comment to them - and the region does not nest: one switch, no counter. Reported are: a marker with blanks or tabs inside (it is ignored, the region is formatted); an opening `{(*}` that is never closed (nothing after it is formatted again); a closing `{*)}` without an open region (it closes nothing); and a second `{(*}` inside an open region (the first `{*)}` already ends it). A region left open to the end of the file on purpose is reported as well - suppress it with `// noinspection FormatterMarker` on the line above the `{(*}`. The compiler sees both markers as plain `{ }` comments, so none of this changes the compiled program. The balance is counted per file; `{$IFDEF}` branches are read as they stand, without evaluating them.

## Examples

### Bad (triggers the rule)

```pascal
{ (*}
const Table: array[0..3] of Integer = (
  1, 2,
  3, 4);
{*)}
```

### Good (idiomatic fix)

```pascal
{(*}
const Table: array[0..3] of Integer = (
  1, 2,
  3, 4);
{*)}
```

## Not reported (by design)

The detector deliberately stays silent on the constructs below. Each is a false-positive class that was measured on the real-world corpus, not a guess.

### Markers inside strings and comments

The formatters read `{(*}` only as a comment token of its own. Inside a string literal, a `//` comment or a `(* *)` comment it is text - JCF keeps exactly such constants and notes in its own sources.

```pascal
const OLD_NOFORMAT_ON = '{(*}';  // not reported
// {(*} starts a region          - not reported
```

### Comments that only look like markers

Only a `{ }` comment whose content is `(*` or `*)` with nothing but blanks or tabs around it counts. A footnote column such as `{ (*) }` and commented-out code such as `{(* Old := 1; *)}` are ordinary comments - the second is the territory of SCA070.

```pascal
CFM_SMALLCAPS = $0040; { (*)    }  // not reported
{(* Old := 1; *)}                 // not reported
```

### Custom GExperts keywords and JCF directives

GExperts lets you change the start and end keywords, and JCF also knows `//jcf:format=off` and `//jcf:format=on`. The rule knows only the default pair `{(*}` / `{*)}` (deliberate false negative).

```pascal
//jcf:format=off  // not checked
```

### A pair split over {$IFDEF} branches

Branches are counted as they stand, the way CnWizards reads them. JCF skips inactive branches, so for JCF such a pair can be incomplete - the rule does not report it.

```pascal
{$IFDEF DEBUG}
{(*}
{$ELSE}
{*)}
{$ENDIF}  // not reported
```
