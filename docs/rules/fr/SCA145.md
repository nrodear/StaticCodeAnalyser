# SCA145 — raise dans un destructeur sans try/except

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Un `raise` non protégé dans un destructeur interrompt la chaîne de nettoyage - inherited Destroy et les FreeAndNil suivants sont sautés, l'état reste incohérent

## Description

Le rôle d'un destructeur est de libérer les ressources d'une instance d'objet, puis d'appeler `inherited Destroy` pour que le parent libère sa part. Si le destructeur lève une exception qu'aucun gestionnaire englobant n'attrape, toute la chaîne de nettoyage est déroulée : inherited Destroy n'est jamais appelé, les ressources du parent fuient, le cadre du destructeur reste à moitié exécuté et l'appelant (typiquement la RTL pendant le déroulement de la pile) voit une exception dans un contexte où il l'avale généralement ou la remonte de façon incorrecte. Le détecteur parcourt les nœuds `nkMethod` dont le `TypeRef` commence par `destructor` (et qui ne sont pas un destructeur de classe, dont la sémantique diffère), puis visite récursivement le corps avec un indicateur `InHandler`. Chaque `nkRaise` rencontré alors que l'indicateur vaut False est signalé. Correspond à la règle Sonar-50 #23.

## Exemples

### Mauvais (déclenche la règle)

```pascal
destructor TFoo.Destroy;
begin
  FList.Free;
  if Bad then raise EInvalidOp.Create('oops');   // <- inherited never runs
  inherited;
end;
```

### Bon (correction idiomatique)

```pascal
destructor TFoo.Destroy;
begin
  try
    FList.Free;
    if Bad then raise EInvalidOp.Create('oops');
  except
    Log('cleanup error');
  end;
  inherited;
end;
```
