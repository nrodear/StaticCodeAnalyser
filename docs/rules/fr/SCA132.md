# SCA132 — except on E: Exception attrape toutes les erreurs

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> `on E: Exception do ...` attrape la classe de base et donc tous ses descendants, y compris les exceptions système qui ne doivent pas être étouffées (EOutOfMemory, EAccessViolation, EAbort)

## Description

Attraper `Exception` elle-même - la racine de la hiérarchie des exceptions Delphi - avale silencieusement des catégories d'erreurs que le code appelant n'est pas prêt à traiter : manque de mémoire, violations d'accès, l'exception de contrôle de flux de type `EAbort`, et tout ce qui ne dérive pas d'une classe de base propre au domaine. Préférer une clause précise `on E: ESpecific do`, ou plusieurs clauses empilées pour les cas dont on peut se rétablir. Si un repli qui relance après journalisation est vraiment nécessaire, utiliser `except Log(''...''); raise; end;` - le `raise;` nu conserve le type et la pile d'origine. Le détecteur parcourt les nœuds `nkOnHandler` et signale ceux dont le `TypeRef` vaut `Exception` (insensible à la casse). Correspond à la règle Sonar-50 #11 (`ExceptionTooGeneral`).

## Exemples

### Mauvais (déclenche la règle)

```pascal
try
  ParseConfig(s);
except
  on E: Exception do        // swallows EOutOfMemory / EAbort / ...
    Log(E.Message);
end;
```

### Bon (correction idiomatique)

```pascal
try
  ParseConfig(s);
except
  on E: EConvertError do
    Log(E.Message);
  on E: EFileNotFoundException do
    Log(E.Message);
end;
```
