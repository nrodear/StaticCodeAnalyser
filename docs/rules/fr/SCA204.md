# SCA204 — Résultat affecté via le nom de la fonction

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

## Description

Dans une fonction, 'GetCount := FItems.Count;' définit le résultat - la forme qu'avait Pascal avant l'existence de Result. Cela fonctionne, mais le même nom signifie alors deux choses différentes dans un même corps : à gauche de ':=', c'est la variable de résultat, partout ailleurs, c'est un appel récursif de la fonction (voir SCA205). 'Result :=' dit ce qui est voulu et ne peut pas être confondu avec un appel. Est signalée une affectation au nom nu de la fonction en début d'instruction (y compris derrière une étiquette de case) dans le propre corps de la fonction. Uniquement là où Result existe : en Delphi (pas sous {$X-}), et en Free Pascal dans les modes delphi, delphiunicode et objfpc ou avec {$modeswitch result} ; un fichier sans {$mode} compte comme Delphi dans une analyse Delphi et comme inconnu sous --dialect=fpc. Règle de style (conseil) : profils strict et style, pas default. reDelphix propose le remplacement par 'Result :='.

## Exemples

### Mauvais (déclenche la règle)

```pascal
function TList.GetCount: Integer;
begin
  GetCount := FCount;
end;
```

### Bon (correction idiomatique)

```pascal
function TList.GetCount: Integer;
begin
  Result := FCount;
end;
```

## Volontairement non signalé

Le détecteur garde volontairement le silence sur les constructions ci-dessous. Chacune est une classe de faux positifs mesurée sur le corpus réel — ce n'est pas une supposition.

### No Result available

In the Free Pascal modes fpc, tp, macpas and iso there is no Result unless {$modeswitch result} is set, and Delphi has none under {$X-} or {$EXTENDEDSYNTAX OFF} - assigning to the function name is the only way there. Under --dialect=fpc a file without {$mode} is skipped, because its mode comes from the project or the command line.

```pascal
{$mode fpc}
function Twice(X: Integer): Integer;
begin
  Twice := 2 * X;  // not reported
end;
```

### The name may mean something else

A parameter, local variable, constant, type or nested routine of the same name hides the result; a nested routine that names it may set the outer result itself; inside 'with Obj do' the object can have a member of that name (the assignment then sets the member); inside an anonymous method the outer result is out of reach. Such routines or spans are skipped.

```pascal
with Obj do
  Total := 5;  // not reported - may be Obj.Total
```

### Elements of the result

'GetRec.X := 5', 'GetArr[0] := 1' and 'GetP^ := 8' write into the result under Free Pascal's Delphi mode; for Delphi itself this is not verified, so these forms are left alone (deliberate false negative).

```pascal
GetRec.X := 5;  // not reported
```
