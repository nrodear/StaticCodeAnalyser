# SCA159 — Gestionnaire d'exception typée au corps vide

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> `on E: SomeException do ;` avale silencieusement une classe d'exception précise - pire qu'un `except end` nu, car l'annotation typée a l'air délibérée

## Description

Analyse lexicale de `on [E:] <ExceptionType> do (;|begin end)`. La forme typée `on E:` donne l'impression d'un traitement réfléchi - le lecteur suppose que le développeur a pensé à cette exception précise. Un corps vide rend l'échec invisible en production : pas de journal, pas de retour dans l'interface, pas de télémétrie. Constat fréquent des revues mORMot dans du code de nettoyage où « cela peut être ignoré » n'est pas documenté. La forme nue `except end` est déjà couverte par SCA-001 (EmptyExcept) ; cette règle couvre la variante au gestionnaire typé.

## Exemples

### Mauvais (déclenche la règle)

```pascal
try DoStuff; except
  on E: EDatabaseError do ;
end;
```

### Bon (correction idiomatique)

```pascal
try DoStuff; except
  on E: EDatabaseError do
  begin
    Logger.Error(E.Message);
    raise;
  end;
end;
```
