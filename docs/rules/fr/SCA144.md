# SCA144 — Comparaison d'égalité ou d'inégalité entre flottants

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> `a = b` ou `a <> b` entre Single/Double/Extended n'est pas fiable à cause de l'arrondi IEEE-754 - utiliser SameValue ou Math.IsZero

## Description

L'arithmétique flottante IEEE-754 ne garantit pas l'égalité exacte, même pour des résultats qui semblent identiques au développeur (`0.1 + 0.2 = 0.3` vaut False). Les tests d'égalité sur des flottants sont une source classique de bugs silencieux - ils semblent corrects dans les tests mais se déclenchent parfois à tort. Le détecteur retire chaînes et commentaires, puis procède en deux phases : (1) collecte les déclarations de variables locales dont le type est `Single`, `Double`, `Extended`, `Real` ou `Currency` ; (2) recherche `<ident> = <expr>` ou `<ident> <> <expr>` où au moins un côté référence une variable flottante connue. Les affectations `:=` sont exclues par un lookbehind. Limites : pas d'inférence de type pour les retours de fonction ni les paramètres non locaux ; les expressions complexes comme `a + b = c + d` ne se déclenchent que si au moins un opérande est une variable flottante connue. Correspond à la règle Sonar-50 #19. Correction : utiliser `System.Math.SameValue(a, b, Eps)` ou `IsZero(a - b)`.

## Exemples

### Mauvais (déclenche la règle)

```pascal
var Ratio: Double;
...
if Ratio = 0.5 then DoStuff;     // <- IEEE-754: almost never true after arithmetic
```

### Bon (correction idiomatique)

```pascal
uses System.Math;
...
if SameValue(Ratio, 0.5, 1e-9) then DoStuff;
```
