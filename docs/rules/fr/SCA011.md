# SCA011 — Le code après Exit/Raise est inatteignable

> L'instruction qui suit Exit, raise ou Halt est du code mort

## Description

Tout ce qui suit un terminateur inconditionnel (Exit, raise, Halt, Continue, Break) dans le même bloc n'est jamais exécuté. Il s'agit généralement d'un reste de refactoring. Non signalé lorsque le terminateur lui-même se trouve dans une plage de compilation conditionnelle et que l'instruction suivante n'y est pas (`{$IFDEF DEBUG} raise ...; {$ENDIF}` suivi de `Exit;`) : sans le define, le terminateur n'existe pas et l'instruction suivante est le chemin actif. Cette garde DÉPEND DU DEFINE - pour un build qui pose toujours le define, le résultat masqué serait factuellement correct. L'analyseur ne peut pas trancher sans les defines du projet et tranche en faveur de « atteignable ».

## Exemples

### Mauvais (déclenche la règle)

```pascal
Exit;
WriteLn('never reached');
```

### Bon (correction idiomatique)

```pascal
if Failed then
begin
  WriteLn('failed');
  Exit;
end;
WriteLn('reached');
```
