# SCA195 — Unit utilisee par le projet mais non incluse dedans

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Un fichier .pas est tiré par les units du projet via uses (il compile grâce au chemin de recherche) mais n'est pas liste dans le fichier projet (.dproj/.groupproj) - l'ajouter au projet

## Description

S'exécute uniquement pour les analyses de projet et de groupe de projets (--project / --project-group, ou choix d'un .dproj/.groupproj via le dialogue '...'). Séparée de SCA194 (qui signale les fichiers réellement orphelins) : un fichier qui EST tiré via uses - directement ou transitivement par d'autres unités de ce type - n'est pas du code mort. Il compile grâce au chemin de recherche, mais reste invisible pour la gestion de projet : pas de navigation de projet dans l'IDE, facile à manquer lors des revues, des déploiements et du verrouillage de versions, et un renommage/déplacement ne casse le build qu'à la prochaine compilation complète. La correction consiste à ajouter le fichier au projet. Les commentaires et les littéraux de chaîne ne comptent jamais comme référence uses ; la correspondance compare le nom de fichier sans extension aux noms d'unités (éventuellement pointés) des clauses uses.

## Exemples

### Mauvais (déclenche la règle)

```pascal
MyProject.dproj references uMain - uMain uses uHelper, but uHelper.pas is not in the .dproj -> flagged: add uHelper.pas to the project
```

### Bon (correction idiomatique)

```pascal
Every unit reachable via uses from project units is listed as a DCCReference in the .dproj
```
