# SCA154 — Move/FillChar avec SizeOf d'un type pointeur

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Move, FillChar, CopyMemory ou ZeroMemory appelé avec SizeOf(PXxx) où PXxx est un type pointeur - ne copie que 4 ou 8 octets (la taille du pointeur) au lieu du tampon visé

## Description

Analyse lexicale à la recherche de `Move|FillChar|CopyMemory|ZeroMemory(...SizeOf(<Name>)...)` où <Name> commence par `P` suivi d'une majuscule (convention Delphi du préfixe P pour les types pointeur : PByte, PInteger, PCardinal, PChar, PSomeRecord, ...). En 64 bits, SizeOf(PXxx) renvoie 8 quel que soit le type pointé ; en 32 bits, il renvoie 4. L'auteur voulait presque toujours SizeOf(Xxx) ou Length(Buf) - la copie tronquée laisse silencieusement le reste du tampon intact (FillChar) ou ne copie que partiellement la source (Move). Piège courant dans mORMot : SizeOf(PByte) au lieu d'un nombre d'octets explicite lors d'une copie dans un tableau fixe. La liste blanche exclut SizeOf(TXxx) / SizeOf(Integer) / SizeOf(Variable) - seul le préfixe P suivi d'une majuscule déclenche.

## Exemples

### Mauvais (déclenche la règle)

```pascal
var Buf: array[0..255] of Byte; P: PByte;
Move(Src^, P^, SizeOf(PByte));        // copies 8 bytes (pointer), not the buffer
FillChar(P^, SizeOf(PInteger), 0);    // zeroes 8 bytes, not the integer
```

### Bon (correction idiomatique)

```pascal
Move(Src^, P^, SizeOf(Byte) * Count);  // explicit element count
FillChar(V, SizeOf(V), 0);             // matches the variable's size
```
