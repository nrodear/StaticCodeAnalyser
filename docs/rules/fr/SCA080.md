# SCA080 — Exit/Continue redondant avant end

> `Exit;` / `Continue;` juste avant `end` est sans effet

## Description

Si Exit est la dernière instruction d'une routine, ou Continue la dernière instruction du corps d'une boucle, le flot de contrôle quitte déjà le bloc - l'instruction de saut est du code mort. La supprimer pour clarifier l'intention. Correspond à SonarDelphi communitydelphi:RedundantJump. Non signalé : (1) un Exit atteint depuis l'intérieur du corps d'une boucle - c'est un retour anticipé, et le supprimer laisse la boucle écraser le résultat qu'elle vient de trouver ; une boucle déjà terminée au même niveau (while ... do Inc(Run); Exit;) ne compte pas, ces résultats restent donc. (2) Break, quelle que soit sa position - contrairement à Continue, il supprime les itérations restantes ; suivre l'indication transforme donc les boucles de recherche en parcours complets et les boucles while True en boucles infinies. Break n'est redondant que dans repeat ... Break; until True, qui n'apparaît nulle part dans le corpus de référence de 12 000 fichiers.

## Exemples

### Mauvais (déclenche la règle)

```pascal
procedure Foo;
begin
  DoStuff;
  Exit;
end;
```

### Bon (correction idiomatique)

```pascal
procedure Foo;
begin
  DoStuff;
end;
```

## Volontairement non signalé

Le détecteur garde volontairement le silence sur les constructions ci-dessous. Chacune est une classe de faux positifs mesurée sur le corpus réel — ce n'est pas une supposition.

### `Exit` inside a loop body

This is an early return, not a no-op. Deleting it lets the loop run its remaining iterations - in the canonical search loop the found result is then overwritten by the next iteration. The detector walks backwards from the jump and suppresses the finding when a `for`/`while`/`repeat` body encloses it. A loop that has already finished on the same level (`while ... do Inc(Run); Exit;`) does not count, so the genuine findings behind a completed loop stay.

```pascal
function IndexOfName(const S: string): Integer;
begin
  for Result := 0 to Count - 1 do
    if Items[Result] = S then
      Exit;          // not reported - deleting it breaks the search
  Result := -1;
end;
```

### `Break` in any position

Unlike `Continue`, `Break` at the end of a loop body is not a no-op: it suppresses all remaining iterations. Following the old hint turned search loops into full scans and, in `while True` / `repeat ... until False`, into infinite loops. `Break` is redundant only in `repeat ... Break; until True`, a construct that does not occur in the 12.000-file reference corpus - so the keyword is no longer scanned at all.

```pascal
for I := 0 to List.Count - 1 do
  if List[I] = Wanted then
  begin
    Result := I;
    Break;         // not reported - the loop must stop here
  end;
```
