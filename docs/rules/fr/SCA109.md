# SCA109 — Verrou pris sans libération par try/finally

> TCriticalSection, Monitor ou verrou WinAPI pris sans try..finally englobant - une exception laisse le verrou posé

## Description

Prendre un verrou (TCriticalSection.Enter / .Acquire, TMonitor.Enter, TMultiReadExclusiveWriteSynchronizer.BeginWrite, EnterCriticalSection de WinAPI) sans le faire suivre immédiatement d'un try..finally contenant le Leave / Release / EndWrite correspondant est l'un des bugs de threading Delphi les plus courants : toute exception entre la prise et la libération laisse le verrou posé définitivement, ce qui provoque un interblocage pour chaque appelant suivant. Détection lexicale : reconnaît les motifs de prise et vérifie si l'instruction qui suit le `;` est `try`. Masquer avec `// noinspection LockWithoutTryFinally` pour les séquences volontairement non protégées (rare ; signifie généralement que l'appel suivant ne lèvera de toute façon jamais d'exception).

## Exemples

### Mauvais (déclenche la règle)

```pascal
FLock.Enter;
DoWork;     // exception here leaves FLock held forever
FLock.Leave;
```

### Bon (correction idiomatique)

```pascal
FLock.Enter;
try
  DoWork;
finally
  FLock.Leave;
end;
```
