# SCA008 — Déréférencement nil possible

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Accès a une variable qui peut valoir nil a cet endroit

## Description

Une variable locale est explicitement mise à nil puis déréférencée (appel de méthode ou accès à une propriété) sans réaffectation ni test de nil entre les deux. Provoque un plantage avec EAccessViolation à l'exécution. Le détecteur ne suit que les affectations explicites `obj := nil` ; une valeur renvoyée par une fonction qui peut renvoyer nil (p. ex. une méthode Find...) n'est pas suivie. Gardes reconnues : une réaffectation, `Assigned(obj)` ou `obj <> nil` dans une condition if, un `if obj = nil then Exit` anticipé, le passage de `obj` comme argument (affectation var/out possible) et les appels sûrs vis-à-vis de nil comme `obj.Free`.

## Exemples

### Mauvais (déclenche la règle)

```pascal
obj := nil;
// ... obj is not assigned on this path ...
obj.DoStuff;   // <-- AV: obj is still nil
```

### Bon (correction idiomatique)

```pascal
obj := nil;
// ...
if Assigned(obj) then
  obj.DoStuff;
```
