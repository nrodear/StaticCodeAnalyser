# SCA147 — Méthode privée sans appelant dans l'unité

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Une méthode privée que nulle autre méthode de la même unité ne référence est du code mort - la supprimer ou la brancher

## Description

Les méthodes privées ne peuvent être appelées que depuis la même unité (Delphi classique) ou la même classe (strict private). Si aucune autre méthode ne les référence, elles ne peuvent pas être appelées du tout - c'est du code mort, souvent le reste d'une refactorisation inachevée. Le détecteur parcourt les nœuds `nkClass`, trouve les enfants `nkVisibilitySection` nommés `private` ou `strict private`, collecte leurs noms de `nkMethod`, puis recherche textuellement dans le corps du fichier (débarrassé des chaînes et commentaires) des correspondances en limite de mot. Deux correspondances par méthode sont tolérées (ligne de déclaration + en-tête d'implémentation) ; davantage indique au moins un appel. Comme cette recherche ne voit que les appels *par nom*, tout mécanisme de répartition qui atteint une méthode sans la nommer est écarté avant le signalement - gestionnaires de messages, clauses de résolution de méthode, constructeurs/destructeurs de classe, `override` et implémentations d'interface. Les gestionnaires d'événements DFM sont résolus via le `.dfm` apparié. Angle mort restant : l'invocation uniquement via RTTI (`TypeInfo`, registres pilotés par attributs) - y utiliser `// noinspection UnusedPrivateMethod`. Correspond à la règle Sonar-50 #37.

## Exemples

### Mauvais (déclenche la règle)

```pascal
TFoo = class
private
  procedure HelperA;            // <- never called
public
  procedure DoStuff;
end;
```

### Bon (correction idiomatique)

```pascal
TFoo = class
public
  procedure DoStuff;
end;
// or call HelperA from DoStuff to make the dependency explicit
```

## Volontairement non signalé

Le détecteur garde volontairement le silence sur les constructions ci-dessous. Chacune est une classe de faux positifs mesurée sur le corpus réel — ce n'est pas une supposition.

### Method with a `message` directive

VCL/FMX message handlers are invoked by `TObject.Dispatch` through the message number, never by name. This is the largest exempt class by far (87 % of the gated findings on the reference corpus). The directive is checked on the declaration itself and only at parenthesis depth 0, so the ubiquitous parameter name `Message` does not count as one.

```pascal
private
  procedure WMPaint(var Message: TWMPaint); message WM_PAINT;
```

### Method-resolution clause (`IFace.Name = Impl;`)

A qualified name in a class body is not a declaration at all - it only re-binds an interface member to an existing method. There is no method under that name to be unused.

```pascal
private
  function ISearchCommands.CanFindPrev = CanFindNext;
```

### `class constructor` / `class destructor`

The RTL runs them during unit initialization and finalization; a by-name call would even be illegal. An ordinary private `class procedure`/`class function` is NOT exempt - it stays reportable.

### Method marked `override`

The call arrives through the VMT from the ancestor, so no reference in this unit is required. Deliberately restricted to `override`: a newly introduced private `virtual`/`dynamic` method that nobody calls in the unit is still a legitimate finding.

### Members of a class that implements an interface

Interface members are reached through interface dispatch, usually from another unit. If every implemented interface is declared in the same unit, only the members matching those interfaces are exempt - genuinely dead helpers of the class stay reportable. If even one interface is declared elsewhere (the normal case), the detector cannot tell which private method serves it and stays silent for the whole class. That is a deliberate false-negative trade in favour of precision.

```pascal
TEditor = class(TInterfacedObject, IEditor, IFileCommands)
private
  { IFileCommands }
  function CanClose: Boolean;    // not reported - dispatched via the interface
end;
```
