# SCA050 — Le membre public pourrait être privé a l'unit

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Ce membre public n'est référencé que dans l'unit courante - le `private` classique de Delphi (portée unit) suffit

## Description

Analyse d'un seul fichier : le membre `public` est référencé depuis un endroit de la même unité (autres classes, procédures de premier niveau, ...), mais PAS exclusivement depuis la classe déclarante elle-même. Le restreindre au `private` classique de Delphi (dont la portée est l'unité, pas la classe) est sûr : chaque appelant légal dans l'unité continue de fonctionner. Ce détecteur s'exécute volontairement UNIQUEMENT sur un seul fichier - l'ancienne analyse inter-unités/inter-projets produisait trop de faux positifs (streaming RTTI/DFM, consommateurs .dpk/.dproj voisins, instanciations génériques, API de plugins). Ce conseil est une recommandation ; si une unité étrangère consomme le membre, le compilateur détectera la visibilité cassée avec E2361 une fois la modification appliquée. Exclus : published, virtual/abstract/override/dynamic, constructeurs/destructeurs de classe, classes de base pilotées par RTTI (TForm/TFrame/TDataModule/TComponent), classes utilitaires composées uniquement de méthodes de classe. Masquer ligne par ligne avec `// noinspection CanBeUnitPrivate` pour une surface publique voulue (API de bibliothèque, point d'entrée de plugin).

## Exemples

### Mauvais (déclenche la règle)

> Cette règle signale avec une confiance faible : avec la valeur par défaut `[Rules] MinConfidence=medium`, l'exemple ci-dessous reste masqué. Avec `[Rules] MinConfidence=low`, il apparaît.

```pascal
type
  TFoo = class
  public
    procedure Helper;
  end;
  TBar = class
    procedure Run;  // calls Foo.Helper - same unit
  end;
```

### Bon (correction idiomatique)

```pascal
type
  TFoo = class
  private
    procedure Helper;
  end;
// Same-unit access stays legal under Delphi-classic `private`.
```
