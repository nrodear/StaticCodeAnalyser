# SCA182 — Classe [TestFixture] sans aucune méthode [Test]

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

## Description

DUnitX découvre les classes de test en recherchant les attributs [TestFixture]. Une fixture sans aucune méthode [Test] apparaît dans l'arbre des tests mais n'apporte aucun test exécutable - typiquement un reste de refactoring (tests supprimés, fixture conservée). Le détecteur parcourt le texte du fichier avec une simple machine à états : il entre dans la fenêtre de fixture sur la ligne [TestFixture], guette un [Test] à l'intérieur et en sort au prochain `end;` de premier niveau. Si aucun [Test] n'a été vu, la ligne [TestFixture] est signalée. Les fixtures ne contenant que [SetupFixture] (servant à préparer un état partagé pour d'autres fixtures) sont un cas connu de faux positif - masquer avec `// noinspection AttributeTestFixtureWithoutTests`.

## Exemples

### Mauvais (déclenche la règle)

```pascal
[TestFixture]
TFooTests = class
  procedure Helper;
end;
```

### Bon (correction idiomatique)

```pascal
[TestFixture]
TFooTests = class
  [Test] procedure DoesX;
end;
```
