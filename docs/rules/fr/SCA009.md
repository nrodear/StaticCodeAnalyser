# SCA009 — Objet créé sans try/finally protecteur

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Appel .Create sans try/finally englobant - risque de fuite en cas d'exception

## Métadonnées

| **Kind** | `MissingFinally` |

| **Étiquettes** | `memory`, `exception-safety` |

## Description

Semblable à MemoryLeak (SCA001) mais vérifié structurellement : une variable locale d'une classe suivie par le détecteur de fuites (la liste [Detectors] LeakyClasses, p. ex. TStringList) est créée avec .Create et libérée avec .Free ou FreeAndNil dans la même méthode, mais aucun try/finally ne protège le code intermédiaire - une exception à cet endroit saute le Free et l'objet fuit. Sans aucun Free, le détecteur reste muet (ce cas relève de SCA001). Ne sont pas signalés non plus : un objet renvoyé comme résultat ou confié à un propriétaire, et un intervalle entre Create et Free qui n'appelle que des membres de l'objet lui-même (p. ex. List.Add sur une TStringList).

## Exemples

### Mauvais (déclenche la règle)

```pascal
obj := TStringList.Create;
LoadNames(obj);
obj.Free;
```

### Bon (correction idiomatique)

```pascal
obj := TStringList.Create;
try LoadNames(obj) finally obj.Free end;
```
