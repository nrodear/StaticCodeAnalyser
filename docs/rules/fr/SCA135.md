# SCA135 — Classe concrète héritant d'une méthode abstraite sans override

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Bug-red)

> La classe dérive d'une base ayant une méthode `abstract` mais ne la redéfinit pas - l'appel sur l'instance lève EAbstractError à l'exécution

## Description

Quand une classe hérite d'une méthode `abstract` de son parent et ne la redéfinit pas, l'instanciation de la classe compile sans problème, mais tout appel de la méthode lève `EAbstractError`. Le détecteur parcourt les nœuds `nkClass` ; pour chaque classe dérivée, il cherche le parent direct dans la même unité, collecte les méthodes du parent marquées `abstract` et signale chaque méthode abstraite dont le nom ne figure pas parmi les noms de méthodes de la classe dérivée. Limites : uniquement au sein de l'unité (les bases d'autres unités comme `TForm`/`TStrings` ne sont pas vues) ; uniquement le parent direct (les chaînes à plusieurs niveaux ne vérifient qu'un seul niveau) ; les class helpers / interfaces / records sont ignorés. Les classes elles-mêmes marquées `class abstract` peuvent laisser des méthodes abstraites. Correspond à la règle Sonar-50 #10.

## Exemples

### Mauvais (déclenche la règle)

> Cette règle signale avec une confiance faible : avec la valeur par défaut `[Rules] MinConfidence=medium`, l'exemple ci-dessous reste masqué. Avec `[Rules] MinConfidence=low`, il apparaît.

```pascal
type
  TBase = class
    procedure DoWork; virtual; abstract;
  end;
  TDerived = class(TBase)
    // DoWork not overridden -> EAbstractError on call
  end;
```

### Bon (correction idiomatique)

```pascal
type
  TDerived = class(TBase)
    procedure DoWork; override;
  end;
```
