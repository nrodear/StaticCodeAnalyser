# SCA125 — Redéfinition dont le corps se réduit à `inherited;`

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Une redéfinition qui ne fait que transmettre au parent ne sert à rien - la supprimer

## Description

Une méthode déclarée avec `override` dont l'implémentation ne fait qu'appeler l'ancêtre avec les mêmes arguments n'ajoute rien au comportement de la classe parente : la répartition virtuelle atteint déjà l'ancêtre quand la sous-classe ne redéfinit pas la méthode. La redéfinition vide est du bruit qui ralentit les revues de code et doit être revue chaque fois que la signature de l'ancêtre change. Le détecteur parcourt chaque implémentation de méthode `TClass.Name` dont le corps est exactement une instruction - `inherited;` (procédures, constructeurs, destructeurs), `inherited Name;` (sans paramètres), `inherited Name(p1, .., pn)` avec les paramètres transmis inchangés et dans l'ordre, ou `Result := inherited [Name(..)]` dans les fonctions - et lit la DÉCLARATION dans la classe de la même unité (les en-têtes d'implémentation ne répètent jamais `override`). La déclaration doit être unique (pas de surcharges, pas de jumeaux {$IFDEF}) et porter `override` sans autre directive (message, final, reintroduce, deprecated, convention d'appel, ...), sans attribut ni paramètre par défaut ; aucune directive de compilation ne doit se trouver entre l'en-tête d'implémentation et `end`. Les méthodes de classe sont ignorées. Visibilité : quand la méthode de l'ancêtre est déclarée dans la même unité avec une visibilité moindre, la redéfinition élargit sa visibilité et n'est pas signalée. Quand l'ancêtre se trouve hors de l'unité, les redéfinitions private/protected et les redéfinitions public de méthodes racines publiques bien connues (Destroy, Create, AfterConstruction, BeforeDestruction, Assign, ToString, Equals, GetHashCode) sont signalées avec une confiance élevée, les autres redéfinitions public/published avec une confiance faible (masquées par défaut). Le fichier source doit être lisible. Correspond à `InheritedMethodWithNoCodeCheck` de Sonar-Delphi.

## Exemples

### Mauvais (déclenche la règle)

```pascal
type
  TFooSubclass = class(TFoo)
  protected
    procedure Paint; override;
  end;

procedure TFooSubclass.Paint;
begin
  inherited;     // adds nothing - drop this whole override
end;
```

### Bon (correction idiomatique)

```pascal
// Remove both the declaration and the implementation. The
// parent's Paint is reached by normal virtual dispatch.
```
