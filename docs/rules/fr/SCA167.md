# SCA167 — Appel a Random sans Randomize préalable

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Random / RandomRange / RandomFrom sans Randomize - un germe a 0 produit la même suite à chaque exécution

## Description

La fonction Random de Delphi utilise un germe interne qui vaut 0 au démarrage du programme. Tant que Randomize n'a pas été appelé une fois (généralement au début de l'exécution du programme), Random renvoie la même suite de valeurs à chaque lancement du programme. Le détecteur parcourt l'AST à la recherche de tous les appels et ignore l'unité entière si un appel à Randomize s'y trouve n'importe où. Sinon, chaque appel à Random / RandomRange / RandomFrom est signalé. Remarque : les appels à Randomize dans d'autres unités (p. ex. dans le bloc initialization d'une unité utilisée) ne sont pas détectés ; masquer avec `// noinspection InsecureRandom` le cas échéant. Pour les usages cryptographiques (génération de jetons, sels, codes de réinitialisation de mot de passe), Random ne convient pas, avec ou sans Randomize - utiliser des TBytes issus d'un CSPRNG (p. ex. CryptGenRandom sous Windows, /dev/urandom sous POSIX).

## Exemples

### Mauvais (déclenche la règle)

```pascal
procedure DealCards;
var i: Integer;
begin
  for i := 1 to 5 do
    Players[i].Card := Random(52);
end;
```

### Bon (correction idiomatique)

```pascal
procedure DealCards;
var i: Integer;
begin
  Randomize;   // once, at startup
  for i := 1 to 5 do
    Players[i].Card := Random(52);
end;
```
