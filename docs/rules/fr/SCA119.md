# SCA119 — Constante locale pas en UPPER_SNAKE_CASE

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> `const X = 42;` dans une méthode - préférer UPPER_SNAKE_CASE pour les constantes numériques

## Description

Les constantes locales numériques/entières dans le corps d'une méthode gagnent à être en UPPER_SNAKE_CASE (`MAX_RETRIES`, `BUFFER_SIZE`, `DEFAULT_TIMEOUT`) - le lecteur voit immédiatement que l'identificateur est une constante et non une variable, et la convention rejoint celle de C / Java / Python, si bien que les lecteurs venant d'autres langages ne trébuchent pas. Exclusions du détecteur : noms très courts (<=2 caractères, en général compteurs de boucle ou temporaires), constantes de type chaîne/caractère (souvent des libellés d'interface pour lesquels le PascalCase convient). Masquer avec `// noinspection LocalConstantName` pour les constantes locales légitimement en PascalCase.

## Exemples

### Mauvais (déclenche la règle)

```pascal
procedure Foo;
const
  MaxRetries = 3;
begin ... end;
```

### Bon (correction idiomatique)

```pascal
procedure Foo;
const
  MAX_RETRIES = 3;
begin ... end;
```
