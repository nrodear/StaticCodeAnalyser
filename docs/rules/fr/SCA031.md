# SCA031 — Composant DFM sans champ published

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Le composant du DFM n'a pas de champ published correspondant dans la classe de la fiche - entrée DFM périmée (dérive de schéma)

## Description

Un composant DFM nommé sans champ published correspondant est un écart de schéma, pas une erreur d'exécution : le streamer résout le champ via FieldAddress, obtient nil et ignore silencieusement l'affectation (pas d'EReadError). Le composant est tout de même créé mais inaccessible depuis le code - une entrée DFM périmée/morte qu'il vaut la peine de nettoyer.

## Exemples

### Mauvais (déclenche la règle)

```pascal
// .dfm contains object btnSave: TButton, but TForm1 has no btnSave: TButton field
```

### Bon (correction idiomatique)

```pascal
TForm1 = class(TForm)
  edtName: TEdit;
  btnSave: TButton;   // the .dfm creates it - the field must exist
end;
```
