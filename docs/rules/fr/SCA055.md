## Description

Un opérateur binaire a le même opérande textuel des deux côtés : `x = x`, `a and a`, `(p <> p)`. L'expression s'évalue à une constante (True ou False) à la compilation et indique presque toujours une faute de frappe - l'opérande devait être un identificateur au nom proche (`a = b`, `p1 <> p2`). Le détecteur suit : égalité / inégalité / ordre (`=`, `<>`, `<`, `>`, `<=`, `>=`) et opérateurs booléens (`and`, `or`, `xor`). Les opérateurs arithmétiques (`+`, `-`, `*`) sont volontairement exclus : `x + x` et `a * a` sont des idiomes légitimes. La normalisation des opérandes passe en minuscules et supprime les espaces superflus, mais conserve le contenu des littéraux de chaîne, de sorte que `'foo' = 'foo'` est correctement signalé. Le détecteur exige l'égalité des identificateurs de part et d'autre de l'opérateur - un appel de fonction avec effets de bord (`Next = Next`) est aussi signalé, car deux appels produisent le bug dans tous les cas.

## Exemples

### Mauvais (déclenche la règle)

```pascal
if (a = a) then ...
```

### Bon (correction idiomatique)

```pascal
if (a = b) then ...
```
