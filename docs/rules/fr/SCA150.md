# SCA150 — La comparaison booléenne est toujours vraie / toujours fausse

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Des comparaisons comme `Length(s) >= 0` sont des tautologies - le résultat de Length n'est jamais négatif, la condition ne peut donc jamais être fausse

## Description

Les comparaisons booléennes tautologiques indiquent généralement une faute de frappe (`< 0` au lieu de `= 0`, `>= 1` au lieu de `> 0`) ou un reste de copier-coller d'une version antérieure du code. Le compilateur n'avertit pas, car le type de l'opérande autorise syntaxiquement la plage de valeurs. Ce détecteur étroit retire chaînes + commentaires, puis reconnaît lexicalement deux motifs : `Length(...) >= 0` / `Length(...) < 0` et leurs miroirs `0 <= Length(...)` / `0 > Length(...)`. Limites : les variables Cardinal/UInt (`<UInt> >= 0` est également toujours vrai) ne peuvent pas être détectées sans inférence de type ; les expressions complexes comme `Length(s) - 1 < 0` ne sont pas reconnues. Correspond à la règle Sonar-50 #18 (forme étroite).

## Exemples

### Mauvais (déclenche la règle)

```pascal
if Length(s) >= 0 then DoStuff;   // <- always True
if Length(s) < 0 then DoOther;    // <- always False
```

### Bon (correction idiomatique)

```pascal
if Length(s) > 0 then DoStuff;    // non-empty check
if Length(s) = 0 then DoOther;    // empty check
```
