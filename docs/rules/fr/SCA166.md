# SCA166 — Variable locale non initialisée

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Bug-red)

> Variable locale lue avant sa première affectation dans l'ordre du source, ou jamais affectée

## Métadonnées

| Champ | Valeur |
|---|---|
| **Identifiant de règle** | `SCA166` |
| **Kind** | `UninitVar` |
| **Sévérité par défaut** | Error |
| **Type** | Bug |
| **Unité du détecteur** | `uUninitVar.pas` |
| **Étiquettes** | `reliability`, `memory-safety`, `uninit` |

## Description

Les variables locales de types non managés (Integer, Boolean, Pointer, record, instance de classe) démarrent avec un contenu indéfini. Les lire avant affectation donne des valeurs parasites ou une violation d'accès - un bug de plantage classique. Le détecteur parcourt les instructions de chaque méthode dans l'ordre du source et suit la première écriture et la première lecture de chaque variable locale : une variable lue mais jamais écrite est signalée avec une confiance élevée, une lecture qui précède la première écriture dans l'ordre du source avec une confiance moyenne. Le contrôle n'est pas sensible aux chemins - une écriture dans une branche compte pour toutes les lignes situées en dessous, donc `if Cond then L := TStringList.Create; L.Add('x');` n'est pas signalé. Les écrivains connus de la RTL (Read, ReadLn, FillChar, Move, ZeroMemory, Initialize, New, GetMem) sont reconnus via une liste blanche ; les autres appels avec paramètres var/out sont traités de façon pessimiste comme des lectures (faux négatifs, mais pas de faux positifs). Les types managés initialisés automatiquement par Pascal (string, tableau dynamique, interface) sont ignorés, sauf activation via l'INI. Les méthodes qui dépassent des plafonds configurables (200 variables locales / 5000 instructions, par défaut) sont exclues de l'analyse pour éviter un coût pathologique dans le pire cas.

## Exemples

### Mauvais (déclenche la règle)

```pascal
function MaxOf(const A: array of Integer): Integer;
var
  I, Best: Integer;
begin
  for I := Low(A) to High(A) do
    if A[I] > Best then      // Best is read before its first assignment
      Best := A[I];
  Result := Best;
end;
```

### Bon (correction idiomatique)

```pascal
function MaxOf(const A: array of Integer): Integer;
var
  I, Best: Integer;
begin
  Best := Low(Integer);
  for I := Low(A) to High(A) do
    if A[I] > Best then
      Best := A[I];
  Result := Best;
end;
```
