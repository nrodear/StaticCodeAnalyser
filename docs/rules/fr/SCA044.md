# SCA044 — Longue concaténation - préférer Format()

> Concaténation de chaîne en plusieurs segments - a transformer en appel a Format()

## Description

Les enchaînements comme `'a' + Var + 'b' + IntToStr(N)` (trois concaténations ou plus impliquant des segments non littéraux) sont plus difficiles à parcourir et à traduire que `Format('a%sb%d', [Var, N])` : chaque IntToStr / FloatToStr / FormatDateTime au milieu d'une chaîne est un endroit de plus où une `resourcestring` ne peut pas capturer le modèle du message. Le détecteur examine les affectations dont le membre droit comporte au moins trois opérateurs `+` (quatre termes ou plus) avec au moins un terme non littéral, de sorte que les cas triviaux (`'<' + Name + '>'`) restent muets ; une concaténation passée directement comme argument d'appel n'est pas vérifiée. Il ignore les membres droits qui appellent déjà Format, les affectations à des propriétés SQL (SCA003 les couvre) et les lignes sous un `// noinspection ConcatToFormat` actif. La forme signalée peut être voulue dans des boucles internes critiques pour les performances, où les varargs de Format provoquent du boxing ; le marqueur de suppression est prévu pour ce cas.

## Exemples

### Mauvais (déclenche la règle)

```pascal
Msg := 'User ' + Name + ' has ' + IntToStr(N) + ' open tickets';
```

### Bon (correction idiomatique)

```pascal
Msg := Format('User %s has %d open tickets', [Name, N]);
```
