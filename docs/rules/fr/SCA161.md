# SCA161 — Soustraction de pointeurs via un transtypage 32 bits

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> `Cardinal(P1) - Cardinal(P2)` (ou Integer/LongWord/LongInt) tronque les 32 bits de poids fort d'un pointeur 64 bits sous Win64 - la différence est parfois fausse

## Description

Analyse lexicale de `(Cardinal|LongWord|Integer|LongInt)(<id>) - (Cardinal|...)(<id>)` - deux transtypages 32 bits reliés par un moins. Sous Win64, un Pointer fait 64 bits alors que Cardinal/Integer/LongWord/LongInt font 32 bits, donc le transtypage perd les quatre octets de poids fort de l'adresse. La différence obtenue est fausse dès que l'allocateur fournit des adresses hautes - le code fonctionne sous Win32 et échoue par intermittence sous Win64. Bug de portage courant issu d'exemples Delphi-7 / Delphi-2007 antérieurs à Win64. Correction : utiliser `NativeUInt(P1) - NativeUInt(P2)` ou `NativeInt(P1) - NativeInt(P2)` - des types entiers de la largeur d'un pointeur, adaptés à la taille de pointeur de la plateforme (`PtrUInt`/`PtrInt` sont les noms FPC et mORMot ; la RTL Delphi ne les déclare pas).

## Exemples

### Mauvais (déclenche la règle)

```pascal
Diff := Cardinal(P1) - Cardinal(P2);   // upper 32 bits lost on Win64
```

### Bon (correction idiomatique)

```pascal
Diff := NativeUInt(P1) - NativeUInt(P2);   // pointer-wide cast
```
