# SCA174 — TList<T> rempli de T.Create - les éléments fuient a la libération

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> TList<TFoo>.Create plus Add(TFoo.Create) - la liste ne possède pas ses éléments, chaque instance TFoo fuit

## Description

TList<T> est un conteneur typé qui ne possède PAS ses éléments - libérer la liste ne libère pas les éléments qu'elle contient. Quand les éléments sont des instances de classe allouées avec .Create, ils fuient à chaque libération de la liste, sauf si l'appelant parcourt et libère manuellement chacun d'eux. Le bon conteneur est TObjectList<T> de Generics.Collections, qui a OwnsObjects=True par défaut et libère ses éléments à sa destruction. Le détecteur parcourt chaque méthode, collecte toutes les affectations `TList<T>.Create` (où T est un identificateur qui ressemble à une classe), puis recherche des motifs `<varname>.Add(<T>.Create)` dans la même méthode. La possession entre méthodes (Add dans une autre méthode que Create) n'est pas suivie.

## Exemples

### Mauvais (déclenche la règle)

```pascal
L := TList<TFoo>.Create;
L.Add(TFoo.Create);
L.Free; // TFoo instance leaks
```

### Bon (correction idiomatique)

```pascal
L := TObjectList<TFoo>.Create; // OwnsObjects=True default
L.Add(TFoo.Create);
L.Free; // item freed
```
