## Description

Un `begin..end` vide est presque toujours un reste de refactoring ou un emplacement réservé jamais complété. Soit le supprimer, soit implémenter la logique manquante. Les sections d'initialisation `begin end.` au niveau de l'unité sont exclues (c'est la forme d'initialisation vide, pas un reste de refactoring). Correspond à SonarDelphi communitydelphi:EmptyBlock.

## Exemples

### Mauvais (déclenche la règle)

```pascal
if Active then begin end;
```

### Bon (correction idiomatique)

```pascal
if Active then Activate;
```
