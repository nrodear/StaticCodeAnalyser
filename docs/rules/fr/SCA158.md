# SCA158 — PChar(s) +/- décalage sans test de chaîne vide

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> `PChar(s) + n` et variantes sans test préalable de `s` vide - pour une chaîne plus courte que n, le pointeur pointe au-delà du terminateur

## Description

Analyse lexicale de `PChar|PAnsiChar|PWideChar(<id>) [+-] <offset>`. Une fenêtre de 200 caractères en arrière recherche des motifs de garde : `<id> <> ''`, `<id> = ''`, `Length(<id>) ...` ou `Assigned(<id>)`. Si aucune garde n'est trouvée, l'arithmétique est signalée. Pour une chaîne vide, `PChar(s)` renvoie un pointeur vers un caractère #0 statique (pas nil), donc `PChar(s) + 5` pointe cinq caractères au-delà de ce terminateur ; il en va de même pour toute chaîne plus courte que le décalage. Lire via un tel pointeur renvoie des données parasites ou provoque une violation d'accès. Le code interne de mORMot protège systématiquement par des tests explicites de chaîne vide ; le code utilisateur qui copie l'idiome d'arithmétique PChar omet souvent la garde. Limites : la fenêtre arrière est de 200 caractères (les tests plus éloignés ne sont pas vus) ; l'arithmétique via `Inc(p, ...)` sur une variable PChar affectée auparavant n'est PAS détectée (il faudrait une analyse de flux).

## Exemples

### Mauvais (déclenche la règle)

> Cette règle signale avec une confiance faible : avec la valeur par défaut `[Rules] MinConfidence=medium`, l'exemple ci-dessous reste masqué. Avec `[Rules] MinConfidence=low`, il apparaît.

```pascal
p := PChar(s) + 5;       // s shorter than 5 chars -> p points behind the terminator
```

### Bon (correction idiomatique)

```pascal
if Length(s) >= 5 then
  p := PChar(s) + 5;
```
