# SCA168 — Instruction case sans branche else

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> L'instruction case n'a pas de branche else - les valeurs non traitées passent silencieusement ; un else suivant un if dans le dernier bras est le else du case

## Description

Une instruction case sans branche else ignore silencieusement toutes les valeurs qui ne sont pas listées explicitement. Quand l'expression du case prend l'une de ces valeurs non traitées, aucune action n'a lieu et aucune erreur n'est levée, ce qui peut masquer des bugs de logique (surtout quand de nouvelles valeurs d'énumération sont ajoutées plus tard sans que les instructions case soient mises à jour). Ajouter `else ;` pour un no-op voulu (qui documente la décision) ou un traitement par défaut qui lève une exception / journalise / fait une assertion. Remarque pour la comparaison avec une version antérieure : jusqu'en 2026-08, le parseur rattachait un else suivant un if dans le dernier bras (`3: if C then Foo; else Bar;`) à ce if plutôt qu'au case, si bien que la règle signalait une branche else manquante sur des instructions case qui en avaient manifestement une. Ces faux positifs ont disparu - 148 sur le corpus de référence - et rien n'a changé dans ce que la règle compte comme violation.

## Exemples

### Mauvais (déclenche la règle)

```pascal
case Status of
  stNew    : DoNew;
  stActive : DoActive;
end;
```

### Bon (correction idiomatique)

```pascal
case Status of
  stNew    : DoNew;
  stActive : DoActive;
else
  raise EInvalidOpException.Create('Unhandled status');
end;
```
