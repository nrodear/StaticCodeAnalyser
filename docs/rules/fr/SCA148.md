# SCA148 — Méthode d'instance n'accédant jamais à Self - pourrait être de classe

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Une méthode qui n'utilise que ses paramètres (ni Self, ni champs d'instance, ni chaîne virtuelle) est fonctionnellement une méthode de classe - la déclarer comme telle

## Description

Quand une méthode d'instance ne touche jamais `Self`, un champ d'instance ou `inherited`, le paramètre implicite `Self` est gaspillé - la méthode est en fait sans état. La déclarer `class function ... static` économise le passage d'un pointeur, rend explicite l'intention sans état et permet aux appelants de l'invoquer sans instance (`TMath.Add(1, 2)` au lieu de `MyMath.Add(1, 2)`). Le détecteur parcourt les nœuds `nkMethod` qui appartiennent à une classe (nom qualifié comme `TFoo.Bar`), ignore les méthodes déjà de classe (`;class` dans le TypeRef), les polymorphes (`;virtual`/`;override`/`;dynamic`/`;abstract`), les constructeurs et destructeurs, puis recherche récursivement tout identificateur nommé `self`, tout `inherited` ou toute référence de champ `F<UppercaseLetter>`. Rien de tout cela -> résultat. Limites : l'accès implicite à une propriété sans préfixe `Self.` n'est pas détecté comme accès à l'instance, de sorte que des appels comme `Bar := ...` pour une propriété peuvent produire un faux positif. Correspond à la règle Sonar-50 #50.

## Exemples

### Mauvais (déclenche la règle)

> Cette règle signale avec une confiance faible : avec la valeur par défaut `[Rules] MinConfidence=medium`, l'exemple ci-dessous reste masqué. Avec `[Rules] MinConfidence=low`, il apparaît.

```pascal
function TMath.Add(A, B: Integer): Integer;
begin
  Result := A + B;          // only uses params, no Self
end;
```

### Bon (correction idiomatique)

```pascal
class function TMath.Add(A, B: Integer): Integer;
begin
  Result := A + B;
end;
// Caller: TMath.Add(1, 2)   // no instance needed
```
