# SCA157 — SetLength(arr, Length(arr) + N) dans une boucle

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Agrandir un tableau dynamique d'un élément (ou de N) dans une boucle for/while/repeat coûte quadratiquement - agrandir une fois avant la boucle ou procéder par blocs

## Description

Analyse lexicale de tout mot-clé `for|while|repeat` suivi, à moins de 600 caractères, de `SetLength(<id>, Length(<id>) + ...)` où les deux noms `<id>` sont identiques (le tableau s'agrandit lui-même). Chaque réallocation copie le contenu existant - n itérations coûtent n*(n+1)/2 copies d'éléments au lieu de n. À 10_000 éléments, c'est ~5000 fois plus lent qu'un SetLength unique. Piège de performance courant avec mORMot quand le code utilisateur accumule des résultats sans connaître la taille finale. Seul le premier agrandissement par boucle est signalé, pour éviter le spam. `SetLength(A, Length(B)+1)` (tableaux différents) n'est PAS signalé - ce motif est rare et généralement délibéré.

## Exemples

### Mauvais (déclenche la règle)

```pascal
for i := 0 to Source.Count - 1 do
begin
  SetLength(Dest, Length(Dest) + 1);  // O(n*n)
  Dest[High(Dest)] := Source[i];
end;
```

### Bon (correction idiomatique)

```pascal
SetLength(Dest, Source.Count);
for i := 0 to Source.Count - 1 do
  Dest[i] := Source[i];
```
