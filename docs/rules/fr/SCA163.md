# SCA163 — API shell appelée avec concaténation dans les arguments

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Vulnerability-darkred)

> ShellExecute / CreateProcess / WinExec avec `+` dans les arguments - si un opérande est contrôlable, cela devient un vecteur d'injection de commande

## Description

Construire la chaîne de commande par concaténation (`PChar('cmd /c ' + UserInput)`) permet à un attaquant d'ajouter des commandes supplémentaires lorsque l'entrée n'est pas strictement validée. Ce détecteur parcourt l'AST et signale tout nkCall dont le nom de méthode (sans qualificateur) est l'un des points d'entrée shell connus ET dont la liste d'arguments contient un opérateur `+` EN DEHORS de tout littéral de chaîne. Comme il est impossible de dire statiquement si un opérande est contaminé, le résultat est émis avec Confidence = Low ; il n'apparaît dans l'interface que si le seuil de confiance minimale est réglé sur 'low'. Correction : passer les arguments via le tableau de paramètres dédié (CreateProcess) ou les échapper/valider avant la concaténation, préférer ShellExecuteEx avec une structure SHELLEXECUTEINFO.

## Exemples

### Mauvais (déclenche la règle)

> Cette règle signale avec une confiance faible : avec la valeur par défaut `[Rules] MinConfidence=medium`, l'exemple ci-dessous reste masqué. Avec `[Rules] MinConfidence=low`, il apparaît.

```pascal
ShellExecute(0, 'open', PChar('cmd /c ' + UserInput), nil, nil, SW_SHOW);
```

### Bon (correction idiomatique)

```pascal
// Validate UserInput against a strict whitelist, then:
ShellExecute(0, 'open', 'cmd.exe', PChar('/c safe_command'), nil, SW_SHOW);
```
