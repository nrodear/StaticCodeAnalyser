# SCA162 — Utilisation d'un algorithme cryptographique faible ou obsolète

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Vulnerability-darkred)

> Nom d'algorithme ('MD5', 'SHA1', 'DES', 'RC4', 'TLS1.0', 'SSLv3') ou classe d'encapsulation (THashMD5, TIdHashSHA1, ...) référencée - vulnérable aux collisions et aux attaques à texte clair connu

## Description

MD5 présente des collisions praticables depuis 2004 (Wang et al.), SHA1 depuis 2017 (SHAttered, préfixe identique ; préfixe choisi depuis 2020). DES utilise 56 bits et peut être cassé par force brute, 3DES subit la collision CBC Sweet32 (CVE-2016-2183). RC4 présente des biais statistiques documentés et est interdit par la RFC 7465. TLS 1.0 / 1.1 sont déclarés obsolètes par la RFC 8996 (BEAST, POODLE, Lucky13). SSLv3 a été rendu caduc par POODLE (CVE-2014-3566). Le détecteur reconnaît les noms d'algorithmes, délimités comme mots, dans les littéraux de chaîne et les identificateurs, ET un ensemble de noms de classes d'encapsulation connues (correspondance de sous-chaîne). Correction : passer à SHA-256/SHA-3 pour le hachage, à AES-GCM / AES-CCM pour le chiffrement symétrique, et à TLS 1.2 au minimum (1.3 de préférence).

## Exemples

### Mauvais (déclenche la règle)

```pascal
algo := 'MD5';
Hash := THashMD5.GetHashString(Input);
```

### Bon (correction idiomatique)

```pascal
algo := 'SHA256';
Hash := THashSHA2.GetHashString(Input);
```
