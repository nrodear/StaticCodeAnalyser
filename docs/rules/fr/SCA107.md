# SCA107 — Le membre public pourrait être strict private

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Le membre public n'est référencé QUE par des méthodes de sa propre classe - `strict private` atteint l'encapsulation la plus forte

## Description

Analyse d'un seul fichier : chaque appelant visible du membre `public` est lui-même une méthode de la MÊME classe (aucune classe sœur, aucune procédure de niveau supérieur, aucune sous-classe dans cette unité). `strict private` (D2007+, portée de classe, pas d'unité) est la visibilité correcte la plus restrictive. Même réserve liée à l'analyse d'un seul fichier que pour CanBeUnitPrivate : les consommateurs d'autres unités sont invisibles et le compilateur garantit la correction via E2361 si le changement casse quelque chose. Exclusions : published, virtual/abstract/override/dynamic, constructeurs/destructeurs de classe, bases pilotées par RTTI (TForm/TFrame/TDataModule/TComponent), classes utilitaires composées uniquement de méthodes de classe. Masquer ligne par ligne avec `// noinspection CanBeStrictPrivate` pour une surface publique intentionnelle.

## Exemples

### Mauvais (déclenche la règle)

> Cette règle signale avec une confiance faible : avec la valeur par défaut `[Rules] MinConfidence=medium`, l'exemple ci-dessous reste masqué. Avec `[Rules] MinConfidence=low`, il apparaît.

```pascal
type
  TFoo = class
  public
    procedure Helper;       // only TFoo.Run calls it
    procedure Run;
  end;
```

### Bon (correction idiomatique)

```pascal
type
  TFoo = class
  strict private
    procedure Helper;
  public
    procedure Run;
  end;
```
