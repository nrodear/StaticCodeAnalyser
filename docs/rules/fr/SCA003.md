# SCA003 — Chaîne SQL construite par concaténation

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Vulnerability-darkred)

> Chaîne SQL concaténée avec '+' et un opérande non littéral (risque d'injection si cet opérande n'est pas fiable)

## Description

Construire du SQL via 'WHERE x=' + opérande permet une injection SQL lorsque cet opérande n'est pas fiable. Le détecteur signale la CONCATÉNATION - il ne suit pas l'origine de l'opérande, un résultat est donc une piste de revue, pas la preuve d'une vulnérabilité. Les concaténations de littéraux uniquement, les masques de format entiers et les fonctions d'assainissement connues sont déjà exclus. Utiliser plutôt des requêtes paramétrées (Params.ParamByName(...).Value := ...).

## Exemples

### Mauvais (déclenche la règle)

```pascal
Query.SQL.Text := 'SELECT * FROM Users WHERE Name=''' + UserName + '''';
```

### Bon (correction idiomatique)

```pascal
Query.SQL.Text := 'SELECT * FROM Users WHERE Name=:n';
Query.ParamByName('n').AsString := UserName;
```
