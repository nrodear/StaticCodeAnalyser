# SCA115 — URL HTTP en clair

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Security%20Hotspot-orange)

> Littéral `'http://...'` pour un point d'accès distant - vulnérable a l'interception

## Description

Un littéral de chaîne commençant par `http://` pour tout point d'accès autre que localhost transmet sa charge utile sans chiffrement. Identifiants de connexion, jetons de session et données personnelles circulent en clair et peuvent être interceptés ou modifiés par tout acteur réseau actif. La correction ne coûte pratiquement rien : passer le schéma à `https://` (presque tous les services modernes prennent en charge les deux). Le détecteur extrait l'hôte du littéral (userinfo, port et crochets IPv6 retirés) et reste muet quand cet hôte ne peut pas être un point d'accès joignable : bouclage et IPC locale (`localhost`, `127.x.x.x`, `[::1]`, `0.0.0.0`, `host.docker.internal`, la forme de socket `http://unix:` de mORMot) ainsi que les plages réservées à la documentation et aux tests (RFC 2606 `example.com/.net/.org`, `.example`, `.test`, `.invalid` ; RFC 5737 `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24` ; RFC 3849 `2001:db8::/32` ; et les plages lien-local `169.254.0.0/16` et `fe80::/10`, qui ne sont pas des plages de documentation mais n'apparaissent dans les littéraux du code source que comme fixtures de parseur ou exemples de diagnostic - un vrai déploiement sur `fe80::` exige un index de zone, et `169.254.x` n'apparaît que lorsque DHCP a échoué). Les plages LAN privées (RFC 1918) ne sont délibérément PAS ignorées - un appel REST `http://192.168.x.y` est un vrai point d'accès en clair. Les URI d'espaces de noms XML (`xmlns=`, `schemas`, `w3.org`, ...) sont des identités, pas des cibles réseau, et sont également ignorées.

## Exemples

### Mauvais (déclenche la règle)

```pascal
Url := 'http://api.contoso-shop.de/v1/users';
```

### Bon (correction idiomatique)

```pascal
Url := 'https://api.contoso-shop.de/v1/users';
```
