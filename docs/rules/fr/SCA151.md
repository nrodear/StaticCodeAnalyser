# SCA151 — La fonction renvoie toujours le même littéral

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Tous les chemins de la fonction affectent le même littéral à Result - la logique conditionnelle ne change rien au comportement, remplacer la fonction par une constante

## Description

Quand chaque affectation à `Result` (ou au nom de la fonction dans le style Pascal classique) est le même littéral, la fonction renvoie ce littéral quelles que soient les entrées. La structure conditionnelle est morte - soit une refactorisation inachevée (une branche n'a jamais été mise à jour), soit des branches qui auraient dû produire des valeurs différentes ne le font pas. Le détecteur parcourt les `nkMethod` dont le `TypeRef` déclare un type de retour, collecte les nœuds `nkAssign` dont la partie gauche vaut `result` ou le nom non qualifié de la fonction, extrait le littéral de droite (nombre, littéral de chaîne, True/False/nil) et signale quand au moins deux de ces affectations partagent exactement le même littéral et qu'aucune affectation non littérale n'existe. Correspond à la règle Sonar-50 #43.

## Exemples

### Mauvais (déclenche la règle)

```pascal
function GetTimeout: Integer;
begin
  if SlowMode then
    Result := 30
  else
    Result := 30;       // <- always 30
end;
```

### Bon (correction idiomatique)

```pascal
const DEFAULT_TIMEOUT = 30;

function GetTimeout: Integer;
begin
  Result := DEFAULT_TIMEOUT;
end;
```
