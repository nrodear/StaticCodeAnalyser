# SCA194 — Fichier source hors du projet

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Un fichier .pas/.dfm se trouve dans le dossier du projet mais n'est pas référencé par le projet (.dproj/.groupproj) - probablement un fichier source orphelin

## Description

S'exécute uniquement pour les analyses de projet et de groupe de projets (--project / --project-group, ou choix d'un .dproj/.groupproj via le dialogue '...'), où la liste exacte des fichiers du projet (DCCReferences) est connue. Le détecteur parcourt récursivement le répertoire du fichier projet à la recherche de fichiers .pas et .dfm et signale chacun de ceux que le projet ne référence pas. Un .dfm compte comme inclus quand son .pas associé est référencé. Les fichiers qui SONT tirés via uses sont signalés comme SCA195 à la place (ils ne sont pas morts). Cas typiques : unités laissées après un refactoring, copies expérimentales, ou fichiers retirés du projet mais pas du disque. Limite v1 : seuls les fichiers DANS l'arborescence du dossier du projet sont contrôlés - les unités référencées depuis l'extérieur via des DCCReferences relatives en '..' et les unités du chemin de recherche ne sont ni parcourues ni signalées. Les analyses récursives de répertoire et les analyses d'un seul fichier n'exécutent pas ce contrôle (pas de notion d'appartenance au projet). Correction : supprimer le fichier, ou le sortir du dossier du projet (s'il est réellement utilisé, SCA195 indique au contraire de l'ajouter).

## Exemples

### Mauvais (déclenche la règle)

```pascal
MyProject.dproj references uMain, uData - but the folder also contains uOldHelper.pas (not referenced) -> flagged
```

### Bon (correction idiomatique)

```pascal
Remove uOldHelper.pas or move it out of the project folder - since the SCA194/SCA195 split this finding means the file is not referenced by any uses; a unit that IS used but unlisted is reported as SCA195 (add it to the project) instead
```
