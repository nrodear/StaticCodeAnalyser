# SCA203 — La boucle for dépasse le dernier indice

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Bug-red)

> La boucle for va jusqu'à Count, Length() ou High() + 1 et indexe la même collection avec la variable de boucle - le dernier passage est hors limites

## Description

Un off-by-one classique : 'for i := 0 to List.Count do' avec List[i] dans le corps lit List[List.Count], un élément au-delà de la fin. Le compilateur l'accepte ; à l'exécution, cela lève ERangeError avec {$R+}, EArgumentOutOfRangeException ou EStringListError pour TList et TStrings, et sinon lit ou écrit silencieusement la mémoire située après le dernier élément. Sont signalées les têtes de boucle dont la borne supérieure va un indice trop loin - 'X.Count' (depuis 0, ou depuis 1 quand X est une liste prouvée), 'Length(A)' depuis 0, 'Low(A) to Length(A)' pour un tableau dynamique, 'High(A) + 1' - quand le corps lit ou écrit la même collection (même nom ou même chaîne d'accès) avec la variable de boucle non décalée : X[i], X[i, j], et pour .Count aussi X.Items[i], X.Strings[i] et X.Objects[i]. Les chaînes commencent à 1 et ont leurs propres formes : '0 to Length(S)' avec S[i] est faux aux deux bouts (S[0] avant le premier caractère), '1 to Length(S) + 1' au-delà du dernier ; '1 to Length(S)' est correct. Le résultat n'est une erreur que si le type est prouvé : la collection est un nom déclaré dans l'unité (paramètre, variable locale ou inline, Result, champ de la propre classe de la méthode ou de ses ancêtres dans l'unité, variable d'unité) dont le type est une liste connue (TList, TObjectList, TStrings, TStringList, TCollection, TMenuItem, FPC TFPList/TFPGList ...), un tableau ou une chaîne, et le corps ne quitte pas le passage avant l'accès (break, exit, continue, raise, goto), ne fait pas grandir la collection et ne contient pas de méthode anonyme. Sinon, c'est un avertissement. Correction : Count - 1, High(A) (ou Length(A) - 1) et, pour les chaînes, 1 to Length(S).

## Exemples

### Mauvais (déclenche la règle)

```pascal
for i := 0 to Names.Count do
  WriteLn(Names[i]);   // Names[Names.Count] raises
```

### Bon (correction idiomatique)

```pascal
for i := 0 to Names.Count - 1 do
  WriteLn(Names[i]);
```

## Volontairement non signalé

Le détecteur garde volontairement le silence sur les constructions ci-dessous. Chacune est une classe de faux positifs mesurée sur le corpus réel — ce n'est pas une supposition.

### Shifted index, insert position, other collection

Only an access with the plain loop variable proves the last pass is out of range. X[i - 1] with '1 to X.Count', X.Insert(i, ..) (valid up to Count) and an index into another collection (M[i] while counting L, X.L[i] while counting L) are correct or not decidable lexically.

```pascal
for i := 1 to L.Count do S := L[i - 1];  // not reported
```

### A guard on the loop variable

When an if, while, case or until condition in the body before or with the first access names the loop variable outside the index (if i < L.Count, if i = Length(A) then .. else A[i]), the extra pass is deliberate - typically a sentinel step after the last element.

```pascal
for i := 0 to Length(A) do if i = Length(A) then Flush else Add(A[i]);  // not reported
```

### Forms that are correct without a type proof

'1 to X.Count' is not reported for an unproven X: COM collections such as Excel's Sheets are 1-based. 'Low(A) to Length(A)' is reported only for a dynamic array: for a static 'array[1..N]' and for a string it is correct. '1 to Length(S) + 1' needs a proven string. ShortString and PChar are not reported for Length: S[0] is the length byte and P[Length(P)] the terminating #0. For TDictionary-like types X[i] is a key, not a position.

```pascal
for i := 1 to Sheets.Count do Sheets[i].Calculate;  // not reported
```

### Known limits

The loop variable assigned in the body vetoes the finding. downto loops, bounds with further arithmetic (Count - 1, Pred(Count)), named indexed properties other than Items, Strings and Objects (RTID.ThreadIDs[i] while counting RTID.Count) and accesses through 'with' are not reported.

```pascal
for i := 0 to RTID.Count do TID := RTID.ThreadIDs[i];  // not reported (false negative)
```
