# SCA114 — TThread libéré par FreeAndNil - vérifier l'arrêt

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Bug-red)

> `FreeAndNil(MyThread)` sans `Terminate` à proximité - une indication à vérifier, pas un défaut prouvé : `TThread.Destroy` arrête lui-même le thread ; vérifier `Execute`, le destructeur du thread et `FreeOnTerminate`

## Description

Indication à vérifier, pas un défaut prouvé. `TThread.Destroy` arrête lui-même le thread : il appelle `Terminate`, reprend un thread suspendu et attend que `Execute` soit terminé, donc `FreeAndNil(MyThread)` seul est sûr. Vérifier trois choses à la ligne signalée. `Execute` respecte-t-il `Terminated` ? Sinon, le destructeur attend que `Execute` se termine de lui-même. Un destructeur de la classe du thread libère-t-il des champs qu'`Execute` utilise seulement après `inherited` ? Son corps s'exécute avant que `TThread.Destroy` arrête le thread. `FreeOnTerminate` est-il positionné ? Un tel thread se libère lui-même à la fin d'`Execute`, il ne doit donc pas être libéré aussi de l'extérieur. Un `WaitFor` supplémentaire n'apporte rien : il ne revient pas pour un thread créé suspendu et jamais démarré. Heuristique : signale `FreeAndNil(<id>)` quand `<id>` a un type thread (le type déclaré ou construit se termine par `Thread` ou dérive de TThread dans le même fichier ; si aucun type n'est résolu, l'identificateur contient `thread`) et que les ~500 caractères précédents (environ 10 lignes) ne contiennent ni `<id>.Terminate` ni `<id>.WaitFor`. Aucun résultat après `TerminateThread(<id>`, sous une garde positive `if <id>.Finished`, ou quand un `Execute` de la classe du thread dans la même unité référence `Terminated`. La forme simple `.Free` n'est pas vérifiée, et le détecteur ne s'exécute que sur les fichiers qui mentionnent `TThread`, `.Synchronize`, `.Resume`, `.Queue`, `ParamByName` ou `FieldByName`. Masquer avec `// noinspection TThreadDestroyWithoutTerminate` pour les classes qui ne sont pas des threads.

## Exemples

### Mauvais (déclenche la règle)

```pascal
type
  TWorkerThread = class(TThread)
  protected
    procedure Execute; override;
  end;

var
  FWorkerThread: TWorkerThread;

procedure TWorkerThread.Execute;
begin
  RunLongJob;                 // never looks at Terminated
end;

procedure TMainForm.BtnStopClick(Sender: TObject);
begin
  FreeAndNil(FWorkerThread);  // waits until RunLongJob has returned
end;
```

### Bon (correction idiomatique)

```pascal
type
  TWorkerThread = class(TThread)
  private
    FQueue: TList;
  protected
    procedure Execute; override;
  public
    destructor Destroy; override;
  end;

var
  FWorkerThread: TWorkerThread;

procedure TWorkerThread.Execute;
begin
  while not Terminated do
    DoStep;
end;

destructor TWorkerThread.Destroy;
begin
  inherited;                  // ends the thread first
  FreeAndNil(FQueue);         // Execute no longer runs
end;

procedure TMainForm.BtnStopClick(Sender: TObject);
begin
  FreeAndNil(FWorkerThread);  // Destroy ends the thread itself
end;
```
