# SCA026 — Identifiants de base de données en dur dans le DFM

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Vulnerability-darkred)

> Password en clair ou ConnectionString avec Pwd= sur un composant de base de données

## Métadonnées

| **Kind** | `DfmHardcodedDbCreds` |

| **CWE** | [CWE-798](https://cwe.mitre.org/data/definitions/798.html) |
| **OWASP** | A07:2021-Identification-and-Authentication-Failures |

## Description

Les identifiants de base de données enregistrés dans un .dfm fuient dans le contrôle de version, les artefacts de build et n'importe quel décompilateur. Déplacer les secrets vers des variables d'environnement, le magasin d'identifiants du système d'exploitation ou une configuration chiffrée, et les affecter à l'exécution.

## Exemples

### Mauvais (déclenche la règle)

```pascal
object FDConnection1: TFDConnection
  Params.Strings = ('Password=admin123' 'User_Name=sa')
end
```

### Bon (correction idiomatique)

```pascal
FDConnection1.Params.Values['Password'] := GetEnvironmentVariable('DB_PWD');
```
