# SCA185 — Fichier source UTF-8 sans BOM

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Fichier UTF-8 sans BOM contenant du non-ASCII - le compilateur le lit comme de l'ANSI (mojibake)

## Description

Un fichier source enregistré en UTF-8 sans marque d'ordre des octets et contenant des caractères non-ASCII est lu par le compilateur Delphi comme de l'ANSI (page de codes système, GetACP) - ce qui produit du mojibake dans les littéraux de chaîne à l'exécution, et le résultat dépend de la machine. Correction : enregistrer en UTF-8 avec BOM, ou compiler le projet avec --codepage:65001. Un caractère non-ASCII dans un littéral de chaîne ou un identificateur est signalé avec une confiance moyenne (visible par défaut) ; un fichier dont les caractères non-ASCII se trouvent uniquement dans des commentaires est signalé avec une confiance faible, car le compilateur ignore les commentaires. Dialecte FPC/Lazarus : cette règle est ignorée quand l'analyse s'exécute avec --dialect=fpc - l'UTF-8 sans BOM est la NORME de Lazarus (l'IDE Lazarus lui-même enregistre sans BOM, et FPC lit l'UTF-8 par défaut), donc un BOM manquant n'y est pas un défaut. Les règles sœurs (UTF-8 invalide, sources ANSI) restent actives.

## Exemples

### Mauvais (déclenche la règle)

> Une partie des résultats de cette règle porte une confiance faible (voir la description) et reste masquée avec la valeur par défaut `[Rules] MinConfidence=medium` ; avec `[Rules] MinConfidence=low`, tous apparaissent.

```pascal
// file saved as UTF-8 WITHOUT BOM, with non-ASCII text
ShowMessage('...non-ASCII...');  // compiler reads ANSI -> mojibake at runtime
```

### Bon (correction idiomatique)

```pascal
// same file saved as UTF-8 WITH BOM (EF BB BF), or build --codepage:65001
ShowMessage('...non-ASCII...');
```
