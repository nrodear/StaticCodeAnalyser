# SCA175 — Méthode anonyme capturant la variable de boucle par référence

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Bug-red)

> Une méthode anonyme dans `for i := ... do` référence i - toutes les closures voient la même valeur finale

## Métadonnées

| Champ | Valeur |
|---|---|
| **Identifiant de règle** | `SCA175` |
| **Kind** | `AnonMethodCaptureLoopVar` |
| **Sévérité par défaut** | Error |
| **Type** | Bug |

## Description

Delphi capture les variables par référence dans les méthodes anonymes. Quand la méthode anonyme est créée dans une boucle for et référence la variable de boucle, toutes les closures partagent la même référence - au moment où les closures s'exécutent, la variable de boucle a atteint sa valeur terminale et toutes observent cette valeur finale. Le symptôme classique : N threads parallèles créés dans une boucle journalisent tous le numéro de la dernière itération au lieu de 0..N-1. Le détecteur parcourt les instructions for, extrait le nom de la variable de boucle (`for i :=` classique ou `for var i :=` inline) et examine les descendants nkCall / nkAssign à la recherche de la combinaison d'un mot-clé `procedure` (début de méthode anonyme) et d'une référence à la variable de boucle. Correction : copier la variable de boucle dans une variable locale juste avant le corps de la méthode anonyme.

## Exemples

### Mauvais (déclenche la règle)

```pascal
for i := 0 to 9 do
  TThread.CreateAnonymousThread(procedure
  begin WriteLn(i); end).Start;
```

### Bon (correction idiomatique)

```pascal
for i := 0 to 9 do
begin
  var Captured := i;
  TThread.CreateAnonymousThread(procedure
  begin WriteLn(Captured); end).Start;
end;
```
