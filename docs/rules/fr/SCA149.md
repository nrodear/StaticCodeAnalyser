# SCA149 — La méthode masque une méthode virtuelle parente sans `override`

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Une méthode redéclarée dans une classe dérivée avec le même nom qu'une méthode parente virtuelle ou dynamique, mais sans `override`, casse le polymorphisme - le compilateur émet W1010

## Description

Sans `override`, le compilateur traite la méthode de la sous-classe comme une nouvelle méthode. La répartition polymorphe via la vtable du parent appelle toujours l'implémentation du parent - `Base := Derived; Base.DoWork` exécute `TBase.DoWork`, pas `TDerived.DoWork`. Le compilateur avertit (W1010), mais de nombreuses bases de code désactivent cette indication. Le détecteur parcourt les nœuds `nkClass`, identifie leur parent direct dans la même unité, collecte les méthodes du parent ayant `;virtual` ou `;dynamic` dans le `TypeRef`, puis vérifie chaque méthode de la sous-classe dont le nom non qualifié correspond à un nom polymorphe du parent : `;override` absent ET `;reintroduce` absent -> résultat. Limites : uniquement au sein de l'unité (les parents d'autres unités comme `TForm`/`TStrings` ne sont pas vus) ; uniquement le parent direct (les chaînes à plusieurs niveaux ne vérifient qu'un seul niveau). Correspond à la règle Sonar-50 #21.

## Exemples

### Mauvais (déclenche la règle)

```pascal
TBase = class
  procedure DoWork; virtual;
end;

TDerived = class(TBase)
  procedure DoWork;          // <- shadows TBase.DoWork (W1010)
end;
```

### Bon (correction idiomatique)

```pascal
TDerived = class(TBase)
  procedure DoWork; override;
end;
```
