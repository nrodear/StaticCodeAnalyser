# SCA165 — Marqueur noinspection inutilisé

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Un `// noinspection X` ne supprime aucun résultat sur sa ligne cible - soit le détecteur s'est amélioré, soit la cible était mauvaise

## Description

Le filtre de suppression (uSuppression) enregistre chaque commentaire `// noinspection KindName` et la ligne de code suivante qu'il vise. Une fois tous les détecteurs terminés, le filtre vérifie quels marqueurs ont effectivement masqué un résultat. Les marqueurs qui n'ont jamais agi sont signalés comme fkUnusedSuppression sur la ligne du marqueur - l'utilisateur doit supprimer le marqueur (l'évolution du détecteur l'a rendu obsolète) ou vérifier si le nom de type visé était erroné. Résistant aux faux négatifs : seuls les marqueurs ayant une ligne cible claire hors commentaire sont pris en compte (les marqueurs en fin de fichier ou dans des blocs de commentaires de documentation purs sont ignorés). Tient compte du profil : dans le profil default, ce conseil apparaît ; qui veut des rapports d'hygiène des suppressions sans le bruit des détecteurs peut lancer l'analyse avec --profile selftest-quiet.

## Exemples

### Mauvais (déclenche la règle)

```pascal
// noinspection MemoryLeak
WriteLn('hello');   // no leak here - suppression never fires
```

### Bon (correction idiomatique)

```pascal
// (Marker entfernt - das Tool flaggt diese Zeile nicht mehr.)
WriteLn('hello');
```
