# SCA206 — Marqueur de désactivation du formateur mal écrit ou sans partenaire

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Marqueur de formateur `{(*}` / `{*)}` mal écrit ou sans partenaire - GExperts, CnWizards et JCF formatent alors quand même la zone ou plus du tout le reste du fichier

## Description

Les commentaires `{(*}` et `{*)}` désactivent le formateur de code pour la zone qui les sépare, puis le réactivent. Ils viennent de DelForExp et sont reconnus par le formateur de GExperts, celui de CnWizards et JEDI Code Format (aussi dans Lazarus) ; le formateur de l'IDE Delphi (Ctrl+D, jusqu'à Delphi 12) les ignore, et Delphi 13 n'est plus livré avec un formateur. Les formateurs n'acceptent que ces quatre caractères exacts - `{ (*}` ou `{*) }` est pour eux un commentaire ordinaire - et les zones ne s'imbriquent pas : un interrupteur, pas un compteur. Sont signalés : un marqueur contenant des espaces ou des tabulations (il est ignoré, la zone est formatée) ; un `{(*}` ouvrant jamais refermé (plus rien n'est formaté ensuite) ; un `{*)}` fermant sans zone ouverte (il ne ferme rien) ; et un second `{(*}` dans une zone ouverte (le premier `{*)}` la termine déjà). Une zone laissée ouverte volontairement jusqu'à la fin du fichier est signalée aussi - la masquer avec `// noinspection FormatterMarker` sur la ligne au-dessus du `{(*}`. Le compilateur voit les deux marqueurs comme de simples commentaires `{ }` ; rien de tout cela ne modifie le programme compilé. Le bilan se fait par fichier ; les branches `{$IFDEF}` sont lues telles quelles, sans être évaluées.

## Exemples

### Mauvais (déclenche la règle)

```pascal
{ (*}
const Table: array[0..3] of Integer = (
  1, 2,
  3, 4);
{*)}
```

### Bon (correction idiomatique)

```pascal
{(*}
const Table: array[0..3] of Integer = (
  1, 2,
  3, 4);
{*)}
```

## Volontairement non signalé

Le détecteur garde volontairement le silence sur les constructions ci-dessous. Chacune est une classe de faux positifs mesurée sur le corpus réel — ce n'est pas une supposition.

### Markers inside strings and comments

The formatters read `{(*}` only as a comment token of its own. Inside a string literal, a `//` comment or a `(* *)` comment it is text - JCF keeps exactly such constants and notes in its own sources.

```pascal
const OLD_NOFORMAT_ON = '{(*}';  // not reported
// {(*} starts a region          - not reported
```

### Comments that only look like markers

Only a `{ }` comment whose content is `(*` or `*)` with nothing but blanks or tabs around it counts. A footnote column such as `{ (*) }` and commented-out code such as `{(* Old := 1; *)}` are ordinary comments - the second is the territory of SCA070.

```pascal
CFM_SMALLCAPS = $0040; { (*)    }  // not reported
{(* Old := 1; *)}                 // not reported
```

### Custom GExperts keywords and JCF directives

GExperts lets you change the start and end keywords, and JCF also knows `//jcf:format=off` and `//jcf:format=on`. The rule knows only the default pair `{(*}` / `{*)}` (deliberate false negative).

```pascal
//jcf:format=off  // not checked
```

### A pair split over {$IFDEF} branches

Branches are counted as they stand, the way CnWizards reads them. JCF skips inactive branches, so for JCF such a pair can be incomplete - the rule does not report it.

```pascal
{$IFDEF DEBUG}
{(*}
{$ELSE}
{*)}
{$ENDIF}  // not reported
```
