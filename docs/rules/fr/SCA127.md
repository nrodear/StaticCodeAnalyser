# SCA127 — Levée de la classe de base `Exception` au lieu d'une sous-classe

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> `raise Exception.Create('...')` - la classe de base ne porte aucune information sémantique, les appelants ne peuvent pas filtrer sélectivement

## Description

Lever la classe de base `Exception` de la RTL équivaut à lancer `new Error('something')` en JavaScript : cela indique à l'appelant *qu'*une erreur s'est produite, mais pas *laquelle*. Le code appelant est alors contraint d'attraper la classe la plus large possible (`on E: Exception do ...`), qui attrape aussi toutes les erreurs d'exécution sans rapport et tend à avaler des bugs. Préférer une sous-classe spécifique (p. ex. `EArgumentOutOfRangeException`, `EFileNotFoundException`, une `EMyDomainError` propre au domaine). Le détecteur parcourt chaque nœud `nkRaise` et le signale quand l'expression levée commence par `Exception.Create` (insensible à la casse) ou est exactement `Exception` (sans appel à Create). Le `raise;` nu (relance) et `raise E;` (variable) ne sont pas signalés. Correspond à `RaisingRawExceptionCheck` de Sonar-Delphi.

## Exemples

### Mauvais (déclenche la règle)

```pascal
if x < 0 then
  raise Exception.Create('x is negative');
```

### Bon (correction idiomatique)

```pascal
if x < 0 then
  raise EArgumentOutOfRangeException.CreateFmt('x = %d', [x]);
```
