# SCA116 — Vérification TLS désactivée

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Vulnerability-darkred)

> `SecureProtocols` vide, `IgnoreCertificateErrors := True` ou `OnVerifyPeer := nil`

## Description

Trois motifs Delphi désactivent silencieusement la validation TLS : (a) `SecureProtocols := []` retire tous les protocoles, ce qui permet un repli vers le texte en clair ou le protocole le plus faible disponible, (b) `IgnoreCertificateErrors := True` accepte n'importe quel certificat, y compris expiré ou auto-signé, (c) `OnVerifyPeer := nil` court-circuite le callback de vérification. Tous trois sont des cibles de choix pour une attaque MITM. Remplacer par des protocoles explicitement modernes uniquement (`[TLSv1_2, TLSv1_3]`), un vrai magasin de confiance, ou un gestionnaire OnVerifyPeer qui épingle l'empreinte. Le détecteur reconnaît lexicalement les trois motifs d'affectation de propriété.

## Exemples

### Mauvais (déclenche la règle)

```pascal
Client.SecureProtocols := [];
Client.IgnoreCertificateErrors := True;
```

### Bon (correction idiomatique)

```pascal
Client.SecureProtocols := [TLSv1_2, TLSv1_3];
Client.OnVerifyPeer := VerifyPinnedFingerprint;
```
