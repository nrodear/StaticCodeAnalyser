# SCA208 — Littéral à virgule flottante qui peut faire planter l'IDE Delphi 12

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

## Description

L'unité contient un littéral à virgule flottante comme 4.90, 1e5 ou 1.5E-3. Le code est correct ; le défaut se trouve dans l'IDE Delphi 12 : lorsque l'unité est affichée dans l'éditeur, l'analyseur géré de l'IDE qui sert à Error Insight peut, pendant sa compilation JIT, rencontrer une exception de virgule flottante x87 non masquée, et l'IDE se termine par un débordement de pile dans clr.dll (0xC00000FD). Observé sur une machine avec Delphi 12.1 Community Edition, avant et après le Patch 1, le plantage n'est survenu que lorsque tout était réuni : Delphi 12 ; un fournisseur Code Insight autre que le fournisseur LSP (le fournisseur classique Borland.CodeInsight.Pascal ou celui d'un paquet tiers) ; un niveau Error Insight différent de None (ErrorInsightLevel différent de 0) ; et l'unité affichée dans l'éditeur. Avec le fournisseur LSP (réglage d'usine), l'IDE n'a pas appelé l'analyseur concerné et n'a pas planté. La même pile d'appels est signalée pour des commandes de refactoring (non mesuré). Avec Delphi 13, le plantage n'a pas été vu lors d'une observation isolée. Cela peut aussi dépendre de la machine ; la règle marque donc des fichiers à risque, pas des plantages certains. Contournements observés sur cette machine, sans modifier le source : passer Code Insight au fournisseur LSP ; régler le niveau Error Insight sur None (le marquage des erreurs disparaît, le repliement de code reste) ; ou démarrer l'IDE avec la variable d'environnement COMPlus_JITMinOpts=1, définie pour le seul processus de l'IDE et non pour tout le compte utilisateur (le marquage des erreurs reste). Ces réglages de l'IDE sont la meilleure voie - le code source n'a pas à être réécrit pour ce défaut. Les littéraux dans des branches {$IFDEF} inactives comptent aussi (l'éditeur les affiche), de même que les littéraux d'un fichier inclus par {$I} ou {$INCLUDE} : ils sont signalés dans l'unité qui inclut, à la directive, et le message nomme le littéral, le fichier inclus et sa ligne. Un signalement par fichier, au premier littéral. La règle est désactivée par défaut : elle ne figure pas dans le profil default, seulement dans strict et style. Seulement là où les réglages de l'IDE ne peuvent pas être modifiés, on peut écrire la valeur sans littéral à virgule flottante, par exemple comme quotient d'entiers (490 / 100) - un contournement du défaut de l'IDE, pas une recommandation de style.

## Exemples

### Mauvais (déclenche la règle)

```pascal
Price := 4.90;  // floating-point literal - showing this unit can crash the Delphi 12 IDE
```

### Bon (correction idiomatique)

```pascal
Price := 490 / 100;  // only if the IDE settings cannot be changed: the same value without a floating-point literal
```

## Volontairement non signalé

Le détecteur garde volontairement le silence sur les constructions ci-dessous. Chacune est une classe de faux positifs mesurée sur le corpus réel — ce n'est pas une supposition.

### Numbers in comments and string literals

Only tokens of the code count. A number in a comment or in a string literal - also the argument of StrToFloat('4.90') - is not a literal; the IDE did not crash on it in the measurements.

```pascal
// 4.90
X := StrToFloat('4.90');  // not reported
```

### Integers, hex literals, ranges and integer division

490, $FF, 1..5 (subrange, array bound, case label) and 49 / 10 contain no floating-point literal; all were measured without a crash.

```pascal
type TSmall = 1..5;
X := 49 / 10;  // not reported
```

### Method call on an integer literal

In 5.ToString and 5.Equals(5) no digit follows the dot and an identifier starts right after it - a method call on an integer, measured without a crash. A dot followed by neither a digit nor an identifier (X := 1.;) was not measured and is reported.

```pascal
S := 5.ToString;  // not reported
```

### The include file itself

Showing an include file with a floating-point literal in the editor did not crash the IDE; the risk lies with the unit that includes it, which is reported at its {$I} directive. A file counts as an include file by its extension .inc only.

```pascal
// scanned file Rates.inc
const Rate = 4.90;  // not reported
```
