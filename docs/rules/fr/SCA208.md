# SCA208 — Littéral à virgule flottante qui peut faire planter l'IDE Delphi 12

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

## Description

L'unité contient un littéral à virgule flottante comme 4.90, 1e5 ou 1.5E-3. Le code est correct ; le défaut se trouve dans l'IDE Delphi 12 : dès que l'unité est affichée dans l'éditeur, l'analyseur géré de l'IDE qui sert au repliement de code et à Error Insight peut échouer sur une exception de virgule flottante non masquée, et l'IDE se termine par un débordement de pile dans clr.dll (0xC00000FD). Cela dépend de la machine (le mot de contrôle x87 du processus de l'IDE) ; la règle marque donc des fichiers à risque, pas des plantages certains. Observé avec Delphi 12.1 Community Edition, avant et après le Patch 1 ; avec Delphi 13, le plantage n'a pas été vu lors d'une observation isolée. Les littéraux dans des branches {$IFDEF} inactives comptent aussi (l'éditeur les affiche), de même que les littéraux d'un fichier inclus par {$I} ou {$INCLUDE} : ils sont signalés dans l'unité qui inclut, à la directive, et le message nomme le littéral, le fichier inclus et sa ligne. Un signalement par fichier, au premier littéral. La règle est désactivée par défaut : elle ne figure pas dans le profil default, seulement dans strict et style. Là où le plantage se produit, un contournement possible consiste à écrire la valeur sans littéral à virgule flottante, par exemple comme quotient d'entiers (490 / 100) - un contournement du défaut de l'IDE, pas une recommandation de style.

## Exemples

### Mauvais (déclenche la règle)

```pascal
Price := 4.90;  // floating-point literal - showing this unit can crash the Delphi 12 IDE
```

### Bon (correction idiomatique)

```pascal
Price := 490 / 100;  // workaround for the IDE fault: the same value without a floating-point literal
```

## Volontairement non signalé

Le détecteur garde volontairement le silence sur les constructions ci-dessous. Chacune est une classe de faux positifs mesurée sur le corpus réel — ce n'est pas une supposition.

### Numbers in comments and string literals

Only tokens of the code count. A number in a comment or in a string literal - also the argument of StrToFloat('4.90') - is not a literal; the IDE did not crash on it in the measurements.

```pascal
// 4.90
X := StrToFloat('4.90');  // not reported
```

### Integers, hex literals, ranges and integer division

490, $FF, 1..5 (subrange, array bound, case label) and 49 / 10 contain no floating-point literal; all were measured without a crash.

```pascal
type TSmall = 1..5;
X := 49 / 10;  // not reported
```

### Method call on an integer literal

In 5.ToString and 5.Equals(5) no digit follows the dot and an identifier starts right after it - a method call on an integer, measured without a crash. A dot followed by neither a digit nor an identifier (X := 1.;) was not measured and is reported.

```pascal
S := 5.ToString;  // not reported
```

### The include file itself

Showing an include file with a floating-point literal in the editor did not crash the IDE; the risk lies with the unit that includes it, which is reported at its {$I} directive. A file counts as an include file by its extension .inc only.

```pascal
// scanned file Rates.inc
const Rate = 4.90;  // not reported
```
