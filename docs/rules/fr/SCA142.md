# SCA142 — La clause uses n'est pas dans l'ordre alphabétique

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Les entrées d'une clause `uses` ne sont pas dans l'ordre alphabétique - les fusions deviennent non déterministes et la relecture plus difficile

## Description

L'ordre alphabétique rend les conflits de fusion déterministes et élimine toute une catégorie de débats stériles en revue de code. Le détecteur parcourt les nœuds `nkUses`, collecte les enfants `nkUsesItem` et compare l'ordre réel à un tri insensible à la casse. Toute différence produit un résultat sur la ligne `uses`. Les clauses à une seule entrée sont ignorées. La sévérité est Conseil, car de nombreux projets regroupent délibérément les entrées par couche (RTL / VCL / tiers / propre) plutôt qu'alphabétiquement - un style à activer volontairement, pas une règle stricte. Correspond à la règle Sonar-50 #47.

## Exemples

### Mauvais (déclenche la règle)

> Cette règle signale avec une confiance faible : avec la valeur par défaut `[Rules] MinConfidence=medium`, l'exemple ci-dessous reste masqué. Avec `[Rules] MinConfidence=low`, il apparaît.

```pascal
uses
  System.SysUtils,
  System.Classes,
  System.IOUtils,                    // <- order broken
  System.JSON;
```

### Bon (correction idiomatique)

```pascal
uses
  System.Classes,
  System.IOUtils,
  System.JSON,
  System.SysUtils;
```
