# SCA178 — API d'ouverture de fichier recevant une saisie utilisateur concaténée

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Vulnerability-darkred)

> Ouverture de fichier (TFileStream.Create, AssignFile, ...) avec un chemin construit à partir d'une saisie utilisateur (Edit.Text, Request.Params, ...) - risque de path traversal

## Description

Vulnérabilité classique de path traversal : une saisie contrôlée par l'utilisateur aboutit dans une API du système de fichiers. Un attaquant peut soumettre `../../../etc/passwd` ou équivalent pour sortir du répertoire prévu et lire/écrire des fichiers arbitraires. Le détecteur signale les expressions qui contiennent à la fois un jeton d'API d'ouverture de fichier (TFileStream.Create, TFile.OpenRead/WriteText, AssignFile, FileOpen, FileCreate) ET un jeton de source de saisie utilisateur (.Text, .Lines.Text, .Caption, .Value, Request.Params, Sender.Text, ParamStr) ET un opérateur `+` (concaténation de chaînes). Le détecteur est heuristique - pas de suivi de contamination - donc des fonctions d'assainissement enveloppantes (p. ex. `Sanitize(edPath.Text)`) déclenchent des faux positifs ; masquer via un marqueur si la fonction d'assainissement est fiable.

## Exemples

### Mauvais (déclenche la règle)

```pascal
Stream := TFileStream.Create(BaseDir + edPath.Text, fmOpenRead);
```

### Bon (correction idiomatique)

```pascal
var SafePath := TPath.Combine(BaseDir, TPath.GetFileName(edPath.Text));
Stream := TFileStream.Create(SafePath, fmOpenRead);
```
