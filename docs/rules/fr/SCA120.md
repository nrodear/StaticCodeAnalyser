# SCA120 — Exception construite mais jamais levée

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Bug-red)

> `EFoo.Create('msg');` alloue un objet exception sans `raise` - le chemin d'erreur est sauté silencieusement

## Description

Le motif `EConvertError.Create('bad input');` sans `raise` devant construit une instance d'exception, ne la lève pas, et le code appelant continue comme si de rien n'était. L'objet alloué fuit (TObject classique) ou est immédiatement collecté (ARC), et la branche d'erreur prévue disparaît. Il s'agit presque toujours d'une régression de copier-coller à partir de `raise EConvertError.Create(...)` où le mot-clé `raise` a été supprimé. Heuristique du détecteur : tout `nkCall` nommé `<Ident>.Create(...)` où `<Ident>` est `Exception` ou suit la convention Delphi du préfixe `E` (`E` + lettre majuscule, p. ex. `EConvertError`, `EMyDomainError`). `raise X.Create(...)` est consommé comme chaîne par le parseur de l'instruction raise et ne produit jamais de `nkCall`, si bien que les exceptions réellement levées ne sont pas des faux positifs. Correspond à `MissingRaiseCheck` de Sonar-Delphi.

## Exemples

### Mauvais (déclenche la règle)

```pascal
procedure Validate(x: Integer);
begin
  if x < 0 then
    EArgumentOutOfRangeException.Create('x negative');  // never raised!
end;
```

### Bon (correction idiomatique)

```pascal
procedure Validate(x: Integer);
begin
  if x < 0 then
    raise EArgumentOutOfRangeException.Create('x negative');
end;
```
