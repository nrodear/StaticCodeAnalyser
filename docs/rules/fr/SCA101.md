# SCA101 — Branche sans bloc begin..end

> `then`/`else`/`do <instruction>` - préférer un `begin..end` explicite

## Description

Une branche à instruction unique sans `begin..end` est facile à mal lire ; ajouter plus tard une deuxième instruction sans recréer de bloc est une source classique de bugs où l'indentation contredit la sémantique. Règle de style débattue (de nombreuses bases de code Delphi utilisent délibérément la forme compacte) - lsHint, facile à désactiver dans les profils. La chaîne `else if`, `raise`/`exit`/`break`/`continue` et les autres instructions ouvrant un bloc sont explicitement autorisées. Correspond à SonarDelphi communitydelphi:BeginEndRequired.

## Exemples

### Mauvais (déclenche la règle)

```pascal
if Active then DoStuff;
```

### Bon (correction idiomatique)

```pascal
if Active then
begin
  DoStuff;
end;
```
