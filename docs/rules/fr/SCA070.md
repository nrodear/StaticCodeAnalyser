## Description

Heuristique : un contenu de commentaire avec 2 marqueurs de style code ou plus (`;` final, `:=`, mots-clés `begin`/`end`/`procedure`/`function`/`if`/`then`/`for`/`while`) est presque certainement du code mis en commentaire. Ce code pourrit en silence : personne n'ose le supprimer, personne ne le met à jour. Soit le supprimer, soit le remplacer par un TODO qui explique l'intention. Une ligne `//` n'est signalée que si aucune des lignes voisines n'est elle aussi un commentaire `//` - un bloc `//` de plusieurs lignes est traité comme de la documentation avec des exemples de code - et un commentaire en fin de ligne après du code n'est pas signalé non plus. Les lignes signalées adjacentes (p. ex. des commentaires `{ ... }` consécutifs) sont signalées comme UN SEUL résultat couvrant le bloc (endLine marque l'étendue) ; une ligne signalée isolée conserve le message par ligne. Correspond à SonarDelphi communitydelphi:CommentedOutCode.

## Exemples

### Mauvais (déclenche la règle)

```pascal
LoadSettings;
// FCacheSize := 42;
ApplySettings;
```

### Bon (correction idiomatique)

```pascal
LoadSettings;
// TODO: re-enable once issue #123 is fixed - see history
ApplySettings;
```
