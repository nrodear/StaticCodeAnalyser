## Description

WriteLn / ShowMessage / OutputDebugString / OutputDebugStringA dans du code hors test est presque toujours un reste de débogage : ShowMessage en particulier bloque le thread d'interface et ne convient à aucun chemin de code de production. Remplacer par un logger structuré (TLogger, mORMot TSynLog, log4d) afin que le point d'appel capture la sévérité, la catégorie et l'emplacement dans le source, et que l'exploitation puisse régler la verbosité à l'exécution. Le détecteur ignore les unités situées dans des segments de répertoire test/sample/demo (la définition des chemins de fixtures valable pour tout le projet : `test`, `tests`, `unittest`, `unittests`, `samples`, `demos`, ancrés sous la racine de l'analyse) ainsi que les unités console/test-runner (`*Console*`, `*TestProject*` dans le nom de fichier de l'unité) - la sortie y est voulue, ce n'est pas un reste de débogage. Implémenté le 2026-09-05, après que l'audit du 2026-09-04 a constaté que l'exclusion promise à l'origine n'avait jamais été construite. Un marqueur `// noinspection DebugOutput` masque des lignes individuelles (p. ex. des bannières CLI interactives).

## Exemples

### Mauvais (déclenche la règle)

```pascal
WriteLn('here #3');
```

### Bon (correction idiomatique)

```pascal
Logger.Debug('reached step 3');
```
