# SCA155 — Instruction with sur plusieurs cibles

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> `with A, B do` (deux receveurs ou plus séparés par des virgules) rend la résolution des membres ambiguë - ajouter une méthode à A ou à B change silencieusement le sens du corps

## Description

Correspondance regex \bwith\s+<id>,\s*<id>\s*do\b sur tout le fichier (multiligne / commentaires retirés), suivie d'une passe d'équilibrage des parenthèses sur la tête du with. Une seule cible est déjà un code smell (couvert par fkWithStatement) ; deux ou plus transforment le corps en piège de maintenance : une nouvelle méthode ajoutée à A ou à B peut silencieusement supplanter ce qui était auparavant résolu vers l'autre. Le compilateur choisit la correspondance la plus proche et n'avertit jamais. Les renommages via la refactorisation de l'IDE omettent ces références, car le receveur n'est pas nommé au site d'appel. Ajusté pour mORMot : accepte jusqu'à 200 caractères par nom de cible pour tolérer des noms entièrement qualifiés comme Owner.SubObject.Component. Correction : séparer en blocs with distincts ou - mieux - abandonner with entièrement et qualifier explicitement chaque membre. Non signalé : une cible unique dont les virgules se trouvent dans une liste d'arguments, d'indices ou d'arguments de type. Seule une virgule à la profondeur de parenthèses 0 sépare des cibles ; la passe d'équilibrage compte les parenthèses et les crochets et ignore les arguments de type génériques (TDict<K,V>), et les littéraux de chaîne sont vidés au préalable. Si la tête ne peut pas être tranchée (aucun do à la profondeur 0 dans la fenêtre, parenthèses déséquilibrées), le résultat est conservé - le filtre ne peut que retirer, jamais ajouter.

## Exemples

### Mauvais (déclenche la règle)

```pascal
with Form1, List1 do
  DoStuff;     // From Form1 or List1?
```

### Bon (correction idiomatique)

```pascal
Form1.DoStuff;
List1.Sort;
```

## Volontairement non signalé

Le détecteur garde volontairement le silence sur les constructions ci-dessous. Chacune est une classe de faux positifs mesurée sur le corpus réel — ce n'est pas une supposition.

### A single target whose commas sit inside an argument, index or type-argument list

Only a comma at bracket depth 0 separates `with` targets. `with Obj.Method(A, B, 'C') do` has exactly one receiver - the commas belong to the call. The balance pass counts round and square brackets and skips generic type arguments (`TDict<K,V>`); string literals are already blanked, so a comma inside a literal can never split a head either. If the head cannot be decided (no `do` at depth 0 within the window, unbalanced brackets), the finding stays - the filter may only remove, never add.

```pascal
// not reported - one target, commas are arguments
with CL.AddInterface(CL.FindInterface('IFoo'), IBar, 'IBar') do
  RegisterMethod('...');

// still reported - two receivers
with Form1, List1 do
  DoStuff;
```
