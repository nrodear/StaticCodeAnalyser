## Description

Un `case` avec de nombreuses branches cache généralement un polymorphisme ou un pattern stratégie. Le code serait plus ouvert/fermé (nouveau comportement = nouvelle classe, pas nouvelle branche) et le fichier plus court si chaque branche devenait sa propre méthode de classe ou une entrée `TDictionary<Key, TProc>`. Correspond à SonarDelphi communitydelphi:CaseStatementSize. Le seuil est configurable via `[Detectors] MaxCaseBranches` et vaut 10 par défaut. Chaque `case` est mesuré séparément : seules les étiquettes à la profondeur de bloc 1 de ce `case` comptent, de sorte que les étiquettes d'un `case` imbriqué ne gonflent plus celui qui l'englobe. Une construction imbriquée peut donc produire plus d'un résultat - un `case` externe et un interne sont signalés séparément dès que chacun dépasse le seuil à lui seul.

## Exemples

### Mauvais (déclenche la règle)

```pascal
case Op of
  opA: ...; opB: ...; opC: ...; opD: ...; opE: ...;
  opF: ...; opG: ...; opH: ...; opI: ...; opJ: ...;
end;
```

### Bon (correction idiomatique)

```pascal
FOperations[Op].Execute;  // dispatch table
```
