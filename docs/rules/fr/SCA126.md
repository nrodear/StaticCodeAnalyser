# SCA126 — Utiliser Assigned() plutôt que `= nil` / `<> nil`

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Convention Pascal : `Assigned(x)` et `not Assigned(x)` sont les tests nil canoniques

## Description

La comparaison directe avec `nil` fonctionne pour les références d'objet mais échoue pour les types pointeur de méthode et les Variants, pour lesquels la bibliothèque standard préfère `Assigned`. S'en tenir à une seule forme dans toute la base de code évite des bugs de cas limites et améliore la lisibilité - le lecteur n'a pas besoin de vérifier quelle forme le type de la variable prend en charge. Le détecteur examine le `Name` et le `TypeRef` de chaque nœud de l'AST (ce dernier contient la forme textuelle des conditions `if`/`while`/`until` et des parties droites d'affectation) à la recherche du motif `<op> nil` où `<op>` vaut `=` ou `<>`. Les littéraux de chaîne (`'nil'`) sont retirés avant la correspondance, et `:= nil` (affectation), `<= nil` / `>= nil` (comparaisons rares et absurdes) sont explicitement exclus. Correspond à `NilComparisonCheck` de Sonar-Delphi.

## Exemples

### Mauvais (déclenche la règle)

```pascal
if Obj = nil then
  Exit;
if Obj <> nil then
  Obj.DoStuff;
```

### Bon (correction idiomatique)

```pascal
if not Assigned(Obj) then
  Exit;
if Assigned(Obj) then
  Obj.DoStuff;
```
