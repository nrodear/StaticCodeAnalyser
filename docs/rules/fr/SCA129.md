# SCA129 — Transtypage de chaîne vers un type 8 bits sans encodage explicite

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> `AnsiString(s)` / `RawByteString(s)` / `ShortString(s)` supprime silencieusement les caractères hors de la page de codes active

## Description

Transtyper une UnicodeString (ou toute expression de type string - la string Delphi est UnicodeString depuis XE) vers l'une des familles de chaînes 8 bits avec perte (AnsiString, RawByteString, ShortString) passe par la conversion implicite DefaultSystemCodePage. Chaque point de code hors de la page de codes active est remplacé silencieusement par ?. Les emoji, les écritures non latines et même certaines lettres accentuées occidentales disparaissent, mais l'affectation compile proprement et s'exécute sans exception - le bug n'apparaît donc que lorsque les données reviennent par un consommateur compatible Unicode (une autre base de données, une API HTTP, un export Excel). Utiliser plutôt une fonction d'encodage délibérée (UTF8Encode, TEncoding.UTF8.GetBytes, WideStringToUTF8 ...). Le détecteur parcourt les nœuds nkCall dont le nom commence (insensible à la casse) par AnsiString(, RawByteString( ou ShortString(, c.-à-d. une instruction ou une affectation qui commence par le transtypage ; un transtypage imbriqué dans un autre appel ou au milieu d'une expression (`SaveToFile(AnsiString(u))`, `'x' + AnsiString(u)`) n'est pas vu. UTF8String(...) n'est délibérément PAS signalé : UTF8String est type AnsiString(CP_UTF8), le transtypage produit donc exactement le même code que l'UTF8Encode recommandé et est sans perte quelle que soit la page de codes du système. Le seul sous-cas restant avec perte, UTF8String(<already 8-bit>), est un faux négatif accepté (zéro occurrence dans le corpus de référence). Les arguments littéraux de chaîne vides (AnsiString('')) ne sont pas signalés. Les transtypages vers string (= UnicodeString dans le Delphi moderne) ne sont pas non plus signalés. Accepte le faux positif où l'entrée serait déjà du même type 8 bits (transtypage redondant, toujours suspect en tant que code smell). Correspond à UnicodeToAnsiCastCheck de Sonar-Delphi. Dialecte FPC/Lazarus : cette règle est ignorée quand l'analyse s'exécute avec --dialect=fpc - sous FPC, le type string par défaut EST 8 bits (UTF-8 par convention Lazarus), le transtypage n'y est donc pas un rétrécissement Unicode avec perte.

## Exemples

### Mauvais (déclenche la règle)

```pascal
var u: UnicodeString;
var a: AnsiString;
u := 'Smiley: ' + #$1F600;
a := AnsiString(u);          // smiley becomes '?'
logStream.WriteString(a);
```

### Bon (correction idiomatique)

```pascal
var u: UnicodeString;
u := 'Smiley: ' + #$1F600;
logStream.WriteString(UTF8Encode(u));   // explicit, full Unicode
```
