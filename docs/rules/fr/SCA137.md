# SCA137 — Cible Int64 recevant le produit de deux opérandes 32 bits

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Bug-red)

> `<var-Int64> := <a> * <b>` évalue la multiplication en 32 bits avant l'élargissement - un dépassement tronque silencieusement

## Description

Delphi évalue une expression binaire dans le type de ses opérandes, pas dans celui de la cible de l'affectation. Quand deux opérandes `Integer` (32 bits) sont multipliés et que le résultat est affecté à un `Int64`, la multiplication s'effectue en 32 bits ; si le produit réel dépasse `MaxInt`, la valeur est tronquée silencieusement avant d'être élargie. La correction consiste à transtyper au moins un opérande en `Int64`. Le détecteur retire chaînes + commentaires, analyse le texte nettoyé à la recherche de déclarations `<ident>: Int64|UInt64|QWord` pour constituer un ensemble de variables 64 bits, puis cherche les affectations `<lhs> := <a> * <b>;` où la partie gauche est une variable 64 bits mais où les deux opérandes de droite sont de simples identificateurs (sans transtypage, sans expression entre parenthèses) qui ne sont pas eux-mêmes 64 bits. Un littéral numérique d'un côté ou de l'autre empêche le résultat (le compilateur peut souvent évaluer la constante sans risque). Limites : pas d'inférence de type pour les opérandes non locaux (paramètres, champs) ; seul `*` est vérifié, pas `+`/`-` ; les expressions complexes comme `(a + b) * c` ne sont pas reconnues. Correspond à la règle Sonar-50 #14.

## Exemples

### Mauvais (déclenche la règle)

```pascal
var
  BytesTotal: Int64;
  SectorCount, SectorSize: Integer;
begin
  BytesTotal := SectorCount * SectorSize;   // <- 32-bit overflow, then widen
```

### Bon (correction idiomatique)

```pascal
BytesTotal := Int64(SectorCount) * SectorSize;
// Cast one operand; the other is auto-promoted; multiplication is 64-bit.
```
