# SCA121 — La fonction n'affecte jamais Result

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Bug-red)

> Le corps de la fonction se termine sans écrire `Result` (ni `<NomFonction> := ...`) - la valeur de retour est indéfinie

## Description

Une fonction qui atteint son `end;` sans aucun `Result := ...` ni `<FunctionName> := ...` à la manière Pascal renvoie les résidus de registre/pile qui occupent par hasard l'emplacement du résultat. Dans les builds Release, l'appelant reçoit donc la valeur du dernier appel de même taille - un Heisenbug classique qui change selon le niveau d'optimisation. Le détecteur est volontairement prudent : il ignore les fonctions qui contiennent un `Exit` quelconque (peut être `Exit(value)`) ou un `raise` (la fonction lève peut-être systématiquement). Remarque : le parseur enregistre bien l'argument de `Exit(value)`, cette exclusion est donc plus grossière que strictement nécessaire - la resserrer ajouterait des résultats et attend donc une analyse mesurée du corpus. Les procédures, les déclarations abstract/forward/external et les déclarations uniquement DispatchID sont aussi ignorées. Une couverture partielle (Result affecté dans une seule branche) est actuellement un faux négatif en attendant l'analyse CFG. Correspond à `RoutineResultAssignedCheck` de Sonar-Delphi.

## Exemples

### Mauvais (déclenche la règle)

```pascal
function GetCount(L: TList): Integer;
begin
  if L = nil then
    LogMessage('nil list');
  // Result never set -> garbage
end;
```

### Bon (correction idiomatique)

```pascal
function GetCount(L: TList): Integer;
begin
  Result := 0;
  if L <> nil then
    Result := L.Count;
end;
```
