# SCA043 — Le composant a Action et OnClick

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Action et OnClick sont tous deux définis - le OnClick explicite l'emporte, le câblage TAction est mort

## Métadonnées

| Champ | Valeur |
|---|---|
| **Identifiant de règle** | `SCA043` |
| **Kind** | `DfmActionMismatch` |
| **Sévérité par défaut** | Warning |
| **Type** | Bug |
| **Unité du détecteur** | `uDfmActionMismatch.pas` |
| **Étiquettes** | `dfm`, `dead-code` |

## Description

Lorsque les deux sont définis, le gestionnaire OnClick EXPLICITE l'emporte à l'exécution : TControl.Click appelle FOnClick dès qu'il est affecté et ne pointe pas vers le OnExecute de l'action - ce n'est que dans le cas contraire que ActionLink.Execute s'exécute (même logique dans TMenuItem.Click). Le double câblage est le signal d'alerte : l'un des deux chemins est mort. NON signalé lorsque le OnClick pointe exactement vers le gestionnaire OnExecute de l'action liée trouvée dans le même DFM/LFM - les deux chemins exécutent alors la même procédure (l'IDE Lazarus enregistre cette combinaison comme artefact de sauvegarde dans chaque LFM).

## Exemples

### Mauvais (déclenche la règle)

```pascal
object btnSave: TButton
  Action = actSave   // its OnExecute never fires
  OnClick = btnSaveClick   // THIS one fires
end
```

### Bon (correction idiomatique)

```pascal
object btnSave: TButton
  Action = actSave   // the action carries the handler
end

// or drop Action and keep OnClick - but not both
```
