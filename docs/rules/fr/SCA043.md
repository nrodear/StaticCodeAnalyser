# SCA043 — Le composant a Action et OnClick

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Action et OnClick sont tous deux définis - le OnClick explicite l'emporte, le câblage TAction est mort

## Description

> Cette section n'existe qu'en anglais. Le nom et la description courte sont traduits ; les textes complets suivent la version anglaise.

When both are set, the EXPLICIT OnClick handler wins at runtime: TControl.Click calls FOnClick whenever it is assigned and does not point at the action's OnExecute - only otherwise does ActionLink.Execute run (same logic in TMenuItem.Click). The double wiring is the smell: one of the two paths is dead. NOT reported when the OnClick points at exactly the OnExecute handler of the bound action found in the same DFM/LFM - both paths then run the same procedure (the Lazarus IDE stores that combination as a saving artifact in every LFM).

## Exemples

### Mauvais (déclenche la règle)

```pascal
object btnSave: TButton
  Action = actSave   // its OnExecute never fires
  OnClick = btnSaveClick   // THIS one fires
end
```

### Bon (correction idiomatique)

```pascal
object btnSave: TButton
  Action = actSave   // the action carries the handler
end

// or drop Action and keep OnClick - but not both
```
