# SCA169 — L'argument d'Assert contient un appel a effet de bord

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Assert(SomeCall) - l'appel disparaît en build Release et son effet de bord est perdu silencieusement

## Description

Le compilateur Delphi supprime entièrement les appels à Assert des builds Release (sauf si DCC_Assertions est activé). Si l'expression vérifiée contient un appel de fonction à effet de bord (allocation, modification d'état, E/S, incrémentation de compteur), l'effet de bord disparaît aussi - le comportement en Release diverge de celui en Debug. Le détecteur signale les appels à Assert dont l'argument contient un motif d'appel de fonction, après exclusion d'une liste blanche de fonctions RTL connues comme pures (Length, Assigned, SizeOf, IntToStr, ...). Sortir l'appel de l'Assert et vérifier plutôt son résultat.

## Exemples

### Mauvais (déclenche la règle)

```pascal
Assert(InitializeSubsystem);   // Release build skips Init entirely
```

### Bon (correction idiomatique)

```pascal
var Ok := InitializeSubsystem;
Assert(Ok, 'subsystem init failed');
```
