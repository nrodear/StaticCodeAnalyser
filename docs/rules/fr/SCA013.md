# SCA013 — Trop de paramètres

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> La méthode a plus de paramètres que le maximum configuré (5 par défaut)

## Description

Un nombre élevé de paramètres est un indicateur précoce de violation du SRP : la routine jongle avec des responsabilités qui devraient être séparées. Les longues listes entraînent aussi une confusion de position (le troisième Integer, c'est lequel déjà ?) et obligent les appelants à renseigner des valeurs par défaut qui ne s'appliquent pas forcément. Refactoring : regrouper les paramètres cohérents dans un record (TOrderInput), faire passer la configuration par un pattern builder (FluentQuery.Where(...).OrderBy(...)) ou découper la méthode par axe (SaveOrder + SaveOrderItems). Seuil via [Detectors] LongParamListMaxParams (5 par défaut). Les paramètres out/var comptent comme les paramètres par valeur ; le Self implicite des méthodes de classe ne compte pas.

## Exemples

### Mauvais (déclenche la règle)

```pascal
procedure SaveOrder(id, customer, address, city, zip, country, total, tax, shipping: ...);
```

### Bon (correction idiomatique)

```pascal
procedure SaveOrder(const Order: TOrder);
```
