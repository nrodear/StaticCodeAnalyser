# SCA208 — Floating-point literal that can crash the Delphi 12 IDE

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Unit contains a floating-point literal - showing it in the editor can crash the Delphi 12 IDE (a fault in the IDE parser, the code is correct)

## Description

The unit contains a floating-point literal such as 4.90, 1e5 or 1.5E-3. The code is correct; the fault lies in the Delphi 12 IDE: when the unit is shown in the editor, the managed IDE parser behind Error Insight can hit an unmasked x87 floating-point exception while it is JIT-compiled, and the IDE terminates with a stack overflow in clr.dll (0xC00000FD). Observed on one machine with Delphi 12.1 Community Edition, before and after Patch 1, the crash needed all of these at once: Delphi 12; a Code Insight provider other than the LSP provider (the classic provider Borland.CodeInsight.Pascal or one from a third-party package); an Error Insight level other than None (ErrorInsightLevel not 0); and the unit shown in the editor. With the LSP provider (the factory setting) the IDE did not call the affected parser and did not crash. The same call stack has been reported for refactoring commands (not measured). With Delphi 13 the crash was not seen in a single observation. Whether it happens may also depend on the machine, so the rule marks files at risk, not certain crashes. Workarounds observed on that machine, without changing any source: switch Code Insight to the LSP provider; set the Error Insight level to None (error marking is lost, code folding stays); or start the IDE with the environment variable COMPlus_JITMinOpts=1 set for the IDE process only, not for the whole user account (error marking stays). These IDE settings are the better way - the source code does not have to be rewritten for this fault. Literals in inactive {$IFDEF} branches count as well (the editor shows them), and so do literals in a file included with {$I} or {$INCLUDE}: they are reported in the including unit at the directive, and the message names the literal, the include file and its line. One finding per file, at the first literal. The rule is off by default: it is not in the default profile, only in strict and style. Only where the IDE settings cannot be changed, the value can be written without a floating-point literal, for example as a quotient of integers (490 / 100) - a workaround for the IDE fault, not a style recommendation.

## Examples

### Bad (triggers the rule)

```pascal
Price := 4.90;  // floating-point literal - showing this unit can crash the Delphi 12 IDE
```

### Good (idiomatic fix)

```pascal
Price := 490 / 100;  // only if the IDE settings cannot be changed: the same value without a floating-point literal
```

## Not reported (by design)

The detector deliberately stays silent on the constructs below. Each is a false-positive class that was measured on the real-world corpus, not a guess.

### Numbers in comments and string literals

Only tokens of the code count. A number in a comment or in a string literal - also the argument of StrToFloat('4.90') - is not a literal; the IDE did not crash on it in the measurements.

```pascal
// 4.90
X := StrToFloat('4.90');  // not reported
```

### Integers, hex literals, ranges and integer division

490, $FF, 1..5 (subrange, array bound, case label) and 49 / 10 contain no floating-point literal; all were measured without a crash.

```pascal
type TSmall = 1..5;
X := 49 / 10;  // not reported
```

### Method call on an integer literal

In 5.ToString and 5.Equals(5) no digit follows the dot and an identifier starts right after it - a method call on an integer, measured without a crash. A dot followed by neither a digit nor an identifier (X := 1.;) was not measured and is reported.

```pascal
S := 5.ToString;  // not reported
```

### The include file itself

Showing an include file with a floating-point literal in the editor did not crash the IDE; the risk lies with the unit that includes it, which is reported at its {$I} directive. A file counts as an include file by its extension .inc only.

```pascal
// scanned file Rates.inc
const Rate = 4.90;  // not reported
```
