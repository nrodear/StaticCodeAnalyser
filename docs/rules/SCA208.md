# SCA208 — Floating-point literal that can crash the Delphi 12 IDE

## Description

The unit contains a floating-point literal such as 4.90, 1e5 or 1.5E-3. The code is correct; the fault lies in the Delphi 12 IDE: as soon as the unit is shown in the editor, the managed IDE parser behind code folding and Error Insight can fail with an unmasked floating-point exception, and the IDE terminates with a stack overflow in clr.dll (0xC00000FD). Whether it happens depends on the machine (the x87 control word of the IDE process), so the rule marks files at risk, not certain crashes. Observed with Delphi 12.1 Community Edition, before and after Patch 1; with Delphi 13 the crash was not seen in a single observation. Literals in inactive {$IFDEF} branches count as well (the editor shows them), and so do literals in a file included with {$I} or {$INCLUDE}: they are reported in the including unit at the directive, and the message names the literal, the include file and its line. One finding per file, at the first literal. The rule is off by default: it is not in the default profile, only in strict and style. Where the crash occurs, a possible workaround is to write the value without a floating-point literal, for example as a quotient of integers (490 / 100) - a workaround for the IDE fault, not a style recommendation.

## Examples

### Bad (triggers the rule)

```pascal
Price := 4.90;  // floating-point literal - showing this unit can crash the Delphi 12 IDE
```

### Good (idiomatic fix)

```pascal
Price := 490 / 100;  // workaround for the IDE fault: the same value without a floating-point literal
```

## Not reported (by design)

The detector deliberately stays silent on the constructs below. Each is a false-positive class that was measured on the real-world corpus, not a guess.

### Numbers in comments and string literals

Only tokens of the code count. A number in a comment or in a string literal - also the argument of StrToFloat('4.90') - is not a literal; the IDE did not crash on it in the measurements.

```pascal
// 4.90
X := StrToFloat('4.90');  // not reported
```

### Integers, hex literals, ranges and integer division

490, $FF, 1..5 (subrange, array bound, case label) and 49 / 10 contain no floating-point literal; all were measured without a crash.

```pascal
type TSmall = 1..5;
X := 49 / 10;  // not reported
```

### Method call on an integer literal

In 5.ToString and 5.Equals(5) no digit follows the dot and an identifier starts right after it - a method call on an integer, measured without a crash. A dot followed by neither a digit nor an identifier (X := 1.;) was not measured and is reported.

```pascal
S := 5.ToString;  // not reported
```

### The include file itself

Showing an include file with a floating-point literal in the editor did not crash the IDE; the risk lies with the unit that includes it, which is reported at its {$I} directive. A file counts as an include file by its extension .inc only.

```pascal
// scanned file Rates.inc
const Rate = 4.90;  // not reported
```
