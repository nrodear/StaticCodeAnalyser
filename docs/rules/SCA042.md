# SCA042 — God event handler

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Single method wired to >= N component events (default N=5)

## Metadata

| Field | Value |
|---|---|
| **Rule ID** | `SCA042` |
| **Kind** | `DfmGodHandler` |
| **Default severity** | Hint |
| **Type** | Code Smell |
| **Detector unit** | `uDfmGodHandler.pas` |
| **Tags** | `dfm`, `design` |

## Description

Spaghetti indicator: one handler dispatching many unrelated events is hard to read, hard to change, and almost always has cohesion problems. Split by responsibility. Reported when one method is bound to 5 or more component events in a DFM and the bindings are mixed - different component classes or different events. A handler shared by components of one class on the same event (twelve colour buttons with one OnClick) is parametrised bundling and is not reported.

## Examples

### Bad (triggers the rule)

```pascal
object Form1: TForm1
  object btnSave: TButton
    OnClick = HandleEverything
  end
  object btnOpen: TButton
    OnClick = HandleEverything
  end
  object btnClose: TButton
    OnClick = HandleEverything
  end
  object edtName: TEdit
    OnChange = HandleEverything
  end
  object edtCity: TEdit
    OnChange = HandleEverything
  end
end
```

### Good (idiomatic fix)

```pascal
object Form1: TForm1
  object btnSave: TButton
    OnClick = btnSaveClick
  end
  object btnOpen: TButton
    OnClick = btnOpenClick
  end
  object btnClose: TButton
    OnClick = btnCloseClick
  end
  object edtName: TEdit
    OnChange = edtNameChange
  end
  object edtCity: TEdit
    OnChange = edtCityChange
  end
end
```
