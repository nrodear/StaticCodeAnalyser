# SCA120 — Exception erzeugt, aber nie ausgelöst

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Bug-red)

> `EFoo.Create('msg');` legt ein Exception-Objekt an, ohne es zu `raise`n - der Fehlerpfad wird stillschweigend übersprungen

## Beschreibung

Das Muster `EConvertError.Create('bad input');` ohne vorangehendes `raise` erzeugt eine Exception-Instanz, löst sie nicht aus, und der aufrufende Code läuft weiter, als wäre nichts geschehen. Das allokierte Objekt leckt (klassisches TObject) oder wird sofort eingesammelt (ARC), und der beabsichtigte Fehlerzweig ist verloren. Fast immer eine Copy-Paste-Regression aus `raise EConvertError.Create(...)`, bei der das Schlüsselwort `raise` gelöscht wurde. Heuristik des Detektors: jeder `nkCall` namens `<Ident>.Create(...)`, bei dem `<Ident>` `Exception` ist oder der Delphi-Konvention mit `E`-Präfix folgt (`E` + Großbuchstabe, z. B. `EConvertError`, `EMyDomainError`). `raise X.Create(...)` wird vom Parser der raise-Anweisung als String übernommen und erzeugt nie einen `nkCall`, daher sind tatsächlich ausgelöste Ausnahmen keine Fehlalarme. Entspricht Sonar-Delphi `MissingRaiseCheck`.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
procedure Validate(x: Integer);
begin
  if x < 0 then
    EArgumentOutOfRangeException.Create('x negative');  // never raised!
end;
```

### Gut (idiomatische Korrektur)

```pascal
procedure Validate(x: Integer);
begin
  if x < 0 then
    raise EArgumentOutOfRangeException.Create('x negative');
end;
```
