# SCA126 — Assigned() statt `= nil` / `<> nil` verwenden

> Pascal-Konvention: `Assigned(x)` und `not Assigned(x)` sind die kanonischen nil-Prüfungen

## Beschreibung

Der direkte Vergleich mit `nil` funktioniert für Objektreferenzen, versagt aber bei Methodenzeiger-Typen und Variants, für die die Standardbibliothek `Assigned` bevorzugt. Eine einheitliche Form in der gesamten Codebasis vermeidet Randfall-Fehler und verbessert die Lesbarkeit - der Leser muss nicht prüfen, welche Form der Typ der Variablen unterstützt. Der Detektor durchsucht `Name` und `TypeRef` jedes AST-Knotens (letzteres enthält die Textform von `if`/`while`/`until`-Bedingungen und rechten Seiten von Zuweisungen) nach dem Muster `<op> nil`, wobei `<op>` `=` oder `<>` ist. String-Literale (`'nil'`) werden vor dem Abgleich entfernt, und `:= nil` (Zuweisung), `<= nil` / `>= nil` (seltene unsinnige Vergleiche) sind ausdrücklich ausgenommen. Entspricht Sonar-Delphi `NilComparisonCheck`.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
if Obj = nil then
  Exit;
if Obj <> nil then
  Obj.DoStuff;
```

### Gut (idiomatische Korrektur)

```pascal
if not Assigned(Obj) then
  Exit;
if Assigned(Obj) then
  Obj.DoStuff;
```
