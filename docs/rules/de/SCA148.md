# SCA148 — Instanzmethode greift nie auf Self zu - könnte Klassenmethode sein

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Eine Methode, die nur ihre Parameter nutzt (kein Self, keine Instanzfelder, keine virtuelle Kette), ist funktional eine Klassenmethode - als solche kennzeichnen

## Beschreibung

Berührt eine Instanzmethode nie `Self`, ein Instanzfeld oder `inherited`, ist der implizite Parameter `Self` verschwendet - die Methode ist faktisch zustandslos. Sie als `class function ... static` zu deklarieren, spart die Übergabe eines Zeigers, macht die zustandslose Absicht explizit und erlaubt Aufrufern, sie ohne Instanz aufzurufen (`TMath.Add(1, 2)` statt `MyMath.Add(1, 2)`). Der Detektor durchläuft `nkMethod`-Knoten, die zu einer Klasse gehören (qualifizierter Name wie `TFoo.Bar`), überspringt bereits vorhandene Klassenmethoden (`;class` in TypeRef), polymorphe (`;virtual`/`;override`/`;dynamic`/`;abstract`), Konstruktoren und Destruktoren und prüft dann rekursiv auf einen Bezeichner namens `self`, ein `inherited` oder eine Feldreferenz `F<UppercaseLetter>`. Nichts davon -> Fund. Einschränkungen: Impliziter Property-Zugriff ohne Präfix `Self.` wird nicht als Instanzzugriff erkannt, daher können Aufrufe wie `Bar := ...` für eine Property einen Fehlalarm erzeugen. Entspricht Sonar-50-Regel #50.

## Beispiele

### Schlecht (löst die Regel aus)

> Diese Regel meldet mit niedriger Konfidenz: mit der Vorgabe `[Rules] MinConfidence=medium` bleibt das folgende Beispiel unsichtbar. Mit `[Rules] MinConfidence=low` erscheint es.

```pascal
function TMath.Add(A, B: Integer): Integer;
begin
  Result := A + B;          // only uses params, no Self
end;
```

### Gut (idiomatische Korrektur)

```pascal
class function TMath.Add(A, B: Integer): Integer;
begin
  Result := A + B;
end;
// Caller: TMath.Add(1, 2)   // no instance needed
```
