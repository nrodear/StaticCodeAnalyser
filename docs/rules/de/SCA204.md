# SCA204 — Ergebnis über den Funktionsnamen zugewiesen

## Beschreibung

> Dieser Abschnitt liegt nur auf Englisch vor. Übersetzt sind Name und Kurzbeschreibung; die Volltexte folgen der englischen Fassung.

Inside a function, 'GetCount := FItems.Count;' sets the result - the form Pascal had before Result existed. It works, but the same name means two different things in one body: on the left of ':=' it is the result variable, anywhere else it is a recursive call of the function (see SCA205). 'Result :=' says what is meant and cannot be mistaken for a call. Reported is an assignment to the bare function name at the start of a statement (also behind a case label) in the function's own body. Only where Result exists: in Delphi (not under {$X-}), and in Free Pascal in the modes delphi, delphiunicode and objfpc or with {$modeswitch result}; a file without {$mode} counts as Delphi in a Delphi scan and as unknown under --dialect=fpc. Style rule (hint): profiles strict and style, not default. reDelphix offers the replacement 'Result :='.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
function TList.GetCount: Integer;
begin
  GetCount := FCount;
end;
```

### Gut (idiomatische Korrektur)

```pascal
function TList.GetCount: Integer;
begin
  Result := FCount;
end;
```

## Absichtlich nicht gemeldet

Bei den folgenden Konstrukten schweigt der Detektor absichtlich. Jedes davon ist eine False-Positive-Klasse, die am Realwelt-Korpus gemessen wurde — keine Vermutung.

### No Result available

In the Free Pascal modes fpc, tp, macpas and iso there is no Result unless {$modeswitch result} is set, and Delphi has none under {$X-} or {$EXTENDEDSYNTAX OFF} - assigning to the function name is the only way there. Under --dialect=fpc a file without {$mode} is skipped, because its mode comes from the project or the command line.

```pascal
{$mode fpc}
function Twice(X: Integer): Integer;
begin
  Twice := 2 * X;  // not reported
end;
```

### The name may mean something else

A parameter, local variable, constant, type or nested routine of the same name hides the result; a nested routine that names it may set the outer result itself; inside 'with Obj do' the object can have a member of that name (the assignment then sets the member); inside an anonymous method the outer result is out of reach. Such routines or spans are skipped.

```pascal
with Obj do
  Total := 5;  // not reported - may be Obj.Total
```

### Elements of the result

'GetRec.X := 5', 'GetArr[0] := 1' and 'GetP^ := 8' write into the result under Free Pascal's Delphi mode; for Delphi itself this is not verified, so these forms are left alone (deliberate false negative).

```pascal
GetRec.X := 5;  // not reported
```
