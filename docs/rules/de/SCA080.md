# SCA080 — Überflüssiges Exit/Continue vor end

## Beschreibung

> Dieser Abschnitt liegt nur auf Englisch vor. Übersetzt sind Name und Kurzbeschreibung; die Volltexte folgen der englischen Fassung.

If Exit is the last statement of a routine, or Continue the last statement of a loop body, control flow already leaves the block - the jump statement is dead. Delete it to clarify intent. Matches SonarDelphi communitydelphi:RedundantJump. Not reported: (1) Exit reached from inside a loop body - that is an early return, and deleting it lets the loop overwrite the result it just found; a loop already finished on the same level (while ... do Inc(Run); Exit;) does not count, so those findings stay. (2) Break in any position - unlike Continue it suppresses the remaining iterations, so following the hint turns search loops into full scans and while True loops into infinite ones. Break is redundant only in repeat ... Break; until True, which does not occur anywhere in the 12.000-file reference corpus.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
procedure Foo;
begin
  DoStuff;
  Exit;
end;
```

### Gut (idiomatische Korrektur)

```pascal
procedure Foo;
begin
  DoStuff;
end;
```

## Absichtlich nicht gemeldet

Bei den folgenden Konstrukten schweigt der Detektor absichtlich. Jedes davon ist eine False-Positive-Klasse, die am Realwelt-Korpus gemessen wurde — keine Vermutung.

### `Exit` inside a loop body

This is an early return, not a no-op. Deleting it lets the loop run its remaining iterations - in the canonical search loop the found result is then overwritten by the next iteration. The detector walks backwards from the jump and suppresses the finding when a `for`/`while`/`repeat` body encloses it. A loop that has already finished on the same level (`while ... do Inc(Run); Exit;`) does not count, so the genuine findings behind a completed loop stay.

```pascal
function IndexOfName(const S: string): Integer;
begin
  for Result := 0 to Count - 1 do
    if Items[Result] = S then
      Exit;          // not reported - deleting it breaks the search
  Result := -1;
end;
```

### `Break` in any position

Unlike `Continue`, `Break` at the end of a loop body is not a no-op: it suppresses all remaining iterations. Following the old hint turned search loops into full scans and, in `while True` / `repeat ... until False`, into infinite loops. `Break` is redundant only in `repeat ... Break; until True`, a construct that does not occur in the 12.000-file reference corpus - so the keyword is no longer scanned at all.

```pascal
for I := 0 to List.Count - 1 do
  if List[I] = Wanted then
  begin
    Result := I;
    Break;         // not reported - the loop must stop here
  end;
```
