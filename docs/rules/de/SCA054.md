## Beschreibung

Ein formaler Parameter ist deklariert, wird aber im Methodenrumpf nie gelesen. Der Parameter belastet die Aufrufstelle (jeder Aufrufer übergibt einen Wert, der keine Wirkung hat) und verschleiert die tatsächlichen Abhängigkeiten der Methode. Refactoring: den Parameter entfernen oder die Aufrufstelle auf einen anderen Overload umstellen, der ihn nicht erwartet. Der Detektor überspringt absichtlich von außen festgelegte Signaturen: `override` (die Signatur der Basisklasse ist fest), Platzhalter-Rümpfe mit `; virtual; abstract`, Interface-Implementierungen (Signatur vom Interface vorgegeben), Event-Handler (`Sender: TObject` und der Rest des Event-Tupels) sowie Methoden, die als DFM-Event-Handler registriert sind. Je Methode mit `// noinspection UnusedParameter` unterdrücken, bei Callbacks mit fester Form (RTTI/Streaming).

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
procedure Process(const Data: TData; Mode: Integer);  // Mode never referenced
```

### Gut (idiomatische Korrektur)

```pascal
procedure Process(const Data: TData);
```
