# SCA009 — Objekt ohne schützendes try/finally erzeugt

> .Create ohne umschließendes try/finally - Leck-Risiko im Ausnahmefall

## Beschreibung

Ähnlich wie MemoryLeak (SCA001), aber strukturell geprüft: eine lokale Variable einer Klasse, die der Leck-Detektor verfolgt (die Liste [Detectors] LeakyClasses, z. B. TStringList), wird mit .Create erzeugt und in derselben Methode mit .Free oder FreeAndNil freigegeben, aber kein try/finally schützt den Code dazwischen - eine Ausnahme dort überspringt das Free, und das Objekt leckt. Ganz ohne Free bleibt der Detektor still (dieser Fall ist SCA001). Ebenfalls nicht gemeldet: ein Objekt, das als Ergebnis zurückgegeben oder an einen Owner übergeben wird, und ein Bereich zwischen Create und Free, der nur Member des Objekts selbst aufruft (z. B. List.Add auf einer TStringList).

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
obj := TStringList.Create;
LoadNames(obj);
obj.Free;
```

### Gut (idiomatische Korrektur)

```pascal
obj := TStringList.Create;
try LoadNames(obj) finally obj.Free end;
```
