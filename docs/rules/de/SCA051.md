# SCA051 — Public-Member könnte protected sein

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

## Beschreibung

Analyse einer einzelnen Datei: jeder sichtbare Aufrufer des public-Members ist selbst eine Methode einer Klasse, die von der deklarierenden Klasse abgeleitet ist. `protected` ist die minimale Sichtbarkeit, die alle aktuellen Aufrufstellen bedient, und signalisiert die Entwurfsabsicht ("das ist ein Erweiterungs-Hook, kein Teil der Konsumenten-API"). Derselbe Einzeldatei-Vorbehalt wie bei CanBeUnitPrivate / CanBeStrictPrivate: Unit-übergreifende Konsumenten sind für den Detektor unsichtbar; der Compiler prüft das Refactoring über E2361, falls ein fremder Aufrufer existiert. Übersprungen: published-/RTTI-exponierte Member, virtual-/override-Wurzeln, die Teil der dokumentierten Hierarchie sind. Innerhalb des deklarierenden Projekts unbesorgt verschärfen; bei ausgelieferten Bibliotheks-APIs externe Aufrufer zuerst manuell prüfen.

## Beispiele

### Schlecht (löst die Regel aus)

> Diese Regel meldet mit niedriger Konfidenz: mit der Vorgabe `[Rules] MinConfidence=medium` bleibt das folgende Beispiel unsichtbar. Mit `[Rules] MinConfidence=low` erscheint es.

```pascal
type
  TBase = class
  public
    procedure Hook;          // only called from TSub
  end;
  TSub = class(TBase)
  public
    procedure Run;
  end;

procedure TBase.Hook;
begin
end;

procedure TSub.Run;
begin
  Hook;
end;
```

### Gut (idiomatische Korrektur)

```pascal
type
  TBase = class
  protected
    procedure Hook;
  end;
  TSub = class(TBase)
  public
    procedure Run;
  end;

procedure TBase.Hook;
begin
end;

procedure TSub.Run;
begin
  Hook;
end;
```
