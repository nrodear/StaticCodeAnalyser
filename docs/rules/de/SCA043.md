# SCA043 — Komponente hat Action und OnClick

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Action und OnClick sind beide gesetzt - der explizite OnClick gewinnt, die TAction-Verdrahtung ist tot

## Beschreibung

Wenn beide gesetzt sind, gewinnt zur Laufzeit der EXPLIZITE OnClick-Handler: TControl.Click ruft FOnClick auf, sobald es zugewiesen ist und nicht auf das OnExecute der Action zeigt - nur andernfalls läuft ActionLink.Execute (dieselbe Logik in TMenuItem.Click). Die doppelte Verdrahtung ist der Smell: einer der beiden Pfade ist tot. NICHT gemeldet, wenn der OnClick genau auf den OnExecute-Handler der gebundenen Action zeigt, die in derselben DFM/LFM gefunden wird - beide Pfade führen dann dieselbe Prozedur aus (die Lazarus-IDE speichert diese Kombination als Speicherartefakt in jeder LFM).

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
object btnSave: TButton
  Action = actSave   // its OnExecute never fires
  OnClick = btnSaveClick   // THIS one fires
end
```

### Gut (idiomatische Korrektur)

```pascal
object btnSave: TButton
  Action = actSave   // the action carries the handler
end

// or drop Action and keep OnClick - but not both
```
