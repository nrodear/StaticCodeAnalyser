# SCA142 — uses-Klausel ist nicht alphabetisch sortiert

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

## Beschreibung

Alphabetische Reihenfolge hält Merge-Konflikte deterministisch und beseitigt eine ganze Klasse von Bikeshedding im Code-Review. Der Detektor durchläuft `nkUses`-Knoten, sammelt die `nkUsesItem`-Kinder und vergleicht die tatsächliche Reihenfolge mit einer Sortierung ohne Beachtung der Groß-/Kleinschreibung. Jede Abweichung erzeugt einen Fund auf der `uses`-Zeile. Klauseln mit nur einem Eintrag werden übersprungen. Der Schweregrad ist Hinweis, weil viele Projekte die Einträge bewusst nach Schicht gruppieren (RTL / VCL / Drittanbieter / eigene) statt alphabetisch - Opt-in-Stil, keine harte Regel. Entspricht Sonar-50-Regel #47.

## Beispiele

### Schlecht (löst die Regel aus)

> Diese Regel meldet mit niedriger Konfidenz: mit der Vorgabe `[Rules] MinConfidence=medium` bleibt das folgende Beispiel unsichtbar. Mit `[Rules] MinConfidence=low` erscheint es.

```pascal
uses
  System.SysUtils,
  System.Classes,
  System.IOUtils,                    // <- order broken
  System.JSON;
```

### Gut (idiomatische Korrektur)

```pascal
uses
  System.Classes,
  System.IOUtils,
  System.JSON,
  System.SysUtils;
```
