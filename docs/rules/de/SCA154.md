# SCA154 — Move/FillChar mit SizeOf eines Zeigertyps

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Move, FillChar, CopyMemory oder ZeroMemory mit SizeOf(PXxx), wobei PXxx ein Zeigertyp ist - kopiert nur 4 oder 8 Byte (die Zeigergröße) statt des gemeinten Puffers

## Beschreibung

Lexikalische Suche nach `Move|FillChar|CopyMemory|ZeroMemory(...SizeOf(<Name>)...)`, wobei <Name> mit `P` gefolgt von einem Großbuchstaben beginnt (Delphi-Konvention mit P-Präfix für Zeigertypen: PByte, PInteger, PCardinal, PChar, PSomeRecord, ...). Unter 64 Bit liefert SizeOf(PXxx) unabhängig vom Zieltyp 8; unter 32 Bit liefert es 4. Gemeint war fast immer SizeOf(Xxx) oder Length(Buf) - die verkürzte Kopie lässt den Rest des Puffers stillschweigend unberührt (FillChar) oder kopiert die Quelle nur teilweise (Move). Häufige mORMot-Falle: SizeOf(PByte) statt einer expliziten Byte-Anzahl beim Kopieren in ein festes Array. Die Whitelist schließt SizeOf(TXxx) / SizeOf(Integer) / SizeOf(Variable) aus - nur P-Präfix plus Großbuchstabe löst aus.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
var Buf: array[0..255] of Byte; P: PByte;
Move(Src^, P^, SizeOf(PByte));        // copies 8 bytes (pointer), not the buffer
FillChar(P^, SizeOf(PInteger), 0);    // zeroes 8 bytes, not the integer
```

### Gut (idiomatische Korrektur)

```pascal
Move(Src^, P^, SizeOf(Byte) * Count);  // explicit element count
FillChar(V, SizeOf(V), 0);             // matches the variable's size
```
