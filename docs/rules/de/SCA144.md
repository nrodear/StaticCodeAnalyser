# SCA144 — Gleichheits-/Ungleichheitsvergleich von Gleitkommazahlen

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> `a = b` oder `a <> b` zwischen Single/Double/Extended ist wegen der IEEE-754-Rundung unzuverlässig - SameValue oder Math.IsZero verwenden

## Beschreibung

IEEE-754-Gleitkommaarithmetik garantiert keine exakte Gleichheit, selbst bei Ergebnissen, die für den Entwickler identisch aussehen (`0.1 + 0.2 = 0.3` ist False). Gleichheitsprüfungen auf Gleitkommazahlen sind eine klassische Quelle stiller Fehler - in Tests sehen sie gut aus, schlagen aber gelegentlich falsch aus. Der Detektor entfernt Strings und Kommentare und arbeitet dann in zwei Phasen: (1) sammelt lokale Variablendeklarationen vom Typ `Single`, `Double`, `Extended`, `Real` oder `Currency`; (2) sucht nach `<ident> = <expr>` oder `<ident> <> <expr>`, wobei mindestens eine Seite eine bekannte Gleitkommavariable referenziert. `:=`-Zuweisungen werden per Lookbehind ausgeschlossen. Einschränkungen: keine Typinferenz für Funktionsergebnisse oder nicht lokale Parameter; komplexe Ausdrücke wie `a + b = c + d` schlagen nur an, wenn mindestens ein Operand eine bekannte Gleitkommavariable ist. Entspricht Sonar-50-Regel #19. Korrektur: `System.Math.SameValue(a, b, Eps)` oder `IsZero(a - b)` verwenden.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
var Ratio: Double;
...
if Ratio = 0.5 then DoStuff;     // <- IEEE-754: almost never true after arithmetic
```

### Gut (idiomatische Korrektur)

```pascal
uses System.Math;
...
if SameValue(Ratio, 0.5, 1e-9) then DoStuff;
```
