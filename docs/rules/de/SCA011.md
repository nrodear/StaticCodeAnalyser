## Beschreibung

Alles nach einer unbedingten Abbruchanweisung (Exit, raise, Halt, Continue, Break) im selben Block wird nie ausgeführt. Meist Codereste aus einem Refactoring. Nicht gemeldet, wenn die Abbruchanweisung selbst in einem Bereich bedingter Kompilierung steht und die folgende Anweisung nicht (`{$IFDEF DEBUG} raise ...; {$ENDIF}` gefolgt von `Exit;`): ohne das Define existiert die Abbruchanweisung nicht, und die nächste Anweisung ist der tatsächlich durchlaufene Pfad. Diese Absicherung ist DEFINE-ABHÄNGIG - für einen Build, der das Define immer setzt, wäre der unterdrückte Fund sachlich richtig. Der Analyser kann das ohne die Projekt-Defines nicht entscheiden und entscheidet zugunsten von "erreichbar".

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
Exit;
WriteLn('never reached');
```

### Gut (idiomatische Korrektur)

```pascal
if Failed then
begin
  WriteLn('failed');
  Exit;
end;
WriteLn('reached');
```
