> Zugriff auf eine Variable, die an dieser Stelle nil sein kann

## Beschreibung

Eine lokale Variable wird explizit auf nil gesetzt und danach dereferenziert (Methodenaufruf oder Property-Zugriff), ohne dass dazwischen eine Neuzuweisung oder eine nil-Prüfung steht. Stürzt zur Laufzeit mit EAccessViolation ab. Der Detektor verfolgt nur explizite `obj := nil`-Zuweisungen; ein Wert, den eine Funktion zurückgibt, die nil liefern kann (z. B. eine Find...-Methode), wird nicht verfolgt. Erkannte Absicherungen: eine Neuzuweisung, `Assigned(obj)` oder `obj <> nil` in einer if-Bedingung, ein frühes `if obj = nil then Exit`, die Übergabe von `obj` als Argument (eine mögliche var/out-Zuweisung) und nil-sichere Aufrufe wie `obj.Free`.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
obj := nil;
// ... obj is not assigned on this path ...
obj.DoStuff;   // <-- AV: obj is still nil
```

### Gut (idiomatische Korrektur)

```pascal
obj := nil;
// ...
if Assigned(obj) then
  obj.DoStuff;
```
