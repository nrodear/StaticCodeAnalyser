## Beschreibung

`goto` und Sprungmarken machen den Kontrollfluss unstrukturiert: Schleifen, Verschachtelung und try/finally werden schwer nachvollziehbar. SonarDelphi erfasst dasselbe als communitydelphi:GotoStatement. Moderner Delphi-Code rechtfertigt goto selten - selbst ein mehrstufiges break ist als herausgezogene Prozedur mit Exit sauberer.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
label MyExit;
begin
  if Failed then goto MyExit;
  ...
  MyExit:
end;
```

### Gut (idiomatische Korrektur)

```pascal
if Failed then Exit;
...
```
