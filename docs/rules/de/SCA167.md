# SCA167 — Random-Aufruf ohne vorheriges Randomize

> Random / RandomRange / RandomFrom ohne Randomize - Seed=0 liefert bei jedem Lauf dieselbe Folge

## Beschreibung

Die Delphi-Funktion Random verwendet einen internen Seed, der beim Programmstart 0 ist. Bis Randomize einmal aufgerufen wird (typischerweise zu Beginn der Programmausführung), liefert Random bei jedem Programmstart dieselbe Wertefolge. Der Detektor durchläuft den AST nach allen Aufrufen und überspringt die gesamte Unit, sobald irgendwo ein Randomize-Aufruf vorkommt. Andernfalls wird jeder Aufruf von Random / RandomRange / RandomFrom gemeldet. Hinweis: Randomize-Aufrufe in anderen Units (z. B. im initialization-Block einer per uses eingebundenen Unit) werden nicht erkannt; gegebenenfalls mit `// noinspection InsecureRandom` unterdrücken. Für kryptografische Zwecke (Token-Erzeugung, Salts, Codes zum Zurücksetzen von Passwörtern) ist Random unabhängig von Randomize ungeeignet - TBytes aus einem CSPRNG verwenden (z. B. CryptGenRandom unter Windows, /dev/urandom unter POSIX).

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
procedure DealCards;
var i: Integer;
begin
  for i := 1 to 5 do
    Players[i].Card := Random(52);
end;
```

### Gut (idiomatische Korrektur)

```pascal
procedure DealCards;
var i: Integer;
begin
  Randomize;   // once, at startup
  for i := 1 to 5 do
    Players[i].Card := Random(52);
end;
```
