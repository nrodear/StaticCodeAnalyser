## Beschreibung

Ein binärer Operator hat auf beiden Seiten textuell denselben Operanden: `x = x`, `a and a`, `(p <> p)`. Der Ausdruck ergibt zur Compile-Zeit eine Konstante (True oder False) und deutet fast immer auf einen Tippfehler hin - gemeint war ein ähnlich benannter Bezeichner (`a = b`, `p1 <> p2`). Der Detektor erfasst: Gleichheit / Ungleichheit / Ordnung (`=`, `<>`, `<`, `>`, `<=`, `>=`) und boolesche Operatoren (`and`, `or`, `xor`). Arithmetische Operatoren (`+`, `-`, `*`) sind absichtlich ausgenommen: `x + x` und `a * a` sind legitime Idiome. Die Normalisierung der Operanden wandelt in Kleinbuchstaben um und entfernt überflüssigen Leerraum, erhält aber den Inhalt von String-Literalen, sodass `'foo' = 'foo'` korrekt gemeldet wird. Der Detektor verlangt Bezeichner-Gleichheit über den Operator hinweg - ein Funktionsaufruf mit Seiteneffekten (`Next = Next`) wird ebenfalls gemeldet, weil zwei Aufrufe den Fehler ohnehin erzeugen.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
if (a = a) then ...
```

### Gut (idiomatische Korrektur)

```pascal
if (a = b) then ...
```
