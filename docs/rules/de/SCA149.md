# SCA149 — Methode verdeckt eine virtuelle Basismethode ohne `override`

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Eine in der Ableitung mit demselben Namen wie eine virtuelle oder dynamische Basismethode neu deklarierte Methode ohne `override` bricht die Polymorphie - der Compiler meldet W1010

## Beschreibung

Ohne `override` behandelt der Compiler die Methode der Ableitung als neue Methode. Der polymorphe Dispatch über die vtable der Elternklasse ruft weiterhin deren Implementierung auf - `Base := Derived; Base.DoWork` führt `TBase.DoWork` aus, nicht `TDerived.DoWork`. Der Compiler warnt (W1010), doch viele Codebasen unterdrücken diesen Hinweis. Der Detektor durchläuft `nkClass`-Knoten, ermittelt deren direkte Elternklasse in derselben Unit, sammelt Elternmethoden mit `;virtual` oder `;dynamic` in `TypeRef` und prüft dann jede Methode der Ableitung, deren unqualifizierter Name einem polymorphen Elternnamen entspricht: fehlendes `;override` UND fehlendes `;reintroduce` -> Fund. Einschränkungen: nur innerhalb der Unit (Elternklassen aus anderen Units wie `TForm`/`TStrings` werden nicht gesehen); nur die direkte Elternklasse (mehrstufige Ketten prüfen nur eine Stufe). Entspricht Sonar-50-Regel #21.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
TBase = class
  procedure DoWork; virtual;
end;

TDerived = class(TBase)
  procedure DoWork;          // <- shadows TBase.DoWork (W1010)
end;
```

### Gut (idiomatische Korrektur)

```pascal
TDerived = class(TBase)
  procedure DoWork; override;
end;
```
