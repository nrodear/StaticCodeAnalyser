# SCA119 — Lokale Konstante nicht in UPPER_SNAKE_CASE

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> `const X = 42;` in einer Methode - für Zahlenkonstanten ist UPPER_SNAKE_CASE vorzuziehen

## Beschreibung

Lokale numerische/Integer-Konstanten in einem Methodenrumpf profitieren von UPPER_SNAKE_CASE (`MAX_RETRIES`, `BUFFER_SIZE`, `DEFAULT_TIMEOUT`) - der Leser sieht sofort, dass der Bezeichner eine Konstante und keine Variable ist, und die Konvention entspricht der von C / Java / Python, sodass Leser aus anderen Sprachen nicht stolpern. Der Detektor überspringt: sehr kurze Namen (<=2 Zeichen, typischerweise Schleifenzähler oder Temporäre), String-/Char-typisierte Konstanten (oft UI-Beschriftungen, bei denen PascalCase in Ordnung ist). Für legitime lokale Konstanten in PascalCase mit `// noinspection LocalConstantName` unterdrücken.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
procedure Foo;
const
  MaxRetries = 3;
begin ... end;
```

### Gut (idiomatische Korrektur)

```pascal
procedure Foo;
const
  MAX_RETRIES = 3;
begin ... end;
```
