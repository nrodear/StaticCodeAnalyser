# SCA155 — with-Anweisung mit mehreren Zielen

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> `with A, B do` (zwei oder mehr durch Komma getrennte Empfänger) macht die Member-Auflösung mehrdeutig - eine neue Methode an A oder B ändert stillschweigend die Bedeutung des Rumpfs

## Beschreibung

Regex-Treffer \bwith\s+<id>,\s*<id>\s*do\b über die gesamte Datei (mehrzeilig / Kommentare entfernt), gefolgt von einem Klammerbilanz-Durchlauf über den with-Kopf. Ein einzelnes Ziel ist bereits ein Code-Smell (abgedeckt durch fkWithStatement); zwei oder mehr machen den Rumpf zur Wartungsfalle: Eine neue Methode an A oder B kann stillschweigend überdecken, was bisher an das jeweils andere ging. Der Compiler wählt den nächstliegenden Treffer und warnt nie. Umbenennungen per IDE-Refactoring übergehen diese Referenzen, weil der Empfänger an der Aufrufstelle nicht genannt ist. Auf mORMot abgestimmt: erfasst bis zu 200 Zeichen je Zielname, um voll qualifizierte Namen wie Owner.SubObject.Component zu tolerieren. Korrektur: in getrennte with-Blöcke aufteilen oder - besser - with ganz weglassen und jedes Member explizit qualifizieren. Nicht gemeldet: ein einzelnes Ziel, dessen Kommas in einer Argument-, Index- oder Typargumentliste stehen. Nur ein Komma auf Klammertiefe 0 trennt Ziele; der Bilanz-Durchlauf zählt runde und eckige Klammern und überspringt generische Typargumente (TDict<K,V>), und String-Literale werden vorher geleert. Lässt sich der Kopf nicht entscheiden (kein do auf Tiefe 0 im Fenster, unausgeglichene Klammern), bleibt der Fund - der Filter darf nur entfernen, nie hinzufügen.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
with Form1, List1 do
  DoStuff;     // From Form1 or List1?
```

### Gut (idiomatische Korrektur)

```pascal
Form1.DoStuff;
List1.Sort;
```

## Absichtlich nicht gemeldet

Bei den folgenden Konstrukten schweigt der Detektor absichtlich. Jedes davon ist eine False-Positive-Klasse, die am Realwelt-Korpus gemessen wurde — keine Vermutung.

### A single target whose commas sit inside an argument, index or type-argument list

Only a comma at bracket depth 0 separates `with` targets. `with Obj.Method(A, B, 'C') do` has exactly one receiver - the commas belong to the call. The balance pass counts round and square brackets and skips generic type arguments (`TDict<K,V>`); string literals are already blanked, so a comma inside a literal can never split a head either. If the head cannot be decided (no `do` at depth 0 within the window, unbalanced brackets), the finding stays - the filter may only remove, never add.

```pascal
// not reported - one target, commas are arguments
with CL.AddInterface(CL.FindInterface('IFoo'), IBar, 'IBar') do
  RegisterMethod('...');

// still reported - two receivers
with Form1, List1 do
  DoStuff;
```
