# SCA158 — PChar(s) +/- Offset ohne Leerprüfung

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> `PChar(s) + n` und Verwandte ohne vorherige Leerprüfung auf `s` - bei einem String kürzer als n zeigt der Zeiger hinter den Terminator

## Beschreibung

Lexikalischer Scan nach `PChar|PAnsiChar|PWideChar(<id>) [+-] <offset>`. Ein Rückwärtsfenster von 200 Zeichen sucht nach Schutzmustern: `<id> <> ''`, `<id> = ''`, `Length(<id>) ...` oder `Assigned(<id>)`. Wird kein Schutz gefunden, wird die Arithmetik gemeldet. Für einen leeren String liefert `PChar(s)` einen Zeiger auf ein statisches #0-Zeichen (nicht nil), daher zeigt `PChar(s) + 5` fünf Zeichen hinter diesen Terminator; dasselbe passiert bei jedem String, der kürzer als der Offset ist. Lesen über einen solchen Zeiger liefert Datenmüll oder löst eine Access Violation aus. mORMot-Interna schützen konsequent mit expliziten Leerprüfungen; Anwendercode, der das PChar-Arithmetik-Idiom kopiert, lässt den Schutz oft weg. Einschränkungen: Das Rückwärtsfenster umfasst 200 Zeichen (weiter entfernte Prüfungen werden übersehen); Arithmetik über `Inc(p, ...)` auf einer zuvor zugewiesenen PChar-Variablen wird NICHT erkannt (dafür wäre eine Flussanalyse nötig).

## Beispiele

### Schlecht (löst die Regel aus)

> Diese Regel meldet mit niedriger Konfidenz: mit der Vorgabe `[Rules] MinConfidence=medium` bleibt das folgende Beispiel unsichtbar. Mit `[Rules] MinConfidence=low` erscheint es.

```pascal
p := PChar(s) + 5;       // s shorter than 5 chars -> p points behind the terminator
```

### Gut (idiomatische Korrektur)

```pascal
if Length(s) >= 5 then
  p := PChar(s) + 5;
```
