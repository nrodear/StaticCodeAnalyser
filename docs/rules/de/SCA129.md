# SCA129 — String-Umwandlung in einen 8-Bit-Typ ohne explizite Kodierung

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

## Beschreibung

Ein UnicodeString (oder jeder String-typisierte Ausdruck - der Delphi-string ist seit XE UnicodeString) per Typecast in eine der verlustbehafteten 8-Bit-String-Familien (AnsiString, RawByteString, ShortString) umzuwandeln, läuft über die implizite DefaultSystemCodePage-Konvertierung. Jeder Codepoint außerhalb der aktiven Codepage wird stillschweigend durch ? ersetzt. Emoji, nichtlateinische Schriften und sogar einige westliche Buchstaben mit Akzent verschwinden, doch die Zuweisung kompiliert sauber und läuft ohne Ausnahme - der Fehler zeigt sich daher erst, wenn die Daten über einen Unicode-fähigen Verwender zurücklaufen (eine andere DB, eine HTTP-API, ein Excel-Export). Stattdessen einen bewussten Kodierungs-Helfer verwenden (UTF8Encode, TEncoding.UTF8.GetBytes, WideStringToUTF8 ...). Der Detektor durchläuft nkCall-Knoten, deren Name (ohne Beachtung der Groß-/Kleinschreibung) mit AnsiString(, RawByteString( oder ShortString( beginnt, d. h. eine Anweisung oder Zuweisung, die mit dem Typecast beginnt; ein Typecast, der in einem anderen Aufruf oder mitten in einem Ausdruck steckt (`SaveToFile(AnsiString(u))`, `'x' + AnsiString(u)`), wird nicht gesehen. UTF8String(...) wird bewusst NICHT gemeldet: UTF8String ist type AnsiString(CP_UTF8), daher erzeugt der Typecast genau denselben Code wie das empfohlene UTF8Encode und ist unabhängig von der System-Codepage verlustfrei. Der einzige verbleibende verlustbehaftete Unterfall, UTF8String(<bereits 8-Bit>), ist ein akzeptierter übersehener Fund (null Vorkommen im Referenzkorpus). Leere String-Literal-Argumente (AnsiString('')) werden nicht gemeldet. Typecasts nach string (= UnicodeString in modernem Delphi) werden ebenfalls nicht gemeldet. Akzeptiert wird der Fehlalarm, dass die Eingabe bereits derselbe 8-Bit-Typ sein könnte (überflüssiger Typecast, als Smell trotzdem verdächtig). Entspricht Sonar-Delphi UnicodeToAnsiCastCheck. FPC/Lazarus-Dialekt: Diese Regel wird übersprungen, wenn der Scan mit --dialect=fpc läuft - unter FPC IST der Standard-String-Typ 8-Bit (nach Lazarus-Konvention UTF-8), daher ist der Typecast dort keine verlustbehaftete Unicode-Verengung.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
var u: UnicodeString;
var a: AnsiString;
u := 'Smiley: ' + #$1F600;
a := AnsiString(u);          // smiley becomes '?'
logStream.WriteString(a);
```

### Gut (idiomatische Korrektur)

```pascal
var u: UnicodeString;
u := 'Smiley: ' + #$1F600;
logStream.WriteString(UTF8Encode(u));   // explicit, full Unicode
```
