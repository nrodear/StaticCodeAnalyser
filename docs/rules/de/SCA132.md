# SCA132 — except on E: Exception fängt jeden Fehler

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> `on E: Exception do ...` fängt die Basisklasse und damit jede Ableitung, auch System-Ausnahmen, die nicht stillgestellt werden dürfen (EOutOfMemory, EAccessViolation, EAbort)

## Beschreibung

`Exception` selbst zu fangen - die Wurzel der Delphi-Ausnahmehierarchie - verschluckt stillschweigend Fehlerkategorien, auf die der aufrufende Code nicht vorbereitet ist: Speichermangel, Access Violations, die Ablaufsteuerungs-Ausnahme im Stil von `EAbort` und alles andere, was nicht von einer domänenspezifischen Basisklasse abgeleitet ist. Vorzuziehen ist eine präzise Klausel `on E: ESpecific do` oder mehrere gestapelte Klauseln für die Fälle, aus denen eine Erholung möglich ist. Wird wirklich ein Fallback gebraucht, der nach dem Protokollieren erneut auslöst, `except Log(''...''); raise; end;` verwenden - das blanke `raise;` erhält den ursprünglichen Typ und Stack. Der Detektor durchläuft `nkOnHandler`-Knoten und meldet die, deren `TypeRef` gleich `Exception` ist (ohne Beachtung der Groß-/Kleinschreibung). Entspricht Sonar-50-Regel #11 (`ExceptionTooGeneral`).

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
try
  ParseConfig(s);
except
  on E: Exception do        // swallows EOutOfMemory / EAbort / ...
    Log(E.Message);
end;
```

### Gut (idiomatische Korrektur)

```pascal
try
  ParseConfig(s);
except
  on E: EConvertError do
    Log(E.Message);
  on E: EFileNotFoundException do
    Log(E.Message);
end;
```
