# SCA178 — Datei-Open-API bekommt verkettete Benutzereingabe

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Vulnerability-darkred)

> Datei-Open-Aufruf (TFileStream.Create, AssignFile, ...) mit einem Pfadausdruck, der Benutzereingaben (Edit.Text, Request.Params, ...) verkettet - Path-Traversal-Risiko

## Beschreibung

Klassische Path-Traversal-Schwachstelle: Vom Benutzer kontrollierte Eingabe fließt in eine Dateisystem-API. Ein Angreifer kann `../../../etc/passwd` oder Ähnliches übergeben, um das vorgesehene Verzeichnis zu verlassen und beliebige Dateien zu lesen/zu schreiben. Der Detektor meldet Ausdrücke, die sowohl ein Token einer Datei-Open-API (TFileStream.Create, TFile.OpenRead/WriteText, AssignFile, FileOpen, FileCreate) ALS AUCH ein Token einer Benutzereingabe-Quelle (.Text, .Lines.Text, .Caption, .Value, Request.Params, Sender.Text, ParamStr) UND einen `+`-Operator (String-Verkettung) enthalten. Der Detektor ist heuristisch - kein Taint-Tracking -, daher lösen umhüllende Bereinigungsfunktionen (z. B. `Sanitize(edPath.Text)`) Fehlalarme aus; per Marker unterdrücken, wenn die Bereinigungsfunktion vertrauenswürdig ist.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
Stream := TFileStream.Create(BaseDir + edPath.Text, fmOpenRead);
```

### Gut (idiomatische Korrektur)

```pascal
var SafePath := TPath.Combine(BaseDir, TPath.GetFileName(edPath.Text));
Stream := TFileStream.Create(SafePath, fmOpenRead);
```
