# SCA145 — raise im Destruktor ohne try/except

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Ein ungeschütztes `raise` im Destruktor bricht die Aufräumkette ab - inherited Destroy und nachfolgende FreeAndNil-Aufrufe entfallen, der Zustand bleibt inkonsistent

## Beschreibung

Aufgabe eines Destruktors ist es, die Ressourcen einer Objektinstanz freizugeben und dann `inherited Destroy` aufzurufen, damit die Elternklasse ihren Teil freigibt. Löst der Destruktor eine Ausnahme aus, die kein umgebender Handler fängt, wird die gesamte Aufräumkette abgewickelt: inherited Destroy wird nie aufgerufen, die Ressourcen der Elternklasse lecken, der Destruktor-Frame bleibt halb erledigt zurück, und der Aufrufer (typischerweise die RTL beim Stack-Unwinding) sieht eine Ausnahme in einem Kontext, in dem er sie meist verschluckt oder falsch eskaliert. Der Detektor durchläuft `nkMethod`-Knoten, deren `TypeRef` mit `destructor` beginnt (und die keine Klassendestruktoren sind, die eine andere Semantik haben), und besucht dann rekursiv den Rumpf mit einem Flag `InHandler`. Jedes `nkRaise`, das angetroffen wird, während das Flag False ist, wird gemeldet. Entspricht Sonar-50-Regel #23.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
destructor TFoo.Destroy;
begin
  FList.Free;
  if Bad then raise EInvalidOp.Create('oops');   // <- inherited never runs
  inherited;
end;
```

### Gut (idiomatische Korrektur)

```pascal
destructor TFoo.Destroy;
begin
  try
    FList.Free;
    if Bad then raise EInvalidOp.Create('oops');
  except
    Log('cleanup error');
  end;
  inherited;
end;
```
