# SCA140 — Methode hat zu viele Exit-Anweisungen

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Eine Methode mit mehr als 6 Exit-Aufrufen hat zu viele Rücksprungpfade - schwer zu lesen, schwer zu testen, leicht einen zu übersehen

## Beschreibung

Mehrere frühe Rücksprünge sind für Guard-Clauses nützlich, ab einer kleinen Anzahl zersplittern sie den Kontrollfluss aber so stark, dass künftige Maintainer Bedingungen übersehen. Der Detektor zählt die `nkExit`-Nachfahren jedes `nkMethod` und meldet eine Methode mit mehr als 6 davon: 6 Exit-Anweisungen bleiben still, 7 werden gemeldet. Die Schwelle ist im Detektor fest (`MAX_EXITS`). Exit-Anweisungen in verschachtelten Routinen und anonymen Methoden zählen nicht. Refactoring-Optionen: Guards zu einem einzigen `if (... or ... or ...) then Exit;` zusammenfassen, von frühen Rücksprüngen auf eine einzige Rückgabevariable umstellen oder die innere Logik in einen Helfer extrahieren. Entspricht Sonar-50-Regel #34.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
function Find(Id: Integer): TUser;
begin
  if Id < 0 then begin Result := nil; Exit; end;
  if not Db.Connected then begin Result := nil; Exit; end;
  if Db.IsLocked(Id) then begin Result := nil; Exit; end;
  if Db.IsDeleted(Id) then begin Result := nil; Exit; end;
  if Db.IsArchived(Id) then begin Result := nil; Exit; end;
  if not Cache.Has(Id) then begin Result := DbLoad(Id); Exit; end;
  Result := Cache.Get(Id);
  Exit;                              // 7th Exit
end;
```

### Gut (idiomatische Korrektur)

```pascal
function Find(Id: Integer): TUser;
begin
  Result := nil;
  if (Id < 0) or not Db.Connected then Exit;
  if Db.IsLocked(Id) or Db.IsDeleted(Id) or Db.IsArchived(Id) then Exit;
  if Cache.Has(Id) then
    Result := Cache.Get(Id)
  else
    Result := DbLoad(Id);
end;
```
