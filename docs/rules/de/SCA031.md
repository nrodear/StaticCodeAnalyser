# SCA031 — DFM-Komponente ohne published-Feld

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Komponente im DFM hat kein passendes published-Feld in der Formularklasse - veralteter DFM-Eintrag (Schema-Drift)

## Beschreibung

Eine benannte DFM-Komponente ohne zugehöriges published-Feld ist eine Schema-Abweichung, kein Laufzeitfehler: der Streamer löst das Feld über FieldAddress auf, erhält nil und überspringt die Zuweisung still (kein EReadError). Die Komponente wird trotzdem erzeugt, ist aber aus dem Code nicht erreichbar - ein veralteter/toter DFM-Eintrag, der aufgeräumt werden sollte.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
// .dfm contains object btnSave: TButton, but TForm1 has no btnSave: TButton field
```

### Gut (idiomatische Korrektur)

```pascal
TForm1 = class(TForm)
  edtName: TEdit;
  btnSave: TButton;   // the .dfm creates it - the field must exist
end;
```
