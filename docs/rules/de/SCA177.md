# SCA177 — Thread-Variable nach FreeOnTerminate := True verwendet

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Bug-red)

> Nach T.FreeOnTerminate := True riskiert jeder weitere T.-Zugriff eine Access Violation, wenn der Thread bereits beendet ist

## Beschreibung

TThread.FreeOnTerminate := True überträgt den Besitz der Thread-Instanz an diese selbst - der Thread gibt seinen eigenen Speicher in seinem Lebenszyklus Execute-dann-Destroy frei. Der Aufrufer MUSS alle Referenzen darauf sofort aufgeben (typischerweise, indem er die lokale Variable auf nil setzt), weil es keine Synchronisation zwischen der nächsten Anweisung des Aufrufers und der Selbstzerstörung des Threads gibt. Der Detektor durchläuft jede Methode, sammelt jede Zuweisung `<var>.FreeOnTerminate := True`, dann das erste `<var>.Start` oder `<var>.Resume` - ab diesem Moment läuft der Thread und kann sich selbst freigeben - und meldet jeden späteren Zugriff `<var>.<member>` (Aufruf ODER Zuweisung) in derselben Methode, ausgenommen die Lebenszyklus-Aufrufe Start, Resume und Execute. Ohne Start oder Resume in der Methode wird nichts gemeldet. Umfang je Methode: Referenzen über Methodengrenzen hinweg (Thread in einem Feld, Zugriff in einer anderen Methode) werden nicht verfolgt.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
T := TMyThread.Create(True);
T.FreeOnTerminate := True;
T.Start;
T.WaitFor;   // T may already be freed -> AV
```

### Gut (idiomatische Korrektur)

```pascal
T := TMyThread.Create(True);
T.FreeOnTerminate := True;
T.Start;
T := nil;   // drop the reference
```
