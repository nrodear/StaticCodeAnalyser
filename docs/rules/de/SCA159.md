# SCA159 — Typisierter Exception-Handler mit leerem Rumpf

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> `on E: SomeException do ;` schluckt eine bestimmte Exception-Klasse stillschweigend - schlimmer als ein blankes `except end`, weil die Typangabe absichtsvoll aussieht

## Beschreibung

Lexikalischer Scan nach `on [E:] <ExceptionType> do (;|begin end)`. Die typisierte Form `on E:` erweckt den Eindruck einer durchdachten Behandlung - ein Leser nimmt an, dass sich der Entwickler mit genau dieser Ausnahme befasst hat. Ein leerer Rumpf bedeutet, dass der Fehler in Produktion unsichtbar ist: kein Log, keine Rückmeldung in der Oberfläche, keine Telemetrie. Häufiger Fund in mORMot-Reviews in Aufräumcode, in dem "das kann ignoriert werden" nicht dokumentiert ist. Die blanke Form `except end` erfasst bereits SCA-001 (EmptyExcept); diese Regel deckt die Variante mit typisiertem Handler ab.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
try DoStuff; except
  on E: EDatabaseError do ;
end;
```

### Gut (idiomatische Korrektur)

```pascal
try DoStuff; except
  on E: EDatabaseError do
  begin
    Logger.Error(E.Message);
    raise;
  end;
end;
```
