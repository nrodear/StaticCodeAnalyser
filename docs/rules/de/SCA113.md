## Beschreibung

TThread.Resume ist seit Delphi 2010 zugunsten von TThread.Start veraltet (Suspendieren beim Erzeugen + Fortsetzen beim Starten wurden zu einem expliziten Start-Aufruf). Der Compiler gibt eine Deprecation-Warnung aus, die in größeren Codebasen aber leicht übersehen wird. Zwei Korrekturen: (a) .Start statt .Resume aufrufen, (b) mit CreateSuspended := False erzeugen und den Resume/Start-Schritt ganz weglassen. Der Detektor meldet Aufrufe `<ident>.Resume`. Ist der Typ des Empfängers in derselben Datei sichtbar (`X: TFoo` oder `X := TFoo.Create`), muss er TThread sein, auf `Thread` enden oder in dieser Datei von TThread abgeleitet sein - andere Typen (Timer, Animationen, TProcess) werden übersprungen. Ein nicht aufgelöster Empfänger wird gemeldet, außer bei einer Punktkette oder einer Inline-Variablen, deren Name oder Initialisierer 'thread' nicht erwähnt. Ist ein gemeldeter Empfänger kein TThread, je Zeile mit `// noinspection ThreadResumeDeprecated` unterdrücken.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
MyThread := TWorkerThread.Create(True);
MyThread.Resume;
```

### Gut (idiomatische Korrektur)

```pascal
MyThread := TWorkerThread.Create(True);
MyThread.Start;
```
