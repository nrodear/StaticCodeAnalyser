# SCA208 — Gleitkomma-Literal, an dem die Delphi-12-IDE abstürzen kann

## Beschreibung

Die Unit enthält ein Gleitkomma-Literal wie 4.90, 1e5 oder 1.5E-3. Der Code ist korrekt; der Fehler liegt in der Delphi-12-IDE: Sobald die Unit im Editor angezeigt wird, kann der verwaltete IDE-Parser hinter Code-Faltung und Error Insight an einer unmaskierten Gleitkomma-Ausnahme scheitern, und die IDE endet mit einem Stapelüberlauf in clr.dll (0xC00000FD). Ob es passiert, hängt vom Rechner ab (dem x87-Steuerwort des IDE-Prozesses); die Regel markiert deshalb gefährdete Dateien, keine sicheren Abstürze. Beobachtet mit Delphi 12.1 Community Edition, vor und nach Patch 1; bei Delphi 13 trat der Absturz in einer Einzelbeobachtung nicht auf. Literale in inaktiven {$IFDEF}-Zweigen zählen mit (der Editor zeigt sie), ebenso Literale in einer per {$I} oder {$INCLUDE} eingebundenen Datei: Sie werden in der einbindenden Unit an der Direktive gemeldet, die Meldung nennt das Literal, die Include-Datei und deren Zeile. Ein Fund je Datei, am ersten Literal. Die Regel ist standardmäßig aus: Sie steht nicht im Profil default, nur in strict und style. Wo der Absturz auftritt, ist eine mögliche Umgehung, den Wert ohne Gleitkomma-Literal zu schreiben, etwa als Quotient ganzer Zahlen (490 / 100) - eine Umgehung des IDE-Fehlers, keine Stilempfehlung.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
Price := 4.90;  // floating-point literal - showing this unit can crash the Delphi 12 IDE
```

### Gut (idiomatische Korrektur)

```pascal
Price := 490 / 100;  // workaround for the IDE fault: the same value without a floating-point literal
```

## Absichtlich nicht gemeldet

Bei den folgenden Konstrukten schweigt der Detektor absichtlich. Jedes davon ist eine False-Positive-Klasse, die am Realwelt-Korpus gemessen wurde — keine Vermutung.

### Numbers in comments and string literals

Only tokens of the code count. A number in a comment or in a string literal - also the argument of StrToFloat('4.90') - is not a literal; the IDE did not crash on it in the measurements.

```pascal
// 4.90
X := StrToFloat('4.90');  // not reported
```

### Integers, hex literals, ranges and integer division

490, $FF, 1..5 (subrange, array bound, case label) and 49 / 10 contain no floating-point literal; all were measured without a crash.

```pascal
type TSmall = 1..5;
X := 49 / 10;  // not reported
```

### Method call on an integer literal

In 5.ToString and 5.Equals(5) no digit follows the dot and an identifier starts right after it - a method call on an integer, measured without a crash. A dot followed by neither a digit nor an identifier (X := 1.;) was not measured and is reported.

```pascal
S := 5.ToString;  // not reported
```

### The include file itself

Showing an include file with a floating-point literal in the editor did not crash the IDE; the risk lies with the unit that includes it, which is reported at its {$I} directive. A file counts as an include file by its extension .inc only.

```pascal
// scanned file Rates.inc
const Rate = 4.90;  // not reported
```
