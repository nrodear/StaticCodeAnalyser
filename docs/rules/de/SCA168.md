# SCA168 — case-Anweisung ohne else-Zweig

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

## Beschreibung

Eine case-Anweisung ohne else-Zweig ignoriert stillschweigend alle Werte, die nicht ausdrücklich aufgeführt sind. Nimmt der case-Ausdruck einen dieser unbehandelten Werte an, passiert nichts und es wird kein Fehler ausgelöst, was Logikfehler verdecken kann (besonders, wenn später neue Enum-Werte hinzukommen und die case-Anweisungen nicht angepasst werden). `else ;` für ein beabsichtigtes Nichtstun ergänzen (das die Entscheidung dokumentiert) oder einen Standard-Handler, der eine Ausnahme auslöst / protokolliert / per Assert prüft. Hinweis zum Vergleich mit einer älteren Version: Bis 2026-08 hängte der Parser ein else, das auf ein if im letzten Arm folgte (`3: if C then Foo; else Bar;`), an dieses if statt an das case, sodass die Regel bei case-Anweisungen, die offensichtlich einen else-Zweig hatten, einen fehlenden else-Zweig meldete. Diese Fehlalarme sind verschwunden - 148 davon im Referenzkorpus - und daran, was die Regel als Verstoß zählt, hat sich nichts geändert.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
case Status of
  stNew    : DoNew;
  stActive : DoActive;
end;
```

### Gut (idiomatische Korrektur)

```pascal
case Status of
  stNew    : DoNew;
  stActive : DoActive;
else
  raise EInvalidOpException.Create('Unhandled status');
end;
```
