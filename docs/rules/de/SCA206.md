# SCA206 — Formatter-Marker zum Aus- und Einschalten falsch geschrieben oder ohne Partner

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Formatter-Marker `{(*}` / `{*)}` falsch geschrieben oder ohne Partner - GExperts, CnWizards und JCF formatieren den Bereich dann doch oder den Rest der Datei gar nicht mehr

## Beschreibung

Die Kommentare `{(*}` und `{*)}` schalten den Code-Formatter für den Bereich dazwischen aus und danach wieder ein. Sie stammen aus DelForExp und wirken im Formatter von GExperts, im Formatter von CnWizards und in JEDI Code Format (auch in Lazarus); der Formatter der Delphi-IDE (Strg+D, bis Delphi 12) kennt sie nicht, und Delphi 13 liefert keinen Formatter mehr aus. Die Formatter erkennen nur genau diese vier Zeichen - `{ (*}` oder `{*) }` ist für sie ein gewöhnlicher Kommentar -, und die Bereiche schachteln nicht: ein Schalter, kein Zähler. Gemeldet werden: ein Marker mit Leerzeichen oder Tabs darin (er wird ignoriert, der Bereich wird formatiert); ein öffnendes `{(*}` ohne schließendes (danach wird nichts mehr formatiert); ein schließendes `{*)}` ohne offenen Bereich (es schließt nichts); und ein zweites `{(*}` in einem offenen Bereich (das erste `{*)}` beendet ihn schon). Ein absichtlich bis zum Dateiende offener Bereich wird ebenfalls gemeldet - mit `// noinspection FormatterMarker` in der Zeile über dem `{(*}` unterdrücken. Der Compiler sieht beide Marker als gewöhnliche `{ }`-Kommentare, nichts davon ändert das kompilierte Programm. Die Bilanz zählt je Datei; `{$IFDEF}`-Zweige werden gelesen, wie sie dastehen, ohne sie auszuwerten.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
{ (*}
const Table: array[0..3] of Integer = (
  1, 2,
  3, 4);
{*)}
```

### Gut (idiomatische Korrektur)

```pascal
{(*}
const Table: array[0..3] of Integer = (
  1, 2,
  3, 4);
{*)}
```

## Absichtlich nicht gemeldet

Bei den folgenden Konstrukten schweigt der Detektor absichtlich. Jedes davon ist eine False-Positive-Klasse, die am Realwelt-Korpus gemessen wurde — keine Vermutung.

### Markers inside strings and comments

The formatters read `{(*}` only as a comment token of its own. Inside a string literal, a `//` comment or a `(* *)` comment it is text - JCF keeps exactly such constants and notes in its own sources.

```pascal
const OLD_NOFORMAT_ON = '{(*}';  // not reported
// {(*} starts a region          - not reported
```

### Comments that only look like markers

Only a `{ }` comment whose content is `(*` or `*)` with nothing but blanks or tabs around it counts. A footnote column such as `{ (*) }` and commented-out code such as `{(* Old := 1; *)}` are ordinary comments - the second is the territory of SCA070.

```pascal
CFM_SMALLCAPS = $0040; { (*)    }  // not reported
{(* Old := 1; *)}                 // not reported
```

### Custom GExperts keywords and JCF directives

GExperts lets you change the start and end keywords, and JCF also knows `//jcf:format=off` and `//jcf:format=on`. The rule knows only the default pair `{(*}` / `{*)}` (deliberate false negative).

```pascal
//jcf:format=off  // not checked
```

### A pair split over {$IFDEF} branches

Branches are counted as they stand, the way CnWizards reads them. JCF skips inactive branches, so for JCF such a pair can be incomplete - the rule does not report it.

```pascal
{$IFDEF DEBUG}
{(*}
{$ELSE}
{*)}
{$ENDIF}  // not reported
```
