## Beschreibung

Heuristik: Kommentarinhalt mit 2+ Code-Merkmalen (abschließendes `;`, `:=`, Schlüsselwörter `begin`/`end`/`procedure`/`function`/`if`/`then`/`for`/`while`) ist fast sicher auskommentierter Code. Solcher Code verrottet unbemerkt: niemand traut sich, ihn zu löschen, niemand aktualisiert ihn. Entweder entfernen oder durch ein TODO ersetzen, das die Absicht erklärt. Eine `//`-Zeile wird nur gemeldet, wenn keine der beiden Nachbarzeilen ebenfalls ein `//`-Kommentar ist - ein mehrzeiliger `//`-Block gilt als Dokumentation mit Codebeispielen -, und ein nachgestellter Kommentar hinter Code wird ebenfalls nicht gemeldet. Benachbarte gemeldete Zeilen (z. B. aufeinanderfolgende `{ ... }`-Kommentare) werden als EIN Fund gemeldet, der den Block umspannt (endLine markiert die Spanne); eine einzelne gemeldete Zeile behält die Meldung je Zeile. Entspricht SonarDelphi communitydelphi:CommentedOutCode.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
LoadSettings;
// FCacheSize := 42;
ApplySettings;
```

### Gut (idiomatische Korrektur)

```pascal
LoadSettings;
// TODO: re-enable once issue #123 is fixed - see history
ApplySettings;
```
