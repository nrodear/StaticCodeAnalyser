# SCA131 — IfThen() wertet beide Zweige aus - keine Kurzschlussauswertung

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> `Math.IfThen(cond, A(), B())` und `StrUtils.IfThen` sind normale Funktionen - beide Arme laufen vor dem Aufruf

## Beschreibung

Sowohl `Math.IfThen` (Integer-/Double-Overload) als auch `StrUtils.IfThen` (String-Overload) sind normale Funktionen, keine Sprachkonstrukte. Pascal wertet jedes Argument *vor* dem Aufruf aus, die Funktion sieht also nur die fertigen Ergebniswerte - sie kann den nicht gewählten Zweig nicht 'überspringen'. Enthalten die Arme Funktions- oder Methodenaufrufe mit Seiteneffekten (DB-Lesezugriff, Datei-IO, Zustandsänderung) oder mit nennenswerten Performance-Kosten, laufen beide bedingungslos. Der eigentliche Grund, `IfThen(cond, A, B)` statt `if cond then x := A else x := B` zu schreiben, war meist die Annahme einer Kurzschlussauswertung - die es hier nicht gibt. Der Detektor durchläuft `nkCall`-Knoten, deren Name `IfThen(`, `Math.IfThen(` oder `StrUtils.IfThen(` entspricht (ohne Beachtung der Groß-/Kleinschreibung). Nach dem Herauslösen der äußeren Argumentliste entfernt er String-Literale (damit `'a(b)'` die Heuristik nicht auslöst) und sucht nach verschachtelten `(` - jeder verschachtelte Aufruf ist ein starkes Signal für einen Zweig mit Seiteneffekten. Aufrufe mit nur Literalen oder einfachen Variablen als Armen werden nicht gemeldet - ebenso wenig parameterlose Funktionsaufrufe ohne Klammern (`IfThen(b, FetchA, FetchB)`), weil sich ein Aufruf ohne Klammern nicht von einer Variablen unterscheiden lässt. Entspricht Sonar-Delphi `IfThenShortCircuitCheck`.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
x := Math.IfThen(IsCacheHit, FetchFromCache(Key), FetchFromDb(Key));
//                            both calls run every time
```

### Gut (idiomatische Korrektur)

```pascal
if IsCacheHit then
  x := FetchFromCache(Key)
else
  x := FetchFromDb(Key);
```
