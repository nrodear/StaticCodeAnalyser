# SCA163 — Shell-API mit String-Verkettung im Argument gerufen

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Vulnerability-darkred)

## Beschreibung

Den Befehlsstring per Verkettung aufzubauen (`PChar('cmd /c ' + UserInput)`) erlaubt dem Angreifer, weitere Befehle anzuhängen, wenn die Eingabe nicht streng validiert wird. Dieser Detektor durchläuft den AST und meldet jeden nkCall, dessen Methodenname (ohne Qualifizierer) einer der bekannten Shell-Einstiegspunkte ist UND dessen Argumentliste einen `+`-Operator AUSSERHALB jedes String-Literals enthält. Da sich statisch nicht feststellen lässt, ob ein Operand von außen beeinflusst ist, wird der Fund mit Konfidenz = Low ausgegeben; er erscheint in der Oberfläche nur, wenn die Mindest-Konfidenz auf 'low' steht. Behebung: Argumente über das dafür vorgesehene Parameter-Array übergeben (CreateProcess) oder vor dem Verketten escapen/validieren; ShellExecuteEx mit einer strukturierten SHELLEXECUTEINFO bevorzugen.

## Beispiele

### Schlecht (löst die Regel aus)

> Diese Regel meldet mit niedriger Konfidenz: mit der Vorgabe `[Rules] MinConfidence=medium` bleibt das folgende Beispiel unsichtbar. Mit `[Rules] MinConfidence=low` erscheint es.

```pascal
ShellExecute(0, 'open', PChar('cmd /c ' + UserInput), nil, nil, SW_SHOW);
```

### Gut (idiomatische Korrektur)

```pascal
// Validate UserInput against a strict whitelist, then:
ShellExecute(0, 'open', 'cmd.exe', PChar('/c safe_command'), nil, SW_SHOW);
```
