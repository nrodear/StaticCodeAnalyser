# SCA101 — Zweig ohne begin..end-Block

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> `then`/`else`/`do <Anweisung>` - besser ein ausdrückliches `begin..end`

## Beschreibung

Ein Zweig mit einer einzelnen Anweisung ohne `begin..end` wird leicht falsch gelesen; wird später eine zweite Anweisung ergänzt, ohne neu zu blocken, ist das eine klassische Quelle für Fehler, bei denen Einrückung und Semantik auseinanderlaufen. Stilistisch umstrittene Regel (viele Delphi-Codebasen nutzen die kompakte Form bewusst) - lsHint, in Profilen leicht abzuschalten. `else if`-Ketten, `raise`/`exit`/`break`/`continue` und andere blockeröffnende Anweisungen sind ausdrücklich erlaubt. Entspricht SonarDelphi communitydelphi:BeginEndRequired.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
if Active then DoStuff;
```

### Gut (idiomatische Korrektur)

```pascal
if Active then
begin
  DoStuff;
end;
```
