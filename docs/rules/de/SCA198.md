# SCA198 — Zwei Interfaces teilen sich dieselbe GUID

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Dieselbe GUID steht an mehr als einem Interface - Supports() liefert das zuerst registrierte, ohne Compilerfehler. Mit Strg+Umschalt+G eine neue erzeugen

## Beschreibung

> Dieser Abschnitt liegt nur auf Englisch vor. Übersetzt sind Name und Kurzbeschreibung; die Volltexte folgen der englischen Fassung.

Interface GUIDs identify the interface at run time and must be unique across the program. Declaring a new interface by copying the previous one and forgetting to regenerate the GUID produces code that compiles cleanly and misbehaves silently: Supports(Obj, ISecond, X) succeeds and hands back the FIRST interface, so calls land on the wrong methods or a cast appears to work where it should not. Nothing in the toolchain warns about this. The check needs the whole scan, not one file: the index is built from the same file list that is analysed, so the scope follows the selection - directory, project (.dproj) or project group (.groupproj). The message names the other declarations with file and line, because finding the twin is the actual work. In single-file mode the comparison is limited to that file - 'unique' is not a claim one file can support.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
type
  IReader = interface
    ['{4F2C1A80-91D3-4E7B-B0A6-6C3E1D9F2B54}']
    function Read: string;
  end;

  IWriter = interface
    ['{4F2C1A80-91D3-4E7B-B0A6-6C3E1D9F2B54}']  // copied, not regenerated
    procedure Write(const S: string);
  end;

// succeeds and yields an IReader:
if Supports(Obj, IWriter, W) then W.Write('x');
```

### Gut (idiomatische Korrektur)

```pascal
type
  IReader = interface
    ['{4F2C1A80-91D3-4E7B-B0A6-6C3E1D9F2B54}']
    function Read: string;
  end;

  IWriter = interface
    ['{9B7E30C4-2D18-4A55-8F61-70E5C2A4193D}']  // Ctrl+Shift+G
    procedure Write(const S: string);
  end;
```

## Absichtlich nicht gemeldet

Bei den folgenden Konstrukten schweigt der Detektor absichtlich. Jedes davon ist eine False-Positive-Klasse, die am Realwelt-Korpus gemessen wurde — keine Vermutung.

### Same declaration seen twice

A file that reaches the index more than once must not report itself. Sites are compared by file AND line, so the declaration under inspection is never its own twin.

```pascal
-
```

### The same interface name at both sites

Then it is not a second interface with a stolen GUID but the SAME declaration twice in the tree - a vendored library, a submodule, a backup folder. Reporting it would be actively harmful: 'generate a new GUID' is the wrong move for a duplicated unit, it would make the two copies incompatible. Measured on a 27-project corpus: 1505 of 1705 raw findings were of this shape. The duplicated unit itself is a different question and needs its own rule.

```pascal
JLifecycleOwner in two copies of the same JNI bridge - not reported
```

### A renamed interface that deliberately keeps its GUID

Libraries that rename an interface and keep the GUID stay binary compatible on purpose: existing Supports() calls keep working. JCL did it (IList -> IJclList), JVCL did it (IFillerItem -> IJvDataItem), and ToolsAPI carries IOTAModule50 next to IOTAModule. These ARE reported - the names differ and no heuristic separates them from a real mistake - and they are the main reason this rule is a Warning rather than an Error. Suppress them per unit where the aliasing is intended.

```pascal
IJclList and IList share a GUID by design - reported, suppress locally
```

### Single-file scan

Without a scan-wide index the rule compares only within the current file. A duplicate in another unit stays unreported - a false negative on purpose, because the opposite claim would not be covered by what was read.

```pascal
-
```

### More than four sites

The message lists three other locations and then '+N more'. A message carrying twenty paths is unreadable and breaks the layout of SARIF viewers; three are enough to start the search.
