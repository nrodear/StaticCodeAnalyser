## Beschreibung

Ein leeres `begin..end` ist fast immer ein Refactoring-Rest oder ein nie gefüllter Platzhalter. Entweder löschen oder die fehlende Logik implementieren. Initialisierungsabschnitte `begin end.` auf oberster Unit-Ebene sind ausgenommen (das ist die leere Init-Form, kein Refactoring-Rest). Entspricht SonarDelphi communitydelphi:EmptyBlock.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
if Active then begin end;
```

### Gut (idiomatische Korrektur)

```pascal
if Active then Activate;
```
