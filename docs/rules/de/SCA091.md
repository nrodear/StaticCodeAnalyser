## Beschreibung

Ein `case` mit vielen Zweigen verbirgt meist ein Polymorphie- oder Strategy-Muster. Der Code wäre offener für Erweiterung und geschlossener für Änderung (neues Verhalten = neue Klasse, kein neuer Zweig) und die Datei kürzer, wenn jeder Zweig zu einer eigenen Klassenmethode oder einem `TDictionary<Key, TProc>`-Eintrag wird. Entspricht SonarDelphi communitydelphi:CaseStatementSize. Die Schwelle ist über `[Detectors] MaxCaseBranches` konfigurierbar, Vorgabe 10. Jedes `case` wird für sich gemessen: nur Labels auf Blocktiefe 1 dieses `case` zählen, sodass die Labels eines verschachtelten `case` das umgebende nicht mehr aufblähen. Ein verschachteltes Konstrukt kann daher mehr als einen Fund erzeugen - ein äußeres und ein inneres `case` werden getrennt gemeldet, sobald jedes für sich über der Schwelle liegt.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
case Op of
  opA: ...; opB: ...; opC: ...; opD: ...; opE: ...;
  opF: ...; opG: ...; opH: ...; opI: ...; opJ: ...;
end;
```

### Gut (idiomatische Korrektur)

```pascal
FOperations[Op].Execute;  // dispatch table
```
