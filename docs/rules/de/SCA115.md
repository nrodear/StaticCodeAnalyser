# SCA115 — HTTP-URL im Klartext

## Beschreibung

Ein String-Literal, das mit `http://` beginnt, überträgt für jeden Endpunkt außer localhost seine Nutzdaten unverschlüsselt. Zugangsdaten, Session-Token und personenbezogene Daten laufen im Klartext und können von jedem aktiven Akteur im Netz mitgelesen oder verändert werden. Die Korrektur kostet praktisch nichts: das Schema auf `https://` ändern (fast jeder moderne Dienst unterstützt beides). Der Detektor liest den Host aus dem Literal (ohne Userinfo, Port und IPv6-Klammern) und bleibt still, wenn dieser Host kein erreichbarer Endpunkt sein kann: Loopback und lokale IPC (`localhost`, `127.x.x.x`, `[::1]`, `0.0.0.0`, `host.docker.internal`, das Socket-Layout `http://unix:` von mORMot) sowie die für Dokumentation und Tests reservierten Bereiche (RFC 2606 `example.com/.net/.org`, `.example`, `.test`, `.invalid`; RFC 5737 `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`; RFC 3849 `2001:db8::/32`; und die Link-Local-Bereiche `169.254.0.0/16` und `fe80::/10`, die keine Dokumentationsbereiche sind, in Quelltext-Literalen aber nur als Parser-Fixtures oder Diagnosebeispiele vorkommen - ein echter Einsatz gegen `fe80::` braucht einen Zonenindex, und `169.254.x` tritt nur auf, wenn DHCP fehlgeschlagen ist). Private LAN-Bereiche (RFC 1918) werden bewusst NICHT übersprungen - ein REST-Aufruf an `http://192.168.x.y` ist ein echter Klartext-Endpunkt. XML-Namespace-URIs (`xmlns=`, `schemas`, `w3.org`, ...) sind Identitäten, keine Netzziele, und werden ebenfalls übersprungen.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
Url := 'http://api.contoso-shop.de/v1/users';
```

### Gut (idiomatische Korrektur)

```pascal
Url := 'https://api.contoso-shop.de/v1/users';
```
