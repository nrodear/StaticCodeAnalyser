# SCA161 — Zeigersubtraktion über eine 32-Bit-Umwandlung

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> `Cardinal(P1) - Cardinal(P2)` (auch Integer/LongWord/LongInt) schneidet unter Win64 die oberen 32 Bit ab - die Differenz ist zeitweise falsch

## Beschreibung

Lexikalischer Scan nach `(Cardinal|LongWord|Integer|LongInt)(<id>) - (Cardinal|...)(<id>)` - zwei 32-Bit-Typecasts, durch Minus verbunden. Unter Win64 ist ein Pointer 64 Bit breit, Cardinal/Integer/LongWord/LongInt dagegen 32 Bit, daher verwirft der Typecast die oberen vier Bytes der Adresse. Die resultierende Differenz ist falsch, sobald der Allokator hohe Adressen vergibt - der Code funktioniert unter Win32 und bricht unter Win64 zeitweise. Häufiger Portierungsfehler aus Delphi-7-/Delphi-2007-Beispielen, die älter als Win64 sind. Behebung: `NativeUInt(P1) - NativeUInt(P2)` oder `NativeInt(P1) - NativeInt(P2)` verwenden - Integer-Typen in Zeigerbreite, die der Zeigergröße der Plattform entsprechen (`PtrUInt`/`PtrInt` sind die Namen in FPC und mORMot; die Delphi-RTL deklariert sie nicht).

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
Diff := Cardinal(P1) - Cardinal(P2);   // upper 32 bits lost on Win64
```

### Gut (idiomatische Korrektur)

```pascal
Diff := NativeUInt(P1) - NativeUInt(P2);   // pointer-wide cast
```
