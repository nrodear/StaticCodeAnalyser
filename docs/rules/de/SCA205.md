# SCA205 — Funktionsname im eigenen Rumpf gelesen ist ein rekursiver Aufruf

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Bug-red)

> 'Total := Total + X' in der Funktion Total: rechts ist der Name ein rekursiver Aufruf, nicht das bisherige Ergebnis

## Beschreibung

In Delphi ist der Name einer Funktion in ihrem eigenen Rumpf nur links von ':=' die Ergebnisvariable. Überall sonst - in einem Ausdruck, einer Bedingung, Exit(Name) - ruft er die Funktion erneut auf. 'Total := Total + X;' addiert X daher nicht zum bisher aufgebauten Ergebnis: Es rekursiert, meist bis der Stack überläuft. Die Modi objfpc und fpc von Free Pascal lesen dort stattdessen das Ergebnis, weshalb portierter Code dieses Muster zeigt. Gemeldet wird der bloße Name (ohne Klammern, nicht hinter einem Punkt, nicht nach inherited oder @) in einem Ausdruck einer Funktion, die auch ihrem eigenen Namen zuweist - der Autor verwendet den Namen als Variable. Es ist ein Fehler, wenn die Funktion keine Parameter hat und der Rumpf keine gewollte Rekursion zeigt (kein Name(), keine Aufrufanweisung 'Name;', kein Self.Name, kein Name<T>) und der Name kein bloßes Aufrufargument ist; andernfalls eine Warnung (nur Default-Parameter, gewollte Rekursion daneben, bloßes Argument). Nur im Delphi-Modus: Delphi oder Free Pascal mit {$mode delphi} / {$mode delphiunicode}. Behebung: Result (oder Name(), wenn die Rekursion gewollt ist).

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
function Total: Integer;
var
  I: Integer;
begin
  Total := 0;
  for I := 1 to 3 do
    Total := Total + I;   // recursive call, not the sum
end;
```

### Gut (idiomatische Korrektur)

```pascal
function Total: Integer;
var
  I: Integer;
begin
  Result := 0;
  for I := 1 to 3 do
    Result := Result + I;
end;
```

## Absichtlich nicht gemeldet

Bei den folgenden Konstrukten schweigt der Detektor absichtlich. Jedes davon ist eine False-Positive-Klasse, die am Realwelt-Korpus gemessen wurde — keine Vermutung.

### The function writes Result

Whoever writes Result knows the difference; the bare name is then how Delphi spells a parameterless recursive call - recursive-descent parsers ('Result := -ReadFactor'), retries ('Result := AddKeyStroke'), a function assigned to a procedure variable ('errno := Stub_errno'). Only functions that also assign to their own name are judged.

```pascal
function Factor: Integer;
begin
  if Tok = '-' then begin Next; Result := -Factor; end  // not reported
  else Result := Number;
end;
```

### Mandatory parameters

With a parameter that has no default, the bare name does not compile (not enough actual parameters) or calls another overload: in F(A) the expression 'F + A' calls F(). Neither is a hidden recursion.

```pascal
function F(A: Integer): Integer; overload;
begin
  F := F + A;  // not reported - calls the overload F()
end;
```

### Free Pascal objfpc/fpc modes

There the bare name on the right reads the result - verified with fpc 3.2.2; the pattern is correct code in those modes. A file with any non-Delphi {$mode}, or without {$mode} under --dialect=fpc, is not reported.

```pascal
{$mode objfpc}
Total := Total + I;  // not reported - reads the result
```

### Compiler-error contexts and conditional code

As the argument of Inc, Dec, SetLength and other var-parameter routines the name does not compile in Delphi mode. A compiler directive right before or after the name usually means two {$IFDEF} versions stand side by side. Neither is reported; of {$IFDEF}/{$ELSE} branches only one is read (FPC from the scan dialect, otherwise the first).

```pascal
Inc(Total);  // not reported - does not compile in Delphi mode
```
