# SCA049 — Length(s) - N ohne Absicherung

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Bug-red)

> `Length(s) - K` bzw. `.Count - K` mit K >= 2 ohne Absicherung - negativer Index oder negative Anzahl, wenn die Eingabe kürzer als K ist

## Beschreibung

`Length` und `.Count` liefern einen vorzeichenbehafteten Integer, daher ist `Length(s) - 4` bei einem String mit weniger als vier Zeichen schlicht eine negative Zahl - und diese Zahl geht meist direkt in einen Index, eine Move-Position oder eine Anzahl: `s[Length(s) - 3]` liest vor dem ersten Zeichen (ein Bereichsfehler mit $R+, Datenmüll oder eine Access Violation ohne), `Move(s[Length(s) - 4], Buf, 4)` kopiert von außerhalb des Strings. Der Detektor meldet `Length(...)` und `.Count` gefolgt von `- K`, wobei K ein Integer-Literal von 2 oder mehr ist. `- 1` wird übersprungen: `for I := 0 to Length(s) - 1` läuft bei einem leeren String einfach nullmal. Es ist ein lexikalischer Hinweis - eine vorangehende Absicherung `if Length(s) >= K` wird nicht gesehen. RTL-Hilfsroutinen bevorzugen, die mit kurzer Eingabe zurechtkommen (ExtractFileExt, RightStr, EndsText), oder den Zugriff absichern.

## Beispiele

### Schlecht (löst die Regel aus)

> Diese Regel meldet mit niedriger Konfidenz: mit der Vorgabe `[Rules] MinConfidence=medium` bleibt das folgende Beispiel unsichtbar. Mit `[Rules] MinConfidence=low` erscheint es.

```pascal
if s[Length(s) - 3] = '.' then   // 3-letter extension? Index below 1 when s has fewer than 4 chars
  DoStuff;
```

### Gut (idiomatische Korrektur)

```pascal
if Length(ExtractFileExt(s)) = 4 then   // the RTL handles short strings
  DoStuff;
```
