# SCA182 — [TestFixture]-Klasse ohne [Test]-Methode

## Beschreibung

DUnitX findet Testklassen, indem es nach [TestFixture]-Attributen sucht. Ein Fixture ohne [Test]-Methode erscheint im Testbaum, trägt aber null ausführbare Tests bei - typischerweise ein Rest aus einem Refactoring (Tests gelöscht, Fixture nicht). Der Detektor durchläuft den Dateitext mit einem einfachen Zustandsautomaten: Er betritt das Fixture-Fenster an der [TestFixture]-Zeile, achtet darin auf [Test] und verlässt es beim nächsten `end;` auf oberster Ebene. Wurde kein [Test] gesehen, wird die [TestFixture]-Zeile gemeldet. Fixtures nur mit [SetupFixture] (zum Vorbereiten gemeinsamen Zustands für andere Fixtures) sind ein bekannter Fehlalarm-Fall - mit `// noinspection AttributeTestFixtureWithoutTests` unterdrücken.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
[TestFixture]
TFooTests = class
  procedure Helper;
end;
```

### Gut (idiomatische Korrektur)

```pascal
[TestFixture]
TFooTests = class
  [Test] procedure DoesX;
end;
```
