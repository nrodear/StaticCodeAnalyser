# SCA121 — Funktion weist Result nie zu

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Bug-red)

## Beschreibung

Eine Funktion, die ihr `end;` ohne irgendein `Result := ...` oder Pascal-artiges `<FunctionName> := ...` erreicht, liefert den Register-/Stack-Müll, der zufällig im Ergebnis-Slot steht. In Release-Builds erhält der Aufrufer daher den Wert des letzten Aufrufs gleicher Größe - ein klassischer Heisenbug, der mit der Optimierungsstufe umschlägt. Der Detektor ist absichtlich konservativ: Er überspringt Funktionen, die ein `Exit` (könnte `Exit(value)` sein) oder ein `raise` (die Funktion löst womöglich immer aus) enthalten. Anmerkung: Der Parser erfasst das Argument von `Exit(value)` durchaus, dieses Überspringen ist also gröber als unbedingt nötig - eine Verengung würde Funde hinzufügen und wartet deshalb auf einen gemessenen Korpuslauf. Prozeduren, abstract/forward/external-Deklarationen und reine DispatchID-Deklarationen werden ebenfalls übersprungen. Teilweise Abdeckung (Result nur in einem Zweig gesetzt) ist derzeit ein übersehener Fund, bis eine CFG-Analyse vorliegt. Entspricht Sonar-Delphi `RoutineResultAssignedCheck`.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
function GetCount(L: TList): Integer;
begin
  if L = nil then
    LogMessage('nil list');
  // Result never set -> garbage
end;
```

### Gut (idiomatische Korrektur)

```pascal
function GetCount(L: TList): Integer;
begin
  Result := 0;
  if L <> nil then
    Result := L.Count;
end;
```
