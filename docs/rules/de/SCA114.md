# SCA114 — TThread per FreeAndNil freigegeben - Beendigung prüfen

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Bug-red)

## Beschreibung

Prüfhinweis, kein bewiesener Defekt. `TThread.Destroy` beendet den Thread selbst: Es ruft `Terminate` auf, setzt einen suspendierten Thread fort und wartet, bis `Execute` zurückgekehrt ist; `FreeAndNil(MyThread)` allein ist daher sicher. An der gemeldeten Zeile drei Dinge prüfen. Beachtet `Execute` `Terminated`? Falls nicht, wartet der Destruktor, bis `Execute` von selbst zurückkehrt. Gibt ein Destruktor der Thread-Klasse Felder, die `Execute` verwendet, erst nach `inherited` frei? Sein Rumpf läuft, bevor `TThread.Destroy` den Thread beendet. Ist `FreeOnTerminate` gesetzt? Ein solcher Thread gibt sich am Ende von `Execute` selbst frei und darf daher nicht zusätzlich von außen freigegeben werden. Ein zusätzliches `WaitFor` bringt nichts: Es kehrt bei einem suspendiert erzeugten und nie gestarteten Thread nicht zurück. Heuristik: meldet `FreeAndNil(<id>)`, wenn `<id>` einen Thread-Typ hat (der deklarierte oder erzeugte Typ endet auf `Thread` oder ist in derselben Datei von TThread abgeleitet; löst sich kein Typ auf, enthält der Bezeichner `thread`) und die vorangehenden ~500 Zeichen (etwa 10 Zeilen) weder `<id>.Terminate` noch `<id>.WaitFor` enthalten. Kein Fund nach `TerminateThread(<id>`, unter einer positiven Bedingung `if <id>.Finished` oder wenn ein `Execute` der Thread-Klasse in derselben Unit `Terminated` referenziert. Die blanke Form `.Free` wird nicht geprüft, und der Detektor läuft nur auf Dateien, die `TThread`, `.Synchronize`, `.Resume`, `.Queue`, `ParamByName` oder `FieldByName` erwähnen. Für Nicht-Thread-Klassen mit `// noinspection TThreadDestroyWithoutTerminate` unterdrücken.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
type
  TWorkerThread = class(TThread)
  protected
    procedure Execute; override;
  end;

var
  FWorkerThread: TWorkerThread;

procedure TWorkerThread.Execute;
begin
  RunLongJob;                 // never looks at Terminated
end;

procedure TMainForm.BtnStopClick(Sender: TObject);
begin
  FreeAndNil(FWorkerThread);  // waits until RunLongJob has returned
end;
```

### Gut (idiomatische Korrektur)

```pascal
type
  TWorkerThread = class(TThread)
  private
    FQueue: TList;
  protected
    procedure Execute; override;
  public
    destructor Destroy; override;
  end;

var
  FWorkerThread: TWorkerThread;

procedure TWorkerThread.Execute;
begin
  while not Terminated do
    DoStep;
end;

destructor TWorkerThread.Destroy;
begin
  inherited;                  // ends the thread first
  FreeAndNil(FQueue);         // Execute no longer runs
end;

procedure TMainForm.BtnStopClick(Sender: TObject);
begin
  FreeAndNil(FWorkerThread);  // Destroy ends the thread itself
end;
```
