## Beschreibung

> Dieser Abschnitt liegt nur auf Englisch vor. Übersetzt sind Name und Kurzbeschreibung; die Volltexte folgen der englischen Fassung.

TObject.Create (or LeakyClass.Create) without a protective try/finally block leaks the instance when subsequent code raises an exception. The Free call must run regardless of how the protected block exits. Automatische Freigabe: Klassen, die von TInterfacedObject erben, werden von der Referenzzaehlung freigegeben - der letzte Release ruft Destroy, ein manuelles Free ist dort falsch. Basisklasse: Um dieses Verhalten zu nutzen, muessen Klassen von TInterfacedObject erben. Der Analysator erkennt diese Ahnenlinie ueber den Typindex und senkt die Konfidenz solcher Funde auf fcLow, sodass sie unter den Default-Schwellwert fallen und nur noch im strict-Profil erscheinen. Er unterdrueckt sie NICHT, und zwar aus einem am Korpus gemessenen Grund: die Referenzzaehlung greift erst, wenn das Objekt an eine Interface-Referenz gebunden wird. Wird ein TInterfacedObject-Nachfahre in einer Objekt-Variablen gehalten und nie an ein Interface uebergeben, bleibt der Zaehler bei null und das Leck ist echt - unter 28 solchen Korpusfaellen war genau einer von dieser Art.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
list := TStringList.Create;
DoStuff(list);   // <-- exception here leaks list
```

### Gut (idiomatische Korrektur)

```pascal
list := TStringList.Create;
try
  DoStuff(list);
finally
  list.Free;
end;
```
