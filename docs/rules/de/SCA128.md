# SCA128 — Gebietsschema-abhängiger Formataufruf ohne TFormatSettings

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> `StrToDate(s)`, `FormatFloat(...)` und Verwandte ohne TFormatSettings hängen am System-Gebietsschema - je Rechner und Benutzer verschieden

## Beschreibung

Die gebietsschemaabhängigen Konvertierungsfunktionen von Pascal (`StrToDate`, `StrToTime`, `StrToDateTime`, `DateToStr`, `TimeToStr`, `DateTimeToStr`, `StrToFloat`, `StrToCurr`, `FloatToStr`, `CurrToStr`, `FormatDateTime`, `FormatFloat`, `FormatCurr`) verwenden standardmäßig den globalen Record `SysUtils.FormatSettings`, der aus den Regionaleinstellungen des Betriebssystems initialisiert wird. Derselbe Code verhält sich daher auf einem Entwicklerrechner mit DE-Gebietsschema (`DateSeparator` = '.', `DecimalSeparator` = ',') anders als auf einem Produktionsserver mit EN-Gebietsschema ('/' und '.'). Daten, die über Dateien, APIs, Datenbanken oder CSV ausgetauscht werden, müssen immer über explizite `TFormatSettings` laufen (typischerweise ein lokales `LFormatSettings := TFormatSettings.Invariant` für maschinenlesbare Ausgabe oder ein Schnappschuss des Benutzer-Gebietsschemas für die UI). Der Detektor durchläuft jeden `nkCall`, dessen Funktionsname einer bekannten gebietsschemaabhängigen RTL-Routine entspricht, und meldet den Aufruf, wenn seine Argumentliste keinen Bezeichner erwähnt, der `FormatSettings` oder `FmtSettings` enthält (Teilstring, ohne Beachtung der Groß-/Kleinschreibung) - die Settings-Variable also entsprechend benennen (`LFormatSettings`, `FFmtSettings`). `StrToInt` / `IntToStr` und die Boolean-Varianten sind ausdrücklich **nicht** gebietsschemaabhängig und werden nicht gemeldet. Entspricht Sonar-Delphi `DateFormatSettingsCheck`.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
var d := StrToDate(UserInput);     // breaks under EN locale
WriteLn(DateToStr(Now));
```

### Gut (idiomatische Korrektur)

```pascal
var LFormatSettings := TFormatSettings.Invariant;
var d := StrToDate(UserInput, LFormatSettings);
WriteLn(DateToStr(Now, LFormatSettings));
```
