# SCA150 — Boolescher Vergleich ist immer wahr / immer falsch

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> Vergleiche wie `Length(s) >= 0` sind Tautologien - das Ergebnis von Length ist nie negativ, die Bedingung also nie falsch

## Beschreibung

Tautologische boolesche Vergleiche deuten meist auf einen Tippfehler (`< 0` statt `= 0`, `>= 1` statt `> 0`) oder auf Copy-Paste-Reste aus einer früheren Version des Codes hin. Der Compiler warnt nicht, weil der Operandentyp den Wertebereich syntaktisch zulässt. Dieser enge Detektor entfernt Strings + Kommentare und gleicht dann zwei Muster lexikalisch ab: `Length(...) >= 0` / `Length(...) < 0` und das gespiegelte `0 <= Length(...)` / `0 > Length(...)`. Einschränkungen: Cardinal/UInt-Variablen (`<UInt> >= 0` ist ebenfalls immer wahr) lassen sich ohne Typinferenz nicht erkennen; komplexe Ausdrücke wie `Length(s) - 1 < 0` werden nicht erfasst. Entspricht Sonar-50-Regel #18 (enge Form).

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
if Length(s) >= 0 then DoStuff;   // <- always True
if Length(s) < 0 then DoOther;    // <- always False
```

### Gut (idiomatische Korrektur)

```pascal
if Length(s) > 0 then DoStuff;    // non-empty check
if Length(s) = 0 then DoOther;    // empty check
```
