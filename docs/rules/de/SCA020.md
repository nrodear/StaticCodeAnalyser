## Beschreibung

> Dieser Abschnitt liegt nur auf Englisch vor. Übersetzt sind Name und Kurzbeschreibung; die Volltexte folgen der englischen Fassung.

Empty method may indicate a forgotten implementation, a TODO that was never followed up, or an interface stub. Make intent explicit (assert, exception, or comment). Not reported: an empty body that already carries an explanatory comment ({ do nothing }, // default implementation does nothing) - that *is* one of the three fixes the rule asks for. Not counted as intent: compiler directives ({$REGION}, {$IFDEF}) and commented-out code (recognised by the trailing semicolon). This does not weaken the project rule that comments never count as code *usage* - the question here is documented intent, not use.

### Empty body carrying an explanatory comment

The rule's own advice is to make the intent explicit by assert, exception *or comment*. A body that already carries a comment has followed that advice, so reporting it contradicts the fix the rule asks for. Two things do NOT count as intent: a compiler directive (`{$REGION}`, `{$IFDEF}`) is tooling rather than a statement about intent, and commented-out code - recognised by the trailing semicolon - documents nothing. Note this does not weaken the project rule that comments never count as code *usage*; the question here is documented intent, not use.

```pascal
// not reported - the intent is stated
procedure TFoo.DoNothing;
begin
  { do nothing - base class hook }
end;

// still reported - nothing says why
procedure TFoo.DoNothing;
begin
end;
```
