# SCA184 — Ungenutzte DFM-Komponente

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

## Beschreibung

Eine in der .dfm deklarierte Komponente hat keine Ereignisbindung, wird von keiner Property einer anderen Komponente referenziert (DataSource, Action, ActiveControl, ...), wird im eigenen Pascal-Code des Formulars nie verwendet und wird aus keiner anderen Unit über die globale Formularvariable angesprochen. Höchstwahrscheinlich ist sie ein Rest nach einem Refactoring, der zur Laufzeit trotzdem Speicher belegt. Da der Nutzungsnachweis namensbasiert ist (keine exakte Bindung), wird diese Regel mit niedriger Konfidenz ausgegeben und bleibt aus dem Profil mit Standard-Konfidenz heraus, bis sie an realem Code validiert ist. Persistente Feld-Komponenten (T*Field) sowie eingebettete Frames / geerbte Komponenten werden vorsichtshalber übersprungen; ohne einen Repo-weiten, Unit-übergreifenden Index bleibt der Detektor stumm.

## Beispiele

### Schlecht (löst die Regel aus)

> Diese Regel meldet mit niedriger Konfidenz: mit der Vorgabe `[Rules] MinConfidence=medium` bleibt das folgende Beispiel unsichtbar. Mit `[Rules] MinConfidence=low` erscheint es.

```pascal
object btnOld: TButton  // removed from code, left in the DFM
end
```

### Gut (idiomatische Korrektur)

```pascal
// remove the object block from the .dfm and the field from the
// published section:
TForm1 = class(TForm)
  btnSave: TButton;
end;
```
