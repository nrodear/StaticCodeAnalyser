# SCA151 — Funktion liefert immer dasselbe Literal

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Alle Pfade der Funktion weisen Result dasselbe Literal zu - die Verzweigung ändert nichts am Verhalten, die Funktion durch eine Konstante ersetzen

## Beschreibung

Ist jede Zuweisung an `Result` (oder im klassischen Pascal-Stil an den Funktionsnamen) dasselbe Literal, liefert die Funktion dieses Literal unabhängig von den Eingaben. Die Bedingungsstruktur ist tot - entweder ein unvollständiges Refactoring (ein Zweig wurde nie angepasst), oder Zweige, die unterschiedliche Werte hätten liefern sollen, tun es nicht. Der Detektor durchläuft `nkMethod`, deren `TypeRef` einen Rückgabetyp deklariert, sammelt `nkAssign`-Knoten, deren LHS `result` oder dem unqualifizierten Funktionsnamen entspricht, extrahiert das RHS-Literal (Zahl, String-Literal, True/False/nil) und meldet, wenn mindestens zwei solcher Zuweisungen exakt dasselbe Literal haben und keine Zuweisung ohne Literal existiert. Entspricht Sonar-50-Regel #43.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
function GetTimeout: Integer;
begin
  if SlowMode then
    Result := 30
  else
    Result := 30;       // <- always 30
end;
```

### Gut (idiomatische Korrektur)

```pascal
const DEFAULT_TIMEOUT = 30;

function GetTimeout: Integer;
begin
  Result := DEFAULT_TIMEOUT;
end;
```
