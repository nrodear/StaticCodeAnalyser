# SCA195 — Unit wird vom Projekt genutzt, ist aber nicht darin enthalten

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

## Beschreibung

Läuft nur bei Projekt- und Projektgruppen-Scans (--project / --project-group oder Auswahl einer .dproj/.groupproj über den '...'-Dialog). Abgespalten von SCA194 (das wirklich verwaiste Dateien meldet): Eine Datei, die per uses eingebunden WIRD - direkt oder transitiv über andere solche Units -, ist kein toter Code. Sie kompiliert über den Suchpfad, bleibt aber für die Projektverwaltung unsichtbar: keine Projektnavigation in der IDE, leicht zu übersehen bei Reviews, Deployments und Versionsfixierung, und ein Umbenennen/Verschieben bricht den Build erst beim nächsten vollständigen Kompilieren. Die Behebung besteht darin, die Datei ins Projekt aufzunehmen. Kommentare und String-Literale zählen nie als uses-Referenz; verglichen wird der Dateiname ohne Erweiterung mit den (eventuell punktierten) Unit-Namen in uses-Klauseln.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
MyProject.dproj references uMain - uMain uses uHelper, but uHelper.pas is not in the .dproj -> flagged: add uHelper.pas to the project
```

### Gut (idiomatische Korrektur)

```pascal
Every unit reachable via uses from project units is listed as a DCCReference in the .dproj
```
