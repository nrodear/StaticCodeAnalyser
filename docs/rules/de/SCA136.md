# SCA136 — Konstruktor belegt Felder und löst ohne try/except aus

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Bug-red)

> Der Konstruktor weist Felder per `<Klasse>.Create` zu und löst später ohne try/except aus - die Felder lecken, wenn der Destruktor sie nicht freigibt

## Beschreibung

Löst ein Konstruktor eine Ausnahme aus, ruft Delphi automatisch den Destruktor auf der halb konstruierten Instanz auf. Felder, die der Konstruktor bereits allokiert hat, werden nur freigegeben, wenn dieser Destruktor sie freigibt - ohne Destruktor oder mit einem, der diese Felder nicht freigibt, lecken sie. Der Detektor durchläuft `nkMethod`-Knoten, deren `TypeRef` mit `constructor` beginnt (Klassenkonstruktoren werden über den Marker `;class` übersprungen), und verlangt dann (a) mindestens ein `nkAssign`, dessen LHS `F<Name>` / `Self.F<Name>` ist und dessen RHS einen Aufruf `.Create` enthält, (b) mindestens ein `nkRaise` irgendwo im Rumpf und (c) kein `nkTryExcept` irgendwo im Rumpf. Der Detektor liest auch die Destruktoren der Klasse in derselben Unit: Geben sie jedes allokierte Feld frei (ein Aufruf `Free`, `FreeAndNil`, `Release` oder `DisposeOf`, der das Feld nennt, oder `F<Name> := nil` für ein Interface-Feld), gibt es keinen Fund - es sei denn, ein Destruktor schreibt ohne `if` darauf in ein Member eines solchen Felds (er würde am nil-Feld scheitern, bevor der Rest freigegeben ist), oder ein Thread-Konstruktor löst vor seinem benannten `inherited Create` aus. Freigabe über eine Property, eine Hilfsmethode, eine Owner-Komponente oder einen Destruktor in einer anderen Unit wird nicht erkannt; solche Funde sind Fehlalarme. Einschränkungen: keine Flussanalyse (raise VOR jeder Feldinitialisierung wird trotzdem gemeldet); ein teilweises try/except gilt als vollständig schützend. Entspricht Sonar-50-Regel #12.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
constructor TFoo.Create;
begin
  FList := TStringList.Create;
  FOther := TOther.Create;
  if not Valid then
    raise EInvalidOp.Create('bad');     // <- FList/FOther leak unless Destroy frees them
end;
```

### Gut (idiomatische Korrektur)

```pascal
constructor TFoo.Create;
begin
  FList := TStringList.Create;
  try
    FOther := TOther.Create;
    if not Valid then
      raise EInvalidOp.Create('bad');
  except
    FreeAndNil(FOther);
    FreeAndNil(FList);
    raise;
  end;
end;
```
