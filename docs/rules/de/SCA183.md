# SCA183 — Attribut mit Leerzeile vor dem Ziel-Member

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Attributzeile gefolgt von einer Leerzeile - optisch losgelöst, oft ein Refactoring-Rest

## Beschreibung

Der Delphi-Compiler hängt ein Attribut an das syntaktisch nächste Member, unabhängig von dazwischenliegenden Leerzeilen. Optisch aber ist ein Attribut, das durch eine Leerzeile von seinem Member getrennt ist, leicht zu übersehen - der Leser bemerkt womöglich nicht, dass das Attribut für das Member darunter gilt. Das ist auch ein häufiges Symptom eines Refactorings, bei dem ein Member verschoben/gelöscht, das Attribut aber zurückgelassen wurde. Der Detektor meldet Attributzeilen, deren nächste nicht leere Zeile mehr als eine Zeile entfernt ist.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
[Test]

procedure Foo;
```

### Gut (idiomatische Korrektur)

```pascal
[Test]
procedure Foo;
```
