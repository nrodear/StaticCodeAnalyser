# SCA157 — SetLength(arr, Length(arr) + N) in der Schleife

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Ein dynamisches Array in einer for/while/repeat-Schleife um eins (oder N) zu vergrößern kostet quadratisch - einmal vor der Schleife vergrößern oder blockweise wachsen

## Beschreibung

Lexikalischer Scan nach einem beliebigen `for|while|repeat`-Schlüsselwort, dem innerhalb von 600 Zeichen `SetLength(<id>, Length(<id>) + ...)` folgt, wobei beide `<id>`-Namen identisch sind (das Array vergrößert sich selbst). Jede Neuzuteilung kopiert den vorhandenen Inhalt - n Iterationen kosten n*(n+1)/2 Elementkopien statt n. Bei 10_000 Elementen ist das ~5000x langsamer als ein einmaliges SetLength. Häufige mORMot-Performance-Falle, wenn Anwendercode Ergebnisse sammelt, ohne die endgültige Größe zu kennen. Nur das erste Vergrößern je Schleife wird gemeldet, um Spam zu vermeiden. `SetLength(A, Length(B)+1)` (verschiedene Arrays) wird NICHT gemeldet - dieses Muster ist selten und meist beabsichtigt.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
for i := 0 to Source.Count - 1 do
begin
  SetLength(Dest, Length(Dest) + 1);  // O(n*n)
  Dest[High(Dest)] := Source[i];
end;
```

### Gut (idiomatische Korrektur)

```pascal
SetLength(Dest, Source.Count);
for i := 0 to Source.Count - 1 do
  Dest[i] := Source[i];
```
