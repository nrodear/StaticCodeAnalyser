# SCA107 — Public-Member könnte strict private sein

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Public-Member wird NUR von Methoden der eigenen Klasse referenziert - `strict private` erreicht die stärkste Kapselung

## Beschreibung

Analyse einer einzelnen Datei: Jeder sichtbare Aufrufer des `public`-Members ist selbst eine Methode DERSELBEN Klasse (keine Nachbarklasse, keine Prozedur auf oberster Ebene, keine Ableitung in dieser Unit). `strict private` (D2007+, Klassen-Scope, nicht Unit-Scope) ist die engste korrekte Sichtbarkeit. Derselbe Einzeldatei-Vorbehalt wie bei CanBeUnitPrivate: Verwender in anderen Units sind unsichtbar, und der Compiler sichert die Korrektheit über E2361, falls die Änderung etwas kaputt macht. Übersprungen: published, virtual/abstract/override/dynamic, Klassenkonstruktoren/-destruktoren, RTTI-getriebene Basen (TForm/TFrame/TDataModule/TComponent), Hilfsklassen nur aus Klassenmethoden. Für beabsichtigte öffentliche Schnittstellen je Zeile mit `// noinspection CanBeStrictPrivate` unterdrücken.

## Beispiele

### Schlecht (löst die Regel aus)

> Diese Regel meldet mit niedriger Konfidenz: mit der Vorgabe `[Rules] MinConfidence=medium` bleibt das folgende Beispiel unsichtbar. Mit `[Rules] MinConfidence=low` erscheint es.

```pascal
type
  TFoo = class
  public
    procedure Helper;       // only TFoo.Run calls it
    procedure Run;
  end;
```

### Gut (idiomatische Korrektur)

```pascal
type
  TFoo = class
  strict private
    procedure Helper;
  public
    procedure Run;
  end;
```
