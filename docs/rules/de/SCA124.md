# SCA124 — Konstruktor auf einer Instanz statt der Klasse aufgerufen

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> `obj.Create` - ruft den Konstruktor als Methode auf einer bestehenden Instanz, überspringt die Allokation und initialisiert Felder über lebenden Daten neu

## Beschreibung

Delphi erlaubt es, einen Konstruktor auf einer Instanz aufzurufen, z. B. `obj.Create;`, das Ergebnis ist aber fast nie das Beabsichtigte. Als Klassenmethode aufgerufen (`TFoo.Create`), allokiert die Laufzeit zuerst über `TObject.NewInstance` einen frischen Speicherblock, richtet den VMT-Zeiger ein und führt dann den Konstruktorrumpf aus. Auf einer bestehenden Instanz aufgerufen, entfällt der Allokationspfad vollständig - nur der Konstruktorrumpf läuft und initialisiert Felder neu (`FList := TList.Create;` überschreibt das bisherige `FList`, ohne es freizugeben, Referenzen auf Managed Types werden zertrampelt, Vorgabewerte überschreiben, was der Aufrufer gesetzt hatte). Das Ergebnis ist bestenfalls ein Logikfehler, schlimmstenfalls Speicherkorruption. Heuristik des Detektors (kein Typ-Resolver verfügbar): gleicht `nkCall.Name` mit `<Ident>.Create[(<args>)][;]` ab, wobei `<Ident>` mit einem Kleinbuchstaben beginnt (nach Delphi-Konvention klar eine Variable, da Typen das Präfix `T<Upper>` / `I<Upper>` tragen). Übersprungen werden `Self`, `Result`, `Inherited`, Pfade mit mehreren Punkten (`A.B.Create` - mehrdeutig), Typecast-Formen (`T(x).Create`), Klassennamen und Empfänger nach der Namenskonvention für Metaklassen (Bezeichner-Suffix `Class`, z. B. `itemClass: TFooClass`). Ein kleines bekanntes Fehlalarm-Risiko für anders benannte, `TClass`-typisierte Variablen mit Kleinbuchstaben wird in Kauf genommen (in der Praxis selten). Vorläufige Herabstufung des Schweregrads Fehler -> Warnung (2026-07-25): Ein Audit über den gesamten Korpus maß 100 % Fehlalarme auf der Stufe Fehler; bleibt Warnung, bis strukturelle Guards mit Typauflösung vorliegen. Entspricht Sonar-Delphi `InstanceInvokedConstructorCheck`.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
procedure Reset;
var list: TStringList;
begin
  list := TStringList.Create;
  ...
  list.Create;            // no allocation, re-initialises the existing object
end;
```

### Gut (idiomatische Korrektur)

```pascal
procedure Reset;
var list: TStringList;
begin
  list := TStringList.Create;
  ...
  list.Clear;             // or FreeAndNil + new TStringList.Create
end;
```
