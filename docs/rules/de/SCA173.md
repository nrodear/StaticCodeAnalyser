# SCA173 — Variant in einer leistungskritischen Methode (enthält Schleife)

![Severity](https://img.shields.io/badge/severity-Hint-blue) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Variant-Variable in einer Methode mit Schleife - jede Variant-Operation zahlt den 10- bis 100-fachen COM-Dispatch-Aufwand

## Beschreibung

Variant-Operationen laufen über den COM-VarType-Dispatcher (VarAdd, VarCmp, VarCast, ...), der bei jedem Lesen, Schreiben, Vergleichen und Umwandeln einen Umweg über das Typsystem hinzufügt. In einer heißen Schleife multipliziert sich dieser Aufwand mit der Zahl der Iterationen und kann die Laufzeit der Methode dominieren. Der Detektor meldet jede lokale Variable und jeden Parameter vom Typ Variant / OleVariant in Methoden, die mindestens eine for/while/repeat-Schleife enthalten. Akzeptierte Anwendungsfälle (COM/OLE-Brücken, JSON-Variant-Adapter, Excel-Automatisierung) lassen sich über den Unterdrückungs-Marker `// noinspection VariantTypeMisuse` abdecken.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
procedure SumRows;
var v: Variant; i: Integer;
begin
  for i := 0 to N do v := v + Rows[i];
end;
```

### Gut (idiomatische Korrektur)

```pascal
procedure SumRows;
var s: Double; i: Integer;
begin
  s := 0;
  for i := 0 to N do s := s + Rows[i];
end;
```
