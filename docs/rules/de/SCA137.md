# SCA137 — Int64-Ziel bekommt das Produkt zweier 32-Bit-Operanden

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Bug-red)

> `<Int64-Var> := <a> * <b>` rechnet die Multiplikation in 32 Bit, bevor erweitert wird - ein Überlauf schneidet stillschweigend ab

## Beschreibung

Delphi wertet einen binären Ausdruck im Typ seiner Operanden aus, nicht im Typ des Zuweisungsziels. Werden zwei `Integer`-Operanden (32-Bit) multipliziert und wird das Ergebnis einem `Int64` zugewiesen, läuft die Multiplikation in 32 Bit; übersteigt das tatsächliche Produkt `MaxInt`, wird der Wert stillschweigend abgeschnitten, bevor er erweitert wird. Die Korrektur besteht darin, mindestens einen Operanden per Typecast nach `Int64` umzuwandeln. Der Detektor entfernt Strings + Kommentare, durchsucht den bereinigten Text nach Deklarationen `<ident>: Int64|UInt64|QWord`, um eine Menge von 64-Bit-Variablen aufzubauen, und sucht dann nach Zuweisungen `<lhs> := <a> * <b>;`, bei denen die LHS eine 64-Bit-Variable ist, beide RHS-Operanden aber einfache Bezeichner sind (kein Typecast, kein geklammerter Ausdruck), die selbst nicht 64-Bit sind. Numerische Literale auf einer der beiden Seiten unterdrücken den Fund (der Compiler kann oft sicher konstant falten). Einschränkungen: keine Typinferenz für nicht lokale Operanden (Parameter, Felder); nur `*` wird geprüft, nicht `+`/`-`; komplexe Ausdrücke wie `(a + b) * c` werden nicht erfasst. Entspricht Sonar-50-Regel #14.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
var
  BytesTotal: Int64;
  SectorCount, SectorSize: Integer;
begin
  BytesTotal := SectorCount * SectorSize;   // <- 32-bit overflow, then widen
```

### Gut (idiomatische Korrektur)

```pascal
BytesTotal := Int64(SectorCount) * SectorSize;
// Cast one operand; the other is auto-promoted; multiplication is 64-bit.
```
