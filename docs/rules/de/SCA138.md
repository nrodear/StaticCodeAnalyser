# SCA138 — Klasse hat zu viele Methoden oder Felder

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Code%20Smell-yellow)

> Eine Klasse mit mehr als 20 Methoden oder mehr als 15 Instanzfeldern bündelt zu viele Zuständigkeiten - schwer zu testen, zu ändern und zu prüfen

## Beschreibung

God-Klassen sind Klassen, die zu viel Verhalten und Zustand auf einmal besitzen: typische Beispiele sind UI-Composite-Roots, All-in-one-Manager-Singletons oder Domänenentitäten der ersten Generation, die mit der Anwendung gewachsen sind. Der Detektor durchläuft `nkClass`-Knoten, zählt die direkten `nkMethod`- und `nkField`-Kinder (einschließlich derer in `nkVisibilitySection`) und erzeugt einen Fund, wenn MethodCount > 20 ODER FieldCount > 15. Records, Interfaces, Class Helper, Forward-Deklarationen und als `class abstract` markierte Klassen (Verträge mit Design-Absicht) werden übersprungen. Properties werden nicht gezählt - sie sind syntaktischer Zucker über Getter/Setter-Paaren. Die Schwellen sind fest auf die Sonar-Standardwerte kodiert; God-Klassen überschreiten sie typischerweise um das 3-5-Fache, daher muss die Grenze nicht fein einstellbar sein. Entspricht Sonar-50-Regel #31.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
TUiController = class             // 60 methods, 80 fields
  FToolbar, FFilters, FGrid, ...: ...;
  procedure BuildToolbar;
  procedure FilterChange(...);
  procedure GridDrawCell(...);
  // 50 more methods mixing concerns
end;
```

### Gut (idiomatische Korrektur)

```pascal
TToolbarSlots    = record ... end;
TFilterController = class ... end;
TGridRenderer    = class ... end;

TUiController = class                // ~10 methods, ~5 fields
  FToolbar: TToolbarSlots;
  FFilter:  TFilterController;
  FGrid:    TGridRenderer;
  procedure Setup;
end;
```
