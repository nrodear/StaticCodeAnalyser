# SCA135 — Konkrete Ableitung erbt eine abstrakte Methode ohne override

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Bug-red)

> Die Klasse leitet von einer Basis mit `abstract`-Methode ab, überschreibt sie aber nicht - der Aufruf auf der Instanz löst zur Laufzeit EAbstractError aus

## Beschreibung

Erbt eine Klasse eine `abstract`-Methode von ihrer Elternklasse und überschreibt sie nicht, kompiliert die Instanziierung der Klasse problemlos, aber jeder Aufruf der Methode löst `EAbstractError` aus. Der Detektor durchläuft `nkClass`-Knoten; für jede abgeleitete Klasse sucht er die direkte Elternklasse in derselben Unit, sammelt deren als `abstract` markierte Methoden und meldet jede abstrakte Methode, deren Name nicht unter den Methodennamen der abgeleiteten Klasse vorkommt. Einschränkungen: nur innerhalb der Unit (Basen aus anderen Units wie `TForm`/`TStrings` werden nicht gesehen); nur die direkte Elternklasse (mehrstufige Ketten prüfen nur eine Stufe); Class Helper / Interfaces / Records werden übersprungen. Klassen, die selbst als `class abstract` markiert sind, dürfen Methoden abstrakt lassen. Entspricht Sonar-50-Regel #10.

## Beispiele

### Schlecht (löst die Regel aus)

> Diese Regel meldet mit niedriger Konfidenz: mit der Vorgabe `[Rules] MinConfidence=medium` bleibt das folgende Beispiel unsichtbar. Mit `[Rules] MinConfidence=low` erscheint es.

```pascal
type
  TBase = class
    procedure DoWork; virtual; abstract;
  end;
  TDerived = class(TBase)
    // DoWork not overridden -> EAbstractError on call
  end;
```

### Gut (idiomatische Korrektur)

```pascal
type
  TDerived = class(TBase)
    procedure DoWork; override;
  end;
```
