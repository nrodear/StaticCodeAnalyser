# SCA174 — TList<T> mit T.Create gefüllt - Elemente lecken beim Freigeben

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Bug-red)

> TList<TFoo>.Create plus Add(TFoo.Create) - die Liste besitzt ihre Elemente nicht, jede TFoo-Instanz leckt

## Beschreibung

TList<T> ist ein typisierter Container, der seine Elemente NICHT besitzt - das Freigeben der Liste gibt die enthaltenen Elemente nicht frei. Sind die Elemente mit .Create erzeugte Klasseninstanzen, lecken sie bei jedem Freigeben der Liste, sofern der Aufrufer nicht von Hand iteriert und jedes einzelne freigibt. Der richtige Container ist TObjectList<T> aus Generics.Collections, das standardmäßig OwnsObjects=True hat und seine Elemente beim Zerstören freigibt. Der Detektor durchläuft jede Methode, sammelt alle Zuweisungen `TList<T>.Create` (wobei T ein Bezeichner ist, der nach einer Klasse aussieht) und sucht dann in derselben Methode nach Mustern `<varname>.Add(<T>.Create)`. Besitz über Methodengrenzen hinweg (Add in einer anderen Methode als Create) wird nicht verfolgt.

## Beispiele

### Schlecht (löst die Regel aus)

```pascal
L := TList<TFoo>.Create;
L.Add(TFoo.Create);
L.Free; // TFoo instance leaks
```

### Gut (idiomatische Korrektur)

```pascal
L := TObjectList<TFoo>.Create; // OwnsObjects=True default
L.Add(TFoo.Create);
L.Free; // item freed
```
