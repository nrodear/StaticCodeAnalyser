# SCA200 — IP address as string literal

![Severity](https://img.shields.io/badge/severity-Warning-orange) ![Type](https://img.shields.io/badge/type-Security%20Hotspot-orange)

> Hardcoded IPv4 or IPv6 address (private, shared or public) in a string literal - move it to the configuration or use a host name

## Description

An IP address written into the source couples the program to one network: every move to another server, another environment (development, test, production) or another customer needs a code change and a new build, and the address reveals internal topology to anyone who reads the binary. Read the address from the configuration, the command line or the environment, or use a host name that DNS resolves per environment. The rule reads string literals only - never comments - and recognises IPv4 in strict dotted-decimal form (four octets 0-255, no leading zeros) and IPv6 in every RFC 4291 form, including a zone (%eth0), brackets with a port ([...]:443) and an embedded IPv4 (::ffff:10.1.2.3). Reported are private addresses (RFC 1918, unique local fc00::/7), shared addresses (100.64.0.0/10) and public addresses. Not reported are loopback, unspecified (0.0.0.0, ::), broadcast, netmasks, link-local, the documentation ranges (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24, 2001:db8::/32, 3fff::/20), IETF protocol blocks, benchmarking (198.18.0.0/15), multicast and reserved space. Test units (test/spec naming and directories) are skipped. An address in an http:// URL is also reported by SCA115: the two rules describe different problems, plaintext transport and a fixed address.

## Examples

### Bad (triggers the rule)

```pascal
Client.Host := '10.20.30.40';
```

### Good (idiomatic fix)

```pascal
Client.Host := Settings.ReadString('Server', 'Host', 'localhost');
```

## Not reported (by design)

The detector deliberately stays silent on the constructs below. Each is a false-positive class that was measured on the real-world corpus, not a guess.

### Version numbers, OIDs and product versions

Four-part numbers are often not addresses. A version keyword in the identifiers of the line (Version, Ver, Build, Revision, Release, Assembly) without a host word beside it (BuildServer and ConnectionString are hosts), a version keyword directly before the number in the text ('Version 2.1.0.45'), an OID arc (2.5.x.x, 1.3.6.x, 1.3.14.x, 1.3.101.x) or an OID name, a product prefix ('Chrome/', '\', '-') and a public address of version form (all octets up to 31, the first up to 20) without a host word or port in the line are not reported. An address in a URL, behind a UNC prefix ('\\10.0.0.5\share') or with a port is always a host.

```pascal
Ide.verProc := '1.0.0.0';  // not reported
```

### Range bounds and number columns

An IPv4 ending in .0 or .255 and an IPv6 prefix with a zero interface ID (fd12:3456::/48), each without a port and outside a URL, are network or broadcast bounds (ranges, CIDR blocks), not hosts. A literal holding two more decimal fractions and no URL or port is a number column (SVG paths, measurements).

```pascal
Ranges: array[0..1] of string = ('10.0.0.0', '10.255.255.255');  // not reported
```

### Known limits

Addresses assembled from parts ('10.0.' + '0.1', #46), numeric forms (TIPAddress.Create(10, 0, 0, 1), $0A000001) and the content of Delphi 12 multi-line strings (''') are not read. Form files (.dfm/.lfm/.fmx) are not part of this rule.

```pascal
Host := '10.0.' + '0.1';  // not reported
```
