# SCA205 — Function name read in its own body is a recursive call

![Severity](https://img.shields.io/badge/severity-Error-red) ![Type](https://img.shields.io/badge/type-Bug-red)

> 'Total := Total + X' inside function Total: on the right the name is a recursive call, not the current result

## Description

In Delphi the name of a function inside its own body is the result variable only on the left of ':='. Everywhere else - in an expression, a condition, Exit(Name) - it calls the function again. 'Total := Total + X;' therefore does not add X to the result built so far: it recurses, usually until the stack overflows. Free Pascal's objfpc and fpc modes read the result there instead, which is why ported code shows this pattern. Reported is the bare name (no parentheses, not behind a dot, not after inherited or @) in an expression of a function that also assigns to its own name - the author uses the name as a variable. It is an error when the function has no parameters and the body shows no deliberate recursion (no Name(), no call statement 'Name;', no Self.Name, no Name<T>) and the name is not a bare call argument; otherwise a warning (default parameters only, deliberate recursion next to it, bare argument). Only in Delphi mode: Delphi, or Free Pascal with {$mode delphi} / {$mode delphiunicode}. Fix: Result (or Name() when the recursion is intended).

## Examples

### Bad (triggers the rule)

```pascal
function Total: Integer;
var
  I: Integer;
begin
  Total := 0;
  for I := 1 to 3 do
    Total := Total + I;   // recursive call, not the sum
end;
```

### Good (idiomatic fix)

```pascal
function Total: Integer;
var
  I: Integer;
begin
  Result := 0;
  for I := 1 to 3 do
    Result := Result + I;
end;
```

## Not reported (by design)

The detector deliberately stays silent on the constructs below. Each is a false-positive class that was measured on the real-world corpus, not a guess.

### The function writes Result

Whoever writes Result knows the difference; the bare name is then how Delphi spells a parameterless recursive call - recursive-descent parsers ('Result := -ReadFactor'), retries ('Result := AddKeyStroke'), a function assigned to a procedure variable ('errno := Stub_errno'). Only functions that also assign to their own name are judged.

```pascal
function Factor: Integer;
begin
  if Tok = '-' then begin Next; Result := -Factor; end  // not reported
  else Result := Number;
end;
```

### Mandatory parameters

With a parameter that has no default, the bare name does not compile (not enough actual parameters) or calls another overload: in F(A) the expression 'F + A' calls F(). Neither is a hidden recursion.

```pascal
function F(A: Integer): Integer; overload;
begin
  F := F + A;  // not reported - calls the overload F()
end;
```

### Free Pascal objfpc/fpc modes

There the bare name on the right reads the result - verified with fpc 3.2.2; the pattern is correct code in those modes. A file with any non-Delphi {$mode}, or without {$mode} under --dialect=fpc, is not reported.

```pascal
{$mode objfpc}
Total := Total + I;  // not reported - reads the result
```

### Compiler-error contexts and conditional code

As the argument of Inc, Dec, SetLength and other var-parameter routines the name does not compile in Delphi mode. A compiler directive right before or after the name usually means two {$IFDEF} versions stand side by side. Neither is reported; of {$IFDEF}/{$ELSE} branches only one is read (FPC from the scan dialect, otherwise the first).

```pascal
Inc(Total);  // not reported - does not compile in Delphi mode
```
