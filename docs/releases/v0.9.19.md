# Release 0.9.19 — Fixes at the finding, Lazarus in the scan, and a baseline that counts

🇩🇪 [Deutsche Fassung](v0.9.19_de.md)

So far the analyser told you what was wrong. With **reDelphix**, a new
feature of SCA, it offers the repair right at the finding. Lazarus and Free
Pascal projects become a real scan target, baselines now count findings
instead of hiding them wholesale, and seven new rules join a set that
went through a full review.

Two things to read before you update: the
[Setup and GetIt note](#what-this-means-for-setup-and-getit) and the
[Migration](#migration) section. A CI gate can turn red on code that did
not change, and a pipeline that uses a removed Sonar switch fails.

---

## reDelphix: repair a finding where you read it

reDelphix adds quick-fixes for **96 rules** with 104 menu entries. They
appear behind a separator in the context menu of a finding, in the
editor and in the dock, and in a light bulb at the caret line.

- **Every action proves itself first.** A quick-fix re-checks the finding
  against the current editor buffer. Every action compares each range
  with the text the menu was built on, writes in one undo step, and never
  touches a file on disk. Where the text does not prove a change safe, the entry is greyed
  out and names its reason.
- **Behavior changes are marked.** 37 entries always carry "(changes
  behavior)" and 4 more depending on the finding, for example `raise;`
  in an empty `except` block or a release moved into `try`/`finally`.
  They run only from the menu or the light bulb, never from `Ctrl+Alt+F`.
- **It respects your compiler.** A fix that needs a newer language or
  RTL feature refuses when the unit, one of its includes or a project
  next to it points to an older compiler or to Free Pascal. A fix without
  full proof stays in the menu and leaves the light bulb.
- **Nine code actions work without a finding.** At the caret: introduce
  a local constant, free an object in `try`/`finally`, build `Format()`
  from a concatenation, invert an `if`, turn the last `if` into a guard
  clause, apply De Morgan, swap a comparison, split an `if`, merge two.
- **Three languages.** Menu texts, hints and refusal reasons
  follow the language of the analyser: English, German or French.

[reDelphix/QUICKFIXES.md](../../reDelphix/QUICKFIXES.md) lists each
quick-fix with its menu texts, effect, locks and an example;
[reDelphix/README.md](../../reDelphix/README.md) describes the code
actions without a finding. Both documents are in German.
`examples/ShowcaseDemo` is a small project written to be scanned, with a
finding for every quick-fix except SCA204.

### What it takes

The Setup always installs reDelphix with the plugin, for Delphi 12 and for
the 32-bit and 64-bit IDE of Delphi 13.

To build it from source instead, first remove the Setup installation for
that IDE. Build `SCA.Engine`, `SCA.SharedUI`, `StaticCodeAnalyser.IDE.d12`
and `reDelphix.d12` in this order on the platform of your IDE and install
the last two, see
[HowTo_Build](../../HowTo_Build.md#53-install-redelphix-code-actions).
Build them one by one: `StaticCodeAnalyser.d12.groupproj` also holds test
projects that depend on DUnitX.

### What this means for Setup and GetIt

The Setup no longer installs the single-package plugin
`StaticCodeAnalyser.Plugin.d12`. It installs the same packages a build from
source gives you, four BPLs for each of the three IDEs:
`SCA.Engine<290|370>`, `SCA.SharedUI<290|370>`,
`StaticCodeAnalyser.IDE.d12` and `reDelphix.d12`. The IDE has to find the
two runtime packages, so the Setup puts its folder at the front of the
IDE's PATH setting (Tools > Options > IDE > Environment Variables). Other
entries stay, and uninstalling removes only this folder.

**GetIt is suspended for this release.** The package set cannot be
installed through GetIt, so there is no GetIt package for v0.9.19. If you
use GetIt, take the Setup.

Coming from v0.9.18:

- **Installed with the Setup:** run the new Setup. It removes the old
  plugin from all three IDEs and says so in a message. reDelphix is
  installed with it.
- **Installed from GetIt:** run the Setup. It removes the GetIt
  registration and says so. The package files stay in the GetIt catalog.
- **Your own build:** the Setup replaces your registrations in every IDE
  you tick, `reDelphix.d12` included, and says so. It leaves the other IDEs
  alone; only the old plugin goes from all three. To go back to your build,
  uninstall the Setup and add your packages again, see
  [HowTo_Build](../../HowTo_Build.md#52-tell-the-ide-to-load-the-plugin).

The four quick-fixes built into v0.9.18 (SCA066, SCA072, SCA084, SCA085)
now live in reDelphix, so an installed plugin keeps them and `Ctrl+Alt+F`
applies them. An own build without reDelphix has no quick-fixes:
`Ctrl+Alt+F` reports "Quick-Fix: the reDelphix package is not loaded". The
standalone GUI no longer has the shortcut, and "Copy AI prompt" no longer
prepends a fixed line. Scanning, the dock, the editor markers and all
reports are unaffected. The HTML reports list the editor helps of each
rule; these describe what reDelphix offers.

## Lazarus and Free Pascal

`--dialect=fpc` scans Free Pascal code the way FPC reads it: it also
collects `*.pp` units and `*.lpr` programs, pairs `.lfm` forms with
their units, adds `FPC` and `LCL` to the one-branch defines, and skips
rules whose premise only holds for Delphi. `--project` takes `.lpi` and
`.lpk` files and `--project-group` takes `.lpg` files, and each of them
switches to the fpc dialect on its own.

- **`--dialect=auto`** decides per file in a `--path` scan: the nearest
  folder with project files wins, and a mixed tree runs both groups and
  merges them into one result.
- **`[Scan] Dialect`** in `analyser.ini` sets the dialect when no switch
  is given. The default stays `delphi`.
- **The rules follow.** The DFM rules read `.lfm` files, except SCA041,
  the parser knows `objcclass` and its relatives and `type helper for X`,
  the `{%H-}` marker is honored, and SCA190 reports UTF-16 source as an
  error, because FPC does not compile it.
- **The standalone GUI** shows the dialect in the status bar and switches
  it with a right click.

The IDE plugin stays Delphi-only by design. Lazarus users scan with the
CLI or the standalone GUI.

## Seven new rules

The catalog grows from 198 to **205 rules**.

- **SCA199 ParamNameMismatch**: `ParamByName('x')` with no `:x` in the
  SQL, which fails at run time and which no compiler can see.
- **SCA200 HardcodedIpAddress** and **SCA201 HardcodedIpInConfig**: an
  IP address in a string literal or in an `.ini` file of the source tree.
- **SCA202 ComparisonPrecedence**: `not`, `and`, `or` and `xor` bind
  tighter than comparisons, so `if not List.Count > 0` compiles and
  tests something else.
- **SCA203 LoopPastHighBound**: a `for` loop one index past the end,
  such as `0 to List.Count` with `List[I]` in the body.
- **SCA204 FunctionNameAsResult**: `GetCount := ...` instead of
  `Result := ...`, a style rule that is not in the `default` profile.
- **SCA205 FunctionNameRecursion**: `Total := Total + X;` inside
  function `Total` calls itself instead of adding to the result.

All but SCA204 are on by default, and SCA202, SCA203 and SCA205 can
report Error.

## A baseline that counts

Until now one baseline entry hid *every* finding with its fingerprint,
including findings added after the baseline was written. Each entry now
covers **at most one** finding. The file format is unchanged, and old
and new files work both ways.

Findings are matched in a fixed order, so the CLI, the GUI, the IDE dock
and the IDE silent run mark the same findings as new. Two related
repairs: the method of a finding is only filled in when its line lies
inside a routine, and the IDE watch mode no longer adds the findings of
a form file again on every save.

**What you will see:** where a file has more findings of one kind than
the baseline has entries, the extra ones show up as new. For this
counting effect, these are exactly the findings that were hidden before,
and nothing is hidden that was shown before. Findings can also show up
as new for other reasons, see [Migration](#migration).

## Rules that read more and claim less

The detectors went through a full review, and the fixes go both ways.

- **SCA001 (MemoryLeak) gets a new level structure.** A never-freed
  object that provably cannot leave the method is `proven-leak`, the
  only variant reported as Error. `return-value-not-freed` drops from
  Warning to Hint. Ownership that is visible in the unit now counts, so
  the rule reports less, while more field leaks and nested classes
  are found.
- **SCA007 (UnusedUses) runs in the CLI.** With `--profile strict` or
  `[Detectors] UsesCheck=1` it never actually ran there. In the GUI and
  the IDE its evidence got better in both directions.
- **SCA125 (InheritedMethodEmpty) reports for the first time.** It
  looked for `override` on the implementation header, where Delphi code
  never repeats it.
- **Whole form files came back.** A dotted property value such as
  `PopupMenu = dm.Pop` made the DFM parser give up, and every form rule
  skipped that form without a word. Routines in `program` and `library`
  files now reach the analysis too.
- **Long lists no longer crash a rule.** Several regular expressions
  could overflow the stack on generated code, above all in the IDE,
  whose threads have a small stack.

The full rule-by-rule list is in the [CHANGELOG](../../CHANGELOG.md).

## Reports and exports

- **SARIF:** `artifactLocation.uri` is now a valid URI: percent-encoded,
  `file://` for absolute paths, with `originalUriBaseIds.SRCROOT` as the
  named root of relative paths. Fingerprints stay the same, so code
  scanning alerts do not reopen. `--sarif-editor-help` adds the editor
  helps of a rule on request.
- **CSV:** a field that a spreadsheet would run as a formula gets a
  leading apostrophe (CWE-1236).
- **JSON:** the rule id is now also `ruleId`, as in SARIF and Sonar;
  `ruleID` stays and is deprecated.
- **HTML:** `--html-max-rows` sets the row budget, the rule report and
  the finding details list the editor helps (`--html-no-editor-help`
  leaves them out), and the report names the profile of the run.
- **All report files** are written atomically: an aborted run leaves the
  old file or none, never half a report.
- **`--diff` and `--branch`** now write the requested reports when
  nothing changed, instead of leaving a pipeline with no file or the
  report of the previous run.
- **`--time-detectors`** no longer loses calls under a millisecond.

## Sonar

**SCA writes the file, `sonar-scanner` sends it.** Sonar settings, the
connection check and the two scripts are gone, see
[Migration](#migration). Installation, scanner, tokens and quality
gates are covered by the official Sonar documentation; SCA keeps a
[short guide](../../sonarHowto.md). The export menu entry is now called
*Sonar: write selected as external issue*: it writes files and sends
nothing.

Every issue of the Generic Issue export now matches a file and a line
that SonarQube knows:
`filePath` keeps the spelling from the disk, and issues in binary DFMs
or behind the end of a file move to file level instead of stopping the
scanner. Findings capped by the evidence policy now reach the report.

The repository keeps two check tools: `tools/sca_sonar_validate.py`
checks a report offline, and `tools/sca_sonar_reconcile.py` compares it
with what the server imported.

**The impact of a rule now follows the findings of the run.** Sonar has
one severity per rule, so the strongest finding in the export decides:
one finding at full severity keeps the catalog impacts, otherwise they
are capped (Warning to at most MEDIUM, Hint to at most LOW). The impact
of a rule can therefore change from run to run; rule IDs and issue
history stay, and `[Rules] EvidenceTiering=0` behaves as before.

A read error after opening a file no longer moves its findings to file
level.

## In the IDE

New installations open the editor overlay **below** the finding line, so
the finding stays readable. An existing `analyser.ini` that was created
from the template still says `OverlayPosition=sameline`; change it to
`below`. Rules with a nesting chain show it as a breadcrumb, and the
level-2 panel can show a compact Before/After chain.

The action menu is half as wide with nothing lost: the explanation moved
into the hint, and the suppress entries moved into one submenu. In the
text-only hint a double click dismisses a finding, not a single click.
The caret blinks steadily again, Escape in a filter combo box keeps the
selection, and `[UI] Element.EditorBulb=0` and
`Element.EditorContextActions=0` switch off the new elements.

## Also in this release

A self-built CLI warns when its stack reserve is too small, and
`SCA_CRASH_STACK` logs the stack of exceptions caught during a scan. A
saved setting no longer wipes an `analyser.ini` that could not be
loaded. An include path in a comment no longer stalls a scan on an
unreachable server. Engine users get the source places service and the
"actions at a finding" extension point that reDelphix is built on.

The README and the manuals were checked against the code: dead paths,
keyboard shortcuts that no longer exist and outdated numbers are gone.

## Migration

- **Sonar settings and the connection check are gone. The page Tools >
  Options > Third Party > Sonar Integration and the switches
  `--sonar-test`, `--sonar-init`, `--sonar-host`, `--sonar-token`,
  `--sonar-project`, `--sonar-branch`, `--sonar-insecure` and
  `--sonar-config` are removed, so a pipeline call with one of them
  fails with exit 99. `sonar-scan.ps1` and `sonar-upload.ps1` are gone
  too: write the report with `--sonar-export` and call `sonar-scanner`
  yourself, see [sonarHowto.md](../../sonarHowto.md). Existing `[Sonar]`
  and `[SonarTokens]` sections in `analyser.ini` are ignored and can be
  deleted.**
- **Setup, GetIt and own builds:** see
  [above](#what-this-means-for-setup-and-getit). GetIt is suspended, so
  take the Setup. Quick-fixes now need reDelphix, which the Setup
  always installs.
- **CI gates:** expect new findings on unchanged code from the new rules,
  SCA125, SCA007 under `strict` or `UsesCheck=1`, `program` and `library`
  files and scripts without an `implementation` section (above all new
  SCA121 Errors), forms with dotted references, damaged UTF-8 files that
  used to be skipped, new Error findings of SCA005, SCA026, SCA046,
  SCA048, SCA055, SCA120, SCA130, SCA175 and SCA177, and new Warning
  findings of SCA003 (Error only with `EvidenceTiering=0`) and SCA139.
  SCA001 levels move in both directions, SCA097 findings can swap
  between Error and Warning. SCA114 drops to Hint, so
  `--fail-on warning` no longer trips on it. SCA108 drops to Warning, so
  `--fail-on error` no longer trips on it.
- **Baselines:** nothing to migrate in the format. Review the findings
  that show up as new, then rewrite the baseline. Reworded rule messages
  and merged SCA070 regions can show as new once; with a context hash
  they still match while the code around them is unchanged. The method
  of a finding outside a routine is now empty, which changes its
  fingerprint. Baselines with a context hash still match while the lines
  around it are unchanged; baselines older than v0.9.8, or findings whose
  surrounding lines changed, show them as new. A relative
  `[Baseline] File=` is now resolved against the project first.
- **Scan scope:** a target below `tests/` or `demos/` named with `--file`,
  `--project` or `--project-group` is no longer filtered away. Pass
  `--dialect` in CI, because a run without it now reads `[Scan] Dialect`.
- **SARIF readers:** decode `uri` and strip the `file://` scheme. SCA015
  findings can move to an earlier line and then get a new fingerprint.
- **Scripts:** `--time-detectors` has a new format with a closing
  `Timing format: 2` line. A self-built CLI with a stack reserve below
  32 MB prints a warning on stderr, also with `--quiet`.
- **Sonar:** issues dropped before appear as new, and issues of binary
  DFMs move to file level. BLOCKER and INFO impacts need SonarQube 10.8
  or later; SCA026, and SCA004 with a proven finding, carry BLOCKER. The
  impact of a rule can change from run to run.
- **Engine users:** the runtime packages are now `SCA.Engine290.bpl` and
  `SCA.SharedUI290.bpl` under Delphi 12, `TExporterHtml.Run` takes
  `THtmlReportOptions`, and `uQuickFix` and `uSonarConfig` are gone.
