# Release 0.9.15 — A quiet clipboard, honest filters, and a text-only hint

**Released:** 2026-08-13
🇩🇪 [Deutsche Version](v0.9.15_de.md)

Three threads come together in this release: the clipboard stops being a
side effect, the display filters stop lying, and the annotation hint
gains a variant that draws nothing but text. Under the hood it also
carries the full export/Sonar audit — see the CHANGELOG for that long
tail of CLI and export fixes.

---

## The clipboard belongs to you again

Since the beginning, selecting a finding row silently replaced your
clipboard with an AI prompt — on every arrow-key step, and even when a
grid rebuild or a sort click on the header moved the selection for you.
For a tool whose core promise is that your source never leaves the
machine, pushing code excerpts into a clipboard that Windows history or
cloud sync may forward was the wrong default.

`[UI] ClipboardOnClick` now decides: `1` leaves the clipboard alone
(the new default), `2` copies a compact **Jira mini issue** — one
headline plus five fact bullets (rule, file:line, method, message, fix
hint) —, `3` copies the full Claude AI prompt as before. The deliberate
gesture always works: **Copy AI prompt** in the grid's right-click menu,
which the IDE dock now has too, and the copy targets the row you
right-clicked, not a stale selection. Two correctness bugs fell in the
same sweep: the prompt's snippet cache could show **stale code** after
you fixed a file (it validates timestamp and size now), and programmatic
grid rebuilds no longer arm the copy timer at all.

## Filters that tell the truth

A scan now starts with both filter combos on **All** — a filter left
over from the previous run read like "hardly any findings" while the
old filter was still silently applied. The dropdown only offers
severities that actually have visible hits: the reduction counts
against the same baseline-filtered set the grid shows. And when *show
only new findings* hides everything, the status line finally says so:
`0 / 4 findings - 4 hidden by baseline`.

Behind the visible changes sits a whole class of state-desync fixes:
the plugin's filter cache, the searchable combo's commit memory (which
could swallow the first re-selection after a scan — also via the stat
tiles), and the marker colour schemes, which now recolour existing
marks **immediately** on saving the options instead of at the next scan.

## The text-only annotation hint

The editor marker colour scheme has a fourth entry now: **Text
(one-line hint, no window)**. Instead of the overlay window, one
transparent line — badge + rule name, drawn without any background
fill — sits permanently at every finding's anchor line, replacing the
mini-infobar. Selection and line highlight stay visible *behind* the
text; that transparency is exactly what a window, however styled, can
never deliver. Click the text to dismiss the finding; description and
fix example remain one glance away in the findings panel.

The short form is a measured decision, not a shortcut: on the self-scan
corpus the median finding title is 96 characters, and only a quarter
would fit the space right of the code — so the hint shows badge + rule
name and leaves the full story to the panel. *Default (bright)*, *Gray*
and *Subtle* keep the window overlay with the full expanding hint,
exactly as before; the colour scheme itself survives a round-trip
through the Text mode.

## Also in this release

The complete export/Sonar audit from early August ships here: dead
egress code removed (`uSonarPull`), `--fail-on` no longer hides read
errors, `--custom-rules` actually fires, baseline refreshes no longer
destroy the baseline, JSON exports lost their BOM, `--parallel` warns
about its measured non-determinism, and the release archive itself
ships `rules/sca-rules.json` so the Sonar export is valid out of the
box. The i18n extractor learned to see `_(CONST_ARRAY[i])` call sites —
five live translations had silently fallen out of the template.
