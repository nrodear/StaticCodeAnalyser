# Release 0.9.12 — The panel keeps up

**Released:** 2026-08-04
🇩🇪 [Deutsche Version](v0.9.12_de.md)

A small release, one day after 0.9.11: the file-scan panel in the IDE
follows the mouse now, one genuine detector defect found by reviewing our
own week's work, and two guards that close known traps. One rule may report
slightly **more** than before — that is the fix working, see below.

---

## The file-scan panel

**The list was sluggish.** The renderer asked the IDE's theming service for
style objects **per drawn cell** — a COM interface call, roughly 300 per
frame, several frames per second while scrolling. The main findings grid had
fixed exactly this long ago with a one-slot cache; the panel was the
outlier. It now uses the same pattern, and the cache is invalidated on theme
change — with the handler order corrected so the synchronous repaint happens
*after* the reset, not before. That ordering slip was caught by the review
on the fix itself, the same day it was written.

**Mouse and wheel now follow the finding, with a 50 ms settle delay.**
Before, the three input paths disagreed: a click jumped the editor
instantly, the keyboard was debounced at 80 ms, and the mouse wheel moved
the selection **without the editor following at all** — no handler was
attached to it. All three now share one debounced navigator: mouse and
wheel at 50 ms, keyboard unchanged at 80 ms. Spinning the wheel fast
collapses all notches into a single editor jump on the resting row;
re-clicking the already-selected row re-centres the editor; double-click
and Enter still jump immediately, with no late follow-up.

## `SCA054` — single-line routines report again

The source check introduced in 0.9.11 scans from the line of the `begin`
token — but it took the **whole** line. When the signature shares that line:

```pascal
procedure TFoo.Bar(Sender: TObject); begin end;
```

the parameter's own **declaration** counted as a use, and the finding
vanished. The defect was well hidden: it only ever *suppressed* findings,
so neither the self-scan nor the corpus anchor could raise an alarm, and
every test fixture had `begin` on its own line.

The start line is now cut at the `begin` token before matching — as a whole
word, so an identifier like `BeginUpdate` is not a cut point. Uses to the
*right* of `begin` on the same line still count; there is a paired test for
both directions.

**Expect `SCA054` to rise slightly against existing baselines.** Those are
real findings coming back, exclusively on single-line routines.

## `WatchMode` can no longer stack workers

`SpawnAnalyzer` spawned unconditionally; the generation counter only
discards *late* results and prevents no overlap. When triggers arrive
faster than an analysis finishes — typing against a one-second edit
debounce and a multi-second analysis — the worker list grew. The unit
header itself called it "endless loop possible" and made this guard a
precondition for ever enabling watch mode by default.

Now at most one watch worker runs. A trigger that arrives while one is
running is not dropped: it re-arms the edit debounce timer, so whatever you
touched last gets analysed once the running worker finishes. Deliberately
no `WaitFor` — the main thread must return to the message loop, or the
running worker could never deliver. One subtlety mattered: both debounce
handlers now clear their pending slot *before* spawning, because the guard
uses that very slot as its retry seat — clearing afterwards would have
wiped the re-arm and made the guard silently ineffective.

Still open, and stated in the unit header rather than papered over: if a
worker hangs permanently, the guard blocks permanently and silently. That
needs a watchdog or a real cancel token — separate work.

## Selecting a finding stopped hammering the clipboard

`GridSelectCell` ran on **every** selection change and did three expensive
things immediately — a system-wide clipboard write, an
`Application.ProcessMessages`, and (when a quick-fix provider exists for
the rule) a read of the entire source file. Holding an arrow key meant
roughly thirty rounds per second.

The clipboard copy is now debounced at 120 ms; the resting row wins. With
the copy out of the selection path, the `ProcessMessages` — which existed
only to flush the help panel before the blocking clipboard write — and its
re-entrancy dance (sentinel re-checks, re-fetched references) disappear
entirely. The check now lives in the timer tick, before the access, where
it belongs.

## `package-release.ps1` hardened twice

- **Stale zips of other versions survived every run**, because the
  per-file cleanup only ever removed the exact same versioned name. The
  documented follow-up `gh release create ... <OutDir>\*.zip` would have
  attached the leftovers to the *next* release — precisely the
  wrong-artifact class this script was built to prevent. The output
  directory is now swept of `StaticCodeAnalyser-v*.zip` before packaging.
- **The tag guard was dead code.** PowerShell 5.1 wraps redirected native
  stderr into terminating error records, so a missing tag killed the
  script with a raw `NativeCommandError` before the friendly `throw` could
  run. It now uses `git rev-parse --verify --quiet` and decides on the
  exit code.

## Also

- The self-scan baseline is ratcheted to the current state (0/654/2785) —
  justified fixture suppressions made the numbers better, and tightening
  means future regressions surface earlier.
- The custom-rules documentation stops claiming target filters exist: the
  `target` key is parsed and then ignored, and the comments now say so
  instead of the opposite. The behaviour is unchanged; rejecting the key
  would break existing rule files and belongs in a release of its own.
