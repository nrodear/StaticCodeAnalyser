# Release 0.9.17 — Delphi 13, a report that renders again, and an INI that keeps its comments

🇩🇪 [Deutsche Fassung](v0.9.17_de.md)

The first release that **supports Delphi 13** — and alongside it two
bugs that were silent total failures: an HTML report that no longer came
into existence on a large corpus, and a configuration file that lost its
explanations on every save.

---

## Delphi 13, 32-bit and 64-bit IDE

Setup now installs the plugin for three targets:

| Target | IDE |
|---|---|
| `bpl\d12` | Delphi 12, 32-bit |
| `bpl\d13` | Delphi 13, 32-bit |
| `bpl\d13x64` | Delphi 13, **64-bit** |

Delphi 13 is the first version to ship a 64-bit IDE (`bin64\bds.exe`),
and it will never load a 32-bit BPL. It therefore gets its own build in
its own folder, registered under *Known Packages x64*.

Nothing is written that cannot be loaded: every file and registry entry
first checks whether that IDE is actually installed. With no Delphi
present, setup stops with a clear message instead of dropping files into
a dead registry branch.

**Delphi 12 stays 32-bit.** That is not a limitation on our side: Delphi
12 has no 64-bit IDE, and it ships `designide` — the package every
design-time plugin links against — for Win32 only. A Win64 attempt there
now ends with a readable message instead of `E2202`.

---

## The HTML report no longer rendered on large corpora

On the reference corpus the report page needed **8.4 GB** and ran out of
memory. It now needs **62 MB**. Two further silent failures of the same
page are fixed with it — in certain cases it produced a file the browser
would not display at all.

If you got no report on a large code base before, you get one now.

---

## `analyser.ini` keeps its comments

The file is created from a template on first start, and that template
explains every key. A single save in the options dialog used to erase
that entire documentation — the file was rewritten from the in-memory
model, and that model knows only sections, keys and values.

Comments, ordering and commented-out examples now survive. **Four**
writers touch that file, not one; all four were changed.

---

## In the editor: an edited finding line drops its marker

Change the line a finding sits on and the marker is no longer painted
over text it no longer matches. The finding disappears until the next
scan.

One display defect less, too: the overlay used to draw into the editor
from a timer. That produced a second, counter-moving caret. It now draws
only where it is allowed to.

---

## Also in this release

- **Sonar export:** downgraded findings can be kept out of the report.
  Why there is no per-finding severity there — and why it must not be
  added — is now recorded in the source: the import format rejects an
  entire report that carries severity at issue level.
- **Rule selection in the UI** shows the rule ID and token only, no
  descriptive text.
- **Encoding:** 743 files carried UTF-8 without a BOM and were read as
  ANSI by the compiler, the IDE editor and PowerShell. All of them have
  a BOM now, and a gate keeps it that way. Our own SCA190 detector had
  been reporting it all along.
- **False positives:** several rules claim less without any threshold
  being loosened — each was making a claim it could not support.
- Three-language documentation brought in line throughout.

---

## Upgrading

Nothing to do. If you installed the plugin through setup, install the
new build over it; the registration is carried across. Your
`analyser.ini` stays valid.
